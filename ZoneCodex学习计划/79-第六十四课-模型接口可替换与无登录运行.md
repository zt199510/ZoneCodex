# 第六十四课：模型接口可替换与无 OpenAI 登录运行

创建日期：2026-10-16。产品代码与本地分层验收记录见第 9 节。用户实测确认和八道自测仍待完成；不代填用户答案，不结清第 63.1 课欠账。

## 1. 目标与前提

把模型调用移到独立 Provider 后面，让桌面、CLI 和公共脚本共享选择规则。没有模型配置时仍可启动、管理本地 MCP、查看工具和运行断网验收。

本课只提供 Responses SSE 和内置离线 Provider。离线 Provider 没有推理能力，只返回“当前为离线模式，未调用推理模型，也未执行本轮任务。”普通离线聊天不会调用工具、自动连接 MCP、生成标题、生成摘要或生成 Git 文案。

沿用内部 Responses 协议历史和完整 reasoning 数据；会话 v9、设置 v1、checkpoint v1 不迁移、不清空。MCP 使用独立设置文件，不保存模型密钥。保留 Skills、工作面板和聊天输入框结构。

不加入 Chat Completions、Ollama、自动路由、子 Agent、SSH、登录系统、密钥表单、HTTP MCP 或 OAuth。

## 2. Vue 类比

`ModelProvider` 类似一套可替换的服务实现；`ModelSession` 类似在一次操作开始时创建、随后保持稳定的服务实例。React 组件只读取公开状态，类似 Vue 页面通过 store 展示状态，不直接持有后端密钥。

一次任务的主模型、摘要和风险复核共用同一个 session。就像一次表单提交已选择服务实例后，用户再改全局设置，也不应让同一次提交的后半段换用另一套服务。

能力声明相当于组件可用功能的合同。按钮禁用属于界面反馈，主进程仍须再次检查，不能只靠按钮决定权限。

## 3. 职责划分

| 模块 | 职责 |
|---|---|
| `model-contract.ts` | SendResponse、用途、Provider、固定 Session 合同 |
| `model-configuration.ts` | 统一解析环境配置，验证 HTTPS 和 URL 凭据 |
| `responses-provider.ts` | 保留 SSE、完整 output/reasoning、重试、取消、错误语义 |
| `offline-provider.ts` | 固定离线说明；不产生工具调用 |
| `model-session.ts` | 固定本次配置和能力，按用途创建发送器；提供安全状态 |
| `response-client.ts` | 原接口兼容导出，导入不启动请求 |
| 桌面 / CLI 宿主 | 每次任务捕获 Session，同步接入审批、摘要及能力检查 |
| 标题 / Git 生成 | 各自捕获 Session，离线跳过或明确不可用 |
| Model IPC / preload | 只传公开 Provider 状态和安全错误码 |
| MCP Manager / Client | 本地独立进程、工具快照、配置版本、退出与失效校验 |

## 4. 实施步骤

### 4A. 配置与模型边界

| 环境配置 | 行为 |
|---|---|
| `MODEL_PROVIDER=offline` | 离线；不读取远程三项 |
| `MODEL_PROVIDER=responses` | 三项必须完整且合法 |
| 未指定，三项均空 | 自动离线 |
| 未指定，三项完整 | 兼容原 Responses |
| 缺项、非法或未知 Provider | 模型配置错误，本地功能仍可用 |

三项为 `MODEL_ENDPOINT`、`MODEL_NAME`、`MODEL_API_KEY`。远程地址只允许无 URL 用户名/密码的 HTTPS。连接或认证失败保持真实错误，不降级成离线成功。设置页只读，不把地址、密钥或完整配置传入 renderer、日志、checkpoint、MCP 配置和子进程环境。

抽取原传输到 Responses Provider；核心保持 SendResponse 与原工具循环。Session 在主任务开始时捕获，固定配置和能力。主模型、摘要、审批复核共享它，标题和 Git 生成独立捕获。显式测试 Provider 只通过内部依赖注入，不存在环境、IPC 或聊天文字加载入口。

### 4B. 离线产品行为和安全

离线回复只表示本轮未执行。保留本地初始标题和原始历史，不用离线文本冒充模型摘要。容量保护继续停止超预算请求。图片推理与未完成任务续接明确拒绝，不标记原任务完成。离线风险复核返回人工审批；full-access 仍校验当前权限和上下文。

缺失 MCP 配置文件表示首次使用的空设置；损坏文件保留并持续报错，不能靠再次读取绕过。启动中的进程先登记；连接、刷新和调用都使用版本与 token 校验。超时/取消发送正确请求 ID，最多等待 500 ms，随后关闭未响应进程；退出闸门等待真实子进程退出。

模型只看到 `mcp__<serverId>__<toolName>` 的 function schema，内部仍用原工具名。计划模式不暴露 MCP。每轮固定工具集合、配置版本和 schema，调用前后及等待审批后再次检查。MCP 不获得文件、终端、工作区或命令授权。

MCP 续接证明只保存在当前窗口内存，不保存进程句柄或授权。原工具的配置、连接、schema 变化即失效；窗口关闭或应用重启后，含 MCP 调用的旧任务无法恢复原快照，明确要求核对效果后重新发送。普通无 MCP 任务仍使用原 checkpoint 校验流程。

### 4C. 分层验收

先验证配置和纯接口，再用实际编译后的产品模块做模型与真实 stdio 进程检查，最后运行隔离桌面及本课重建的目录包。默认离线测试不自动构建、打包或请求远程模型。

测试专用 Provider 产生固定工具调用，真实 Agent 工具循环、审批 broker、Manager 和 Client 执行实际 stdio fixture。合成 SSE 只验证真实传输的协议处理，不能声称完成远程模型验收。fixture 无工作区工具，不等于对任意本地程序提供 OS 文件沙箱。

## 5. 验收条件

- 配置矩阵一致，导入/帮助/启动/恢复记录零模型请求。
- 离线固定说明、能力拒绝、标题跳过、摘要容量保护、Git 禁用及审批回退可验证。
- SSE/reasoning、function schema、重试固定请求、取消和迟到事件使用实际产品模块验证。
- 实际 stdio 子进程完成 Agent → 审批 → MCP → 结果；命名空间和白名单不被绕过。
- 配置/schema 变化、窗口关闭、启动失败和异常退出不会接受迟到结果；核验实际 PID 退出。
- 开发版和当前 Windows 目录包完成独立 userData 的 UI 验收；不使用真实登录资料。
- 必要回归与历史欠账分开记录；用户确认和自测不自动标记通过。
