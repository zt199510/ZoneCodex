# 第三十七课：AI 会话标题生成与重命名保护

创建日期：2026-09-29。状态：源码已实施，待真实桌面验收。

前一课：[第三十六课：输入框草稿、快捷键与发送前交互收口](47-第三十六课-输入框草稿快捷键与发送前交互收口.md)。

第35课已经完成首条提问的本地确定性标题，第36课完成了多会话输入和发送边界。本课把标题升级为“即时本地回退 + 可选 AI 摘要”的两阶段行为：首条消息被接受后先显示稳定的本地短标题，再通过现有真实 Agent Responses SSE 基础设施请求一个简短标题。标题请求失败时保留本地标题，不影响聊天请求、工具循环和输入框。

## 1. 本课目标与边界

完成后应达到以下结果：

1. 首次用户消息被接受后立即使用第35课的本地标题，不等待模型返回。
2. 首次请求只触发一次标题生成；标题请求携带明确的 `conversationId` 和首条消息来源，不能写入其他会话。
3. 标题请求使用真实 Agent Responses SSE 适配器和结构化结果校验，不恢复普通文本请求、模拟模型或第二套聊天回复路径。
4. 模型返回的标题只在会话仍是默认占位标题、用户没有手动重命名、来源仍对应首条消息时才可覆盖本地标题。
5. 空消息、同步拒绝、模型失败、停止、超时、非法结构或超长结果均保留本地标题，不复制用户消息、不增加助手消息、不增加工具记录或任务记录。
6. 用户在标题生成期间重命名后，人工标题永久优先；迟到的模型结果不能覆盖它。
7. 成功标题写入现有 `ConversationLibrary`，刷新后恢复；标题请求的进行中状态和临时回退状态不写入 `conversation.json`。
8. 切换、归档、恢复、关闭和刷新不会把标题结果应用到错误会话；旧请求的迟到结果必须被忽略。

本课不做：标题历史版本、永久删除、每条消息重新摘要、标题编辑器重做、标题生成开关、跨窗口标题同步、为标题建立新的任务历史、MCP、Skills、SSH、并发 Agent、自动批准或任意命令。

## 2. 用 Vue 经验理解本课

| Vue 经验 | React / Electron 对应 | 本课用途 |
|---|---|---|
| `data` 中的派生回退值 | 会话快照中的本地标题 | 请求尚未完成时立即有可显示标题 |
| `watch` 请求来源变化 | `conversationId`、首条消息 ID 和请求代次 | 过滤切换会话后的迟到响应 |
| 表单的手动修改优先级 | `isPlaceholderConversationTitle` 与重命名状态 | 模型不能覆盖用户修改 |
| 异步 API 返回 schema | 共享解析器和 IPC 运行时校验 | 不把模型自由文本直接写入持久化数据 |
| `finally` 清理请求句柄 | AbortController、卸载清理和请求代次 | 失败、停止、刷新后不残留标题任务 |

AI 标题是会话元数据副作用，不是聊天消息。它不能把结构化标题结果伪装成助手回答，也不能绕过会话库的保存入口。

标题请求是否需要新增文件，应由当前 IPC 和模型封装的实际边界决定；先复用已有真实传输和保存入口，再决定最小改动位置。

## 4. 按依赖顺序实施

### 第一步：定义标题请求的输入和结果

先定义有限的输入：会话 ID、首条用户消息 ID、首条用户内容和请求代次。结果只允许包含会话 ID、来源消息 ID、请求代次和经过校验的标题文本。标题文本应去除首尾空白、压缩换行，拒绝空值、控制字符、超长内容和模型返回的 JSON 外壳。

预期效果：调用方能够判断结果属于哪一个会话、哪一条首消息和哪一次请求；无效结果不会接近持久化层。

常见错误：只带标题不带来源 ID；直接把模型原文写入会话库；用字符串查找 JSON 字段；把标题请求结果放进 `ChatMessage` 或 `ToolRun`。

### 第二步：复用真实 Agent Responses SSE

在主进程和 preload 中接入标题元数据请求时，沿用当前真实 Agent Responses SSE 的请求、解码、取消和错误处理。提示词要求模型只返回短标题结构，解析器负责最后的字段和长度校验。标题请求可以失败，但不能让失败冒泡成聊天失败，也不能把增量显示到消息区。

预期效果：聊天仍只有一个真实回复链路，标题是独立的元数据结果；网络失败和取消都能收口。

常见错误：恢复 `askModel`、`chat:ask` 或模拟响应；让标题文本走 `model-stream:delta` 并写入助手消息；为了标题创建普通 `TaskRecord`，污染任务历史和容量统计。

### 第三步：接入首次发送后的本地回退和异步更新

首次 `conversation.send()` 返回 `true` 后，继续立即设置第35课的本地标题，再启动一次标题请求。保存和更新必须复用 `useConversation` 的会话入口。请求开始前记录会话 ID、首条用户消息 ID 和本地请求代次，后续响应只接受完全匹配的来源。

预期效果：用户发送后马上看到标题；模型稍后返回时只替换仍符合条件的默认标题；异步失败时标题保持可用。

常见错误：等 AI 标题返回才显示会话；每次新消息都重新生成；在 `ChatWorkspace` 中直接改会话对象；标题请求失败时清空标题或重新复制草稿。

### 第四步：保护人工重命名和会话生命周期

重命名开始、提交成功、切换、归档、恢复、关闭和刷新都要使不再适用的标题请求失效。重命名成功后设置稳定的非占位状态；迟到的 AI 结果即使文本更好也不能覆盖。归档或切换后返回的结果必须按会话 ID 和请求代次丢弃。

预期效果：在 AI 标题生成时改名，最终显示用户输入；切换 A/B 会话后，A 的迟到结果不会改变 B；刷新只恢复已保存标题，不恢复进行中的生成。

常见错误：只比较当前活动会话，不比较来源消息；用闭包中的旧标题判断是否占位；组件卸载后仍调用旧的 `setState`；把请求中的标题写入磁盘。

### 第五步：验证持久化、搜索和真实流式聊天

标题成功后通过现有保存防抖写入会话库，并检查侧栏搜索、归档列表、恢复和刷新。聊天增量、工具调用、失败消息、停止消息和已有重试入口必须与第36课一致。没有真实网关时，只记录协议和静态检查结果，桌面 AI 标题结果标为“待验收”。

## 5. 验收矩阵

| 场景 | 必须观察 |
|---|---|
| 首次发送 | 本地标题立即出现；标题请求只发起一次 |
| AI 返回合法标题 | 当前会话标题更新并可搜索，消息和任务记录数量不变 |
| AI 返回空值、超长或非法结构 | 保留本地标题，显示/保存不崩溃 |
| 模型失败、停止或超时 | 聊天失败/停止按原有路径收口；标题保持本地回退 |
| 发送被拒绝 | 不触发标题请求，原草稿和原标题保留 |
| 生成期间重命名 | 用户标题优先，迟到 AI 结果被丢弃 |
| A/B 会话切换 | A 的响应不会修改 B；每个会话只接受自己的来源 |
| 归档/恢复 | 归档或恢复不丢已保存标题，不应用失效请求 |
| 刷新 | 已保存 AI 标题恢复；进行中标题请求、草稿和一次性句柄不恢复 |
| 搜索 | 标题更新后搜索索引同步，不复制第二份会话库 |
| 真实聊天流式 | 助手增量、工具循环、失败/停止和重试继续走现有真实 Agent Responses SSE |

至少运行当前仓库实际存在的 `npm run typecheck:node`、`npx electron-vite build` 和 `git diff --check`。完整 `npm run typecheck`、`npm run build` 和 `npm run lint -- --quiet` 若仍受到 `WorkspaceStatus.tsx` 既有未使用声明影响，必须记录具体文件和错误，不修改无关用户改动。不得新增模拟模型、普通文本入口或桌面 fixture。
