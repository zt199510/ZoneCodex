# 第四十二课：Agent 指令与行为规则统一

第43课已更新本课的执行权限与审批交互：工作区可选，有效范围内文件写入直接执行，越界按需批准；文件审批弹窗仅展示原因、操作与完整目标路径，命令审批展示原因、工作目录及可读命令。下文逐次确认与完整内容展示的描述保留为第42课历史，当前行为见[第四十三课](54-第四十三课-默认工作目录与统一执行权限.md)。

## 1. 本课目标与前置条件

第41课已经收口 AI 回复的展示层。本课转到主进程中的 Agent 指令：统一聊天请求可携带工作区和已授权附件快照；把重复、分散的指令整理为一个可检查的主 Agent 构造入口，使同一能力始终遵守一致的回答和行动规则。Codex App 没有固定的“三种请求方式”；工作区和附件是本轮可选上下文，不是三个独立入口。

OpenAI 公开文档没有提供可复制的 Codex App 完整内部系统提示词。本课对齐的是可观察的行为：直接回答、按实际工具能力行动、明确区分提案与执行、忠实报告结果及失败。`instructions` 指导模型，工具列表、主进程校验和权限策略仍决定它实际能做什么。

前置条件是第18至30课的 Responses 工具循环、工具范围与受控提案，第39课的工作区 `AGENTS.md`，以及第40、41课的消息和工具活动展示。第41课真实模型及桌面效果仍待验收；本课创建时尚未实施 Agent 源码改动。

本课先统一主 Agent 指令的组成与行为规则，随后按用户新的目标接入工作区本地操作。工作区目录授权后，可在限定路径和容量内列出、搜索、读取文件，并以逐次确认执行小文本文件新建、修改及程序启动；会话分支、并发 Agent 和新的回复通道仍不在本课范围内。程序执行没有 OS 沙箱，用户确认是执行前关口，不等于限制获批程序只能访问工作区。

## 2. 用 Vue 经验理解本课

可以把 Agent 指令看作 Vue 中由固定配置和当前 Props 计算出的派生值：共同规则只定义一次，附件清单、工作区说明和可用工具范围作为本轮输入加入。不能为每个页面状态复制一整段基础规则，否则同一约束会逐渐出现不同版本。

这里的“指令统一”不等于“权限统一”。类似前端隐藏按钮不会撤销后端权限，提示词说“只能读取选中文件”也不能代替主进程的 `ToolScope`、快照和工具参数校验。统一请求协议中的会话 ID 必填，工作区 ID 与已授权附件快照是可选字段；内部 `ToolScope` 仍记录实际工具范围，并隔离不能续用的工具历史。模型输出的行动声明必须由实际工具结果支持。

## 3. 实际文件及职责

- `src/main/model/tool-response.ts`：构造真实 Responses SSE 请求，传入由主 Agent 入口选择的 `instructions`、实际 `tools` 和 `tool_choice: 'auto'`；标题请求仍可独立使用此传输函数。
- `src/renderer/src/features/chat/agent-request.ts`：从会话、可选工作区与授权附件派生同一请求上下文和内部工具范围，取代原 `chat-mode.ts` 的模式分支。
- `src/preload/index.ts`、`src/shared/api.ts`：以单个 `context` 参数传递会话 ID、可选工作区与附件快照，不再额外传会话/工作区参数；preload 在跨 IPC 前校验上下文和工具历史。
- `src/main/agent/agent-ipc.ts`：解析统一请求上下文，验证窗口、会话、工作区和附件快照归属后，调用统一的主 Agent 请求构造入口，并负责工作区操作的逐次确认及任务状态收尾。
- `src/main/agent/project-instruction.ts`：受限读取工作区根目录 `AGENTS.md`，保留 UTF-8、大小、指纹和文件类型边界。
- `src/main/agent/tool-loop.ts`、`src/shared/project.ts`：实际工具循环、统一请求上下文校验与工具白名单，继续作为能力边界；`trace` 是请求和工具记录，不是模型原始思考。
- `src/main/tools/current-time.ts`、`project-snapshot.ts`、`change-proposal.ts`、`command-proposal.ts`：时间与附件快照工具，保留原有受控提案边界。
- `src/main/tools/workspace-files.ts`、`workspace-actions.ts`：工作区受限目录列出、文本搜索/读取，以及经逐次确认的新建、修改和程序执行；前者的路径与资源上限不能代替后者的用户确认。
- `src/main/model/title-response.ts`：会话标题专用指令，属于独立任务，不并入主聊天 Agent。
- `src/main/agent/agent-instructions.ts`：集中放置共同规则，按本轮实际授权能力返回工具清单及相应规则，并附加不可信工作区上下文。
- `scripts/check-lesson42.cjs`：离线检查统一请求上下文的解析、工具范围与历史隔离，并捕获不同可选上下文组合传给 Responses 的负载；不调用真实模型。

## 4. 按依赖顺序实施

### 步骤一：记录统一请求的能力边界

核对无工作区、无附件时只有 `get_current_time`；有工作区授权时增加 `list_workspace_files`、`search_workspace_text`、`read_workspace_file`、`create_workspace_file`、`edit_workspace_file`、`run_workspace_command`；有已授权附件快照时另增加选中文件搜索、读取、单文件修改建议和固定 `npm_typecheck` 命令提案。记录不同上下文组合实际传入的 `instructions` 与 `tools`；工作区目录授权有受限读取范围，但不等于无边界磁盘访问或操作免确认。

预期结果：能解释工作区授权与逐次操作确认各自的作用；Markdown 外链点击不是 Agent 工具，获批程序却可能调用浏览器或访问工作区外资源。

常见错误：只看 UI 上的工作区名称，就认定模型已获自动执行许可；或只看工具使用工作区相对路径，就认定获批程序受 OS 沙箱限制。

### 步骤二：定义一份共同规则与按能力追加的规则

共同规则覆盖任务理解、直接回答、按需调用已提供工具、证据不足时说明限制、工具失败时如实报告、只在执行结果出现后声称“已完成”。回答遵循用户语言，保持简洁具体；不要制造“思考过程”、虚构工具活动或未经执行的操作结果。

附加规则只描述本轮真实提供的能力：时间工具按需使用；工作区工具按授权目录列出、搜索、读取，编辑前先完整读取目标小文件；新建、修改和程序执行要展示目标内容或命令并等待用户本次确认。附件文件只按清单和已授权快照搜索/读取；修改建议要求先完整读取目标小文件、每轮至多一份且明确尚未写入；`npm_typecheck` 只能在用户请求检查建议时提出，每轮至多一份，提案不代表执行许可。没有工作区授权时不得声称已运行程序或改写磁盘。

预期结果：共同语气和诚实报告规则只有一份，附加说明与传给 Responses 的工具列表一致。

常见错误：把工具权限写成纯文字承诺，或用冗长角色扮演规则代替明确的行动边界。

### 步骤三：接入统一构造入口

让统一聊天请求调用同一主 Agent 指令构造入口，按可选工作区和附件快照生成本轮配置。请求上下文应把必填会话 ID、可选工作区 ID 和可选授权附件快照明确分开；由主进程据此校验授权并派生内部 `ToolScope`，不得让前端声称的工具范围直接决定执行许可。附件清单仅保留现有相对标识及行数；`AGENTS.md` 正文仍标为不可信的项目上下文，不得改变工具白名单、授权范围、用户请求或固定安全规则。不要把用户提问、附件正文或工具返回值直接拼成高优先级规则，也不要在日志中输出指令全文或文件内容。

预期结果：每种可选上下文组合都能生成确定、可检查的指令；实际工具注入、授权校验和 `title-response.ts` 仍保持原有路径。

常见错误：统一时漏掉某个分支，导致普通聊天重复规则、工作区请求丢失限制，或让标题请求继承聊天工具指令。

### 步骤四：验证行为和回归边界

先用确定性检查核对不同上下文组合的指令与工具列表，再验证普通问答、当前时间、工作区列出/搜索/读取、确认或拒绝新建/修改/运行、选中文件问答、附件建议、无授权时的操作请求、恶意 `AGENTS.md`/附件文本、工具失败和停止。检查真实工具记录与回答一致，不把 `ToolRun.trace` 命名为原始思考。模型或桌面未实际运行的用例须标为“待验收”。

预期结果：聊天请求的 `context` 参数形状统一；Responses SSE、已保存的 `ToolRun.scope` 与工具协议历史格式、任务记录和附件记录保持原边界。新增工作区工具仍由主进程授权、运行时白名单和逐次确认约束。

常见错误：以提示词文本包含某条规则，代替真实请求 payload、工具范围或运行行为的验证。

## 5. 验收条件

- 主 Agent 共同规则有单一来源；统一请求携带不同可选上下文时，指令与实际工具列表一致，不出现互相矛盾的权限描述。
- 普通问题直接回答；需要已提供工具时才调用。无工作区授权时不虚构工作区读取、程序执行或文件写入；有授权时仍须等到用户确认及工具结果后，才能声称操作已完成。
- 文件内容、工具结果和 `AGENTS.md` 不能改变工具白名单、窗口/会话/快照归属或用户授权；附件范围和固定提案限制保持原样。
- `ToolScope` 保留运行时工具白名单、协议历史校验和跨快照历史隔离；工作区读取受路径、文件类型和资源上限约束，新建/修改/程序执行逐次确认，不自动批准。程序执行没有 OS 沙箱，不能承诺获批程序只能访问工作区。
- renderer 不再用聊天“模式”选择请求类型；preload 与主进程从同一上下文解析实际授权，停止和重试继续校验原会话、工作区和附件快照归属。
- 最终回答区分已执行结果、待用户审查的修改/命令建议和未完成事项；真实工具活动来自工具循环，不能伪装为模型原始思考。
- 保留真实 Agent Responses SSE、工具历史、会话消息、附件与任务记录、生成中/完成/失败/停止/重试状态；标题生成仍用独立指令。
- 至少运行 `npm run typecheck`、`npx electron-vite build`、`npm run build`、`npm run lint -- --quiet` 和 `git diff --check`；记录实际结果。真实模型及桌面行为只在实际观察后记为通过。
