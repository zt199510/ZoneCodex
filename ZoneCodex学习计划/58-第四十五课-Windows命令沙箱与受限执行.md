## 1. 本课目标与前置条件

本课沿两条调用链复习：一条是“命令提案 → 执行计划 → 授权 → 官方沙箱/批准升级 → 输出与进程树收尾”；另一条是“发送 → 等待计时 → 公开过程 → 工具条目 → 后续过程 → 最终回答 → 保存恢复”。两条链在真实工具调用处连接。

| 本课范围            | 当前可观察效果                                                                   |
| ------------------- | -------------------------------------------------------------------------------- |
| Windows 执行后端    | 固定官方 Codex CLI 0.160.1，范围内命令直接使用 `codex sandbox` elevated 路径     |
| 两条命令入口        | 通用 `run_workspace_command` 与旧 npm 共用计划和进程底层，各自保留限额及业务校验 |
| 三种授权模式        | 请求批准、帮我批准、完全访问权限决定实际执行方式；本次升级沿用输入框上方浮窗     |
| 停止与收尾          | 原生 Windows Job 监督器负责输出、超时与终止，核对父、子、孙进程及心跳            |
| 公开过程与最终回答  | 实际 `commentary` 和工具调用按发生顺序展示；最终回答位于过程折叠区外             |
| 工具树与分组        | 调用即时出现，结果更新同一节点；连续调用分组，展开查看真实参数和结果             |

| 网址链接            | 用户及助手的合法 HTTP/HTTPS 链接显示蓝色下划线，可经已有系统浏览器入口打开       |
| 本地文件引用        | 工具文件名已有图标、浅灰下划线与完整路径提示；点击查看本地文件尚未接通           |

前置条件：能找到第44课三模式授权入口，理解 `state`/`ref`、流式事件和版本6会话保存，并区分主进程执行事实与 renderer 展示状态。未选工作区时仍使用每会话稳定默认目录；工作区是可选上下文。

普通使用遵循官方初始化流程。账户、令牌、ACL、防火墙和初始化授权由官方程序管理；ZoneCodex 负责可信资源、计划、批准与生命周期。原来的独立账号、AppContainer 和自定义 WFP 探索已停止，不再作为学习步骤。

## 2. 用 Vue 经验理解本课

在 Vue 中，隐藏按钮不能阻止后端调用；在 Electron 中，页面显示“已批准”也不能决定具体启动什么程序。renderer 是展示层，主进程保有当前权限、不可变计划和一次批准，操作系统后端负责实际访问控制。

| 已有经验                 | 迁移到本课                                                                         |
| ------------------------ | ---------------------------------------------------------------------------------- |
| 服务端核验具体操作       | 主进程绑定命令、参数、目录、范围、后端及批准，启动前再次复核                       |
| 异步请求的取消与清理     | 取消请求和确认进程树退出分别处理，结果只结算一次                                   |
| `v-for` 的稳定 `key`     | 工具用调用 ID，分组用首个调用 ID，增量更新不会重建用户正在操作的节点               |
| `computed` 派生显示数据  | 根据真实工具类型与状态生成摘要、图标和用时，不向模型索要 UI 状态                   |
| `watch` 后调整滚动       | 只在用户仍跟随底部时滚动；主动向上阅读后保留阅读锚点                               |
| 不同组件拥有不同渲染分支 | 助手 Markdown 与用户原文分别处理，给助手链接改颜色不会让纯文本用户消息自动变成链接 |

公开过程来自模型实际发布的 `commentary`，工具节点来自实际调用事件。私有 reasoning、加密内容和内部 ID 不进入回复区；`trace` 是运行记录，不是模型原始思考。

## 3. Codex 官方依据与本课技术路线

本课创建时读取以下官方页面，核对日期为2026-10-06；下述执行实现固定在已验证的 CLI 0.160.1，不声称已核对未来版本：

- [Windows sandbox](https://learn.chatgpt.com/docs/windows/windows-sandbox)：原生 elevated / unelevated 方案与限制。
- [Permissions](https://learn.chatgpt.com/docs/permissions)：文件、网络和批准边界。
- [Agent approvals & security](https://learn.chatgpt.com/docs/agent-approvals-security)：沙箱、升级和完全访问。

### 当前采用的官方路线

ZoneCodex 调用官方独立 `codex sandbox` 入口并传入 `windows.sandbox="elevated"`。固定分发 `codex.exe`、`codex-command-runner.exe` 和 `codex-windows-sandbox-setup.exe`，另有本项目编译的 `host.exe`。官方程序保持原样；host 只负责 Job、输出和停止，不承担文件或网络隔离。

elevated 指初始化需要提升权限，任务使用受限身份执行。unelevated 从当前用户生成受限 token，网络边界较弱，本课未将它作为等效替代。初始化、启动或命令失败如实返回，同次调用不改用普通权限重跑。`codex exec` 会开启另一个 Agent 循环，不是这里的执行入口。

资源来源、版本与完整 SHA-256 核验决定能否调用官方路径；资源可用不等于本机所有隔离探测通过。历史网络 listener 收到5个连接，修复官方规则后仍失败。当前按用户要求直接复用官方机制，移除了额外网络门控和规则枚举，未据此改写失败记录。

### 三种模式如何路由

| 场景                                 | 请求批准 `default`                   | 帮我批准 `auto-approve`                      | 完全访问权限 `full-access`   |
| ------------------------------------ | ------------------------------------ | -------------------------------------------- | ---------------------------- |
| 范围内、可信官方后端可用、未请求升级 | 官方沙箱，无额外批准                 | 官方沙箱，不调用风险评估                     | 按用户选择非沙箱执行         |
| 通用命令明确请求升级                 | 批准精确的本次操作                   | 严格 `safe` 批准，其他结果按现有人工回退处理 | 按完全访问方式执行           |
| 旧 npm 需要非沙箱执行                | 人工批准                             | 缺少可信本轮任务，仍人工批准                 | 按完全访问方式执行           |
| 准备阶段已知官方后端不可用           | 对本次非沙箱执行明确请求批准，或拒绝 | 通用命令按实际风险流程；旧 npm 仍人工批准    | 可信监督器可用时按原权限执行 |
| 已开始初始化或启动后失败             | 返回实际失败，不自动重跑             | 返回实际失败，不自动重跑                     | 返回实际失败，不自动重跑     |
| 取消、过期计划或可信监督器失效       | 拒绝启动                             | 拒绝启动                                     | 拒绝启动                     |

批准仍精确到一次操作，不保存为后续永久能力。需要批准时继续使用输入框上方原浮窗，显示原因、工作目录和可读命令；取消与确认位于右下角，不在批准弹窗中展示文件全文。

第44课已有“评估异常转人工批准”与官方当前 auto-review 失败拒绝存在差异。本课保留这项实际行为记录，三项菜单相同不能代表所有审批行为已完全一致。

## 5. 按调用顺序复习与练习

以下步骤对应已完成的源码，练习用于理解和复核现有行为。功能修改不再从创建时的普通 `spawn` 基线重新实现。

### 步骤一：找到可信后端与单次计划

沿 `inspectWindowsCommandBackend` → `prepareCommandExecution` → `authorizeCommandExecution` → `claimCommandExecution` 阅读。找出参数冻结、资源哈希、目录身份、Git 指向及保护路径快照的核对位置。默认保护名称为 `.git`、`.agents`、`.codex`、`.aws`；现存路径才传显式只读条目，缺失路径不创建占位目录。

**练习与预期：**画出准备、等待批准、领取启动三个时点，说明参数、权限 revision、目录或资源变化如何使旧计划零启动。区分文件写入仍可用布尔批准与命令必须返回具体计划。

**常见错误：**把 `sandboxAvailable` 全局写成 `true`；把资源签名计划理解为签名证书验收；把目录检查当成系统访问控制。

### 步骤二：对照三模式与两个入口

从通用命令与旧 npm 分别追到授权入口，再追到 `startCommandProcess`。统一的是计划、后端和生命周期，业务差异仍由各自入口负责。

| 行为           | 通用命令                           | 旧 npm                                   |
| -------------- | ---------------------------------- | ---------------------------------------- |
| 时间限制       | 30秒                               | 60秒                                     |
| 输出限制       | 合计1800字节，按原始字节捕获       | 合计256KiB，分段输出                     |
| 启动前保护     | 当前性、授权后二次核对、`onEffect` | 一次准备/确认、目录身份及脚本配置核对    |
| 命令环境       | 沿用工具环境白名单                 | 保留必要兼容变量，剔除模型凭据等敏感变量 |
| 非沙箱自动审核 | 有可信任务时按现有审核流程         | 缺少可信任务时人工批准                   |

Windows `npm.cmd` 被解析为实际 `node.exe` 与 `npm-cli.js`，继续用程序和参数数组启动。

**练习与预期：**解释同一模式下两入口的共同后端和批准差异；分别找到限额、配置复核与副作用记录。默认/帮我批准的范围内命令无需额外审核。

**常见错误：**为了统一代码互换输出/环境策略；拼接不可信 Shell；把一次获批升级变成后续批准。

### 步骤三：理解输出、取消和进程树结算

阅读 `command-runner.ts` 与原生 host 的收尾协议。Job 在程序运行前容纳受控进程，停止、超时、撤销、刷新和关闭都由主进程拥有者收尾；停止请求发出后继续等待退出证据，终态仅结算一次。

**练习与预期：**用已有隔离 fixture 核对父、子、孙 PID 与 heartbeat，解释父进程先退和退出未确认的结果。取消是请求状态，不能单凭 `cancelled` 就断言全部进程已退出。

**常见错误：**调用 `kill()` 后立即标成功；清理监听过早导致退出事件丢失；启动不确定后允许安全自动重试。

### 步骤四：区分文件、网络、进程与打包证据

阅读第9节中的真实文件探测、网络失败、17项官方生命周期、8项监督器检查和两版各19项桌面矩阵。文件边界、网络连接、进程退出和 UI 接线分别有证据；桌面矩阵使用合成模型结果，不能据此宣称真实模型已完成沙箱命令。

**练习与预期：**为每项证据写出“证明什么、尚未证明什么”。网络探测必须看受控 listener，当前5次连接成功保持未通过。构建和 copied/signed hook 验证资源字节，不代表真实证书签名已验收。

**常见错误：**把历史普通权限运行记成当前沙箱运行；把公网连接失败当隔离；遇到官方初始化失败就自动普通权限重跑。

### 步骤五：按公开事件还原回复顺序

沿 SSE 公开消息阶段和调用开始/结束事件，追到 `useChatRequest` 与 `MessageActivity`。过程采用稳定消息标识与累计文本快照；未知阶段等待权威元数据，不先猜成最终正文。

```text
接受发送，计时开始
  → 等待模型
  → 公开过程文字
  → 实际工具条目，调用结束后更新同一节点
  → 后续公开过程文字
  → 最终回答单独流式显示，过程仅自动收起一次
  → 完成 / 失败 / 停止，固定耗时并保存
```

**练习与预期：**检查工具前后文字、多次调用交错、无工具公开过程和普通无过程回复。开始最终回答后手动展开过程，后续增量与结束仍保持手动选择。

**常见错误：**把工具结果当公开说明；把过程文字先写进最终正文再搬走；每次 render 强制设置外层 `open`。

### 步骤六：理解工具树、分组和状态摘要

工具详情使用原生 `<details>` 与局部树状缩进，展开查看实际参数、结果以及命令的 cwd、stdout/stderr、退出码和进程树证据。连续调用归为同组，公开文字切断分组；单次没有多余组标题，多次默认折叠。

分组 key 使用首个调用 ID，子项 key 使用各自调用 ID。单次增长为多次时，只对未交互的组自动收起一次；用户已经操作的条目和焦点保留。摘要依据真实操作类别和结果生成，全部 `no_change` 显示“文件没有变化”，失败、取消、超时和未确认继续明确显示。

**练习与预期：**比较“已读取文件运行了命令”“编辑了文件运行了命令”和无变化/失败组合；让组在流式中增长，观察节点、开合和焦点保持。

**常见错误：**用数组下标当 key；收到结果就重置折叠；把所有 `completed` 都标成命令成功。

### 步骤七：检查从发送开始的全轮计时

计时在接受发送时记录单调时钟起点，覆盖目录解析、模型等待、流式过程和最终正文。`MessageActivity` 根据实际耗时派生显示，不依赖是否调用工具。完成、失败或停止时固定一条用时 trace；刷新恢复已保存数值，旧记录没有数据时不补造。

| 情况                | 展示                                    |
| ------------------- | --------------------------------------- |
| 等待或流式输出      | `正在处理 · 3秒`，持续累计              |
| 普通无过程/工具回复 | 独立计时行，不创建空折叠区              |
| 短时终态            | `用时 5秒`；不足一秒为 `用时 不到1秒`   |
| 分钟与小时          | `用时 12分钟33秒`、`用时 1小时1分钟1秒` |
| 整分钟              | `用时 1分钟0秒`，保留零秒段             |

**练习与预期：**分别等待完成、等待停止和等待失败，确认只保存一条耗时、终态不增长、刷新不重启计时。总秒数取整后再拆分，避免分钟边界出现“60秒”。

**常见错误：**工具开始时才启动计时；最终正文出现就停止；卸载后仍保留计时器。

### 步骤八：检查 Markdown、代码和链接的两种分支

助手正文与公开过程使用现有 Markdown 渲染。代码由固定 `lowlight 3.3.0` / `highlight.js 11.11.1` 处理11种常用语言，token 转为 React 文本节点。未知语言、超过12000字符、单行超过2000字符或解析异常保留原文，复制保留原始内容和末尾换行。

用户消息用同文件内的 `UserMessageContent` 识别链接，再按源文本位置恢复其余原文。空格、换行、制表符、Markdown/HTML 与代码字面保持；代码内 URL 不变成链接，中文末尾标点位于裸网址之外。编辑、复制和存储仍使用原始消息。

合法 HTTP/HTTPS 统一蓝色 `#0969da` 与下划线，点击沿 `ExternalLink` → `window.api.openExternal` → preload → `external:open` → `shell.openExternal`。不接受带凭据的 URL；无效地址不呈现误导性的蓝色可点样式。本地路径目前仍被过滤。

**练习与预期：**分别发送裸网址及 `[Codeg](https://github.com/spacering-net/codeg)`，比较用户气泡、公开过程和最终正文的链接；同时检查缩进、代码字面、未知语言和精确复制。

**常见错误：**只改 CSS，忽略用户分支没有链接元素；把用户整段文本按助手 Markdown 重排；把本地路径交给浏览器外链入口。

### 步骤九：保持阅读位置、焦点和保存恢复

`useChatWorkspace` 只在底部跟随状态自动滚动。用户主动向上阅读，包括小幅上滚或 `Shift + Space` 翻页后，流式增量保留阅读位置；向下回到底部恢复跟随。折叠内容中的焦点移到直接摘要，生成结束不抢用户已选中的消息区或侧栏焦点。

工具文件名用浅灰下划线及完整路径 `title`，书本、铅笔、文件和终端图标区分操作；目前文件名仍是 `<span>`。工具/组摘要的键盘焦点为2px蓝色圆角框。失败或取消保留实际调用前缀，未完成协议不参与后续模型历史。

**练习与预期：**用鼠标和 Enter 操作工具、用滚轮和键盘阅读历史，再保存刷新。顺序、终态和用时恢复，缺失的历史详情不补造；文件样式不会被误记为点击查看已实现。

**常见错误：**每次增量都滚到底部；自动折叠造成焦点消失；结束生成后覆盖用户焦点。
