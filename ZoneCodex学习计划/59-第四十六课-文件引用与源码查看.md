## 1. 本课目标与前置条件

完成一个可观察的闭环：**点击消息中的文件引用或工具文件名，在应用右侧查看文本源码，定位引用的行号；关闭后继续阅读聊天。**沿用当前 Electron、React、TypeScript 与样式，不增加新的目录授权流程。

## 2. 用 Vue 经验理解本课

这相当于“列表中点文件 → 调后端读取 → 右侧详情展示”，但 Electron 的 renderer 不能直接使用 `fs`。组件负责点击与展示，preload 传递严格参数，主进程核对来源并读取。

| Vue 经验                | 本课迁移                                         |
| ----------------------- | ------------------------------------------------ |
| 点击行打开详情          | 正文引用和工具文件名都调用同一个 `openFile`      |
| `computed` 解析展示目标 | 引用解析得到路径和行号，不在组件里散落多套正则   |
| `ref` 与异步请求代次    | 新文件、会话切换或关闭后丢弃旧读取结果           |
| 插槽里的独立按钮        | 工具 `<summary>` 内文件控件与折叠动作分别响应    |
| 详情页组件状态          | 源码面板保存临时查看状态，聊天消息仍保存原始文字 |

窗口来源、会话归属、文件路径形式、现有读取规则和本机文件权限分别核对。当前 `permission-policy.ts` 对 `read` 返回允许；这不等于跳过路径/文件身份检查，也不应改成“所有只读只能在工作区内”。

## 4. 按依赖顺序实施

### 步骤一：定义文件引用与内容来源

先将网页和文件分类，再解析本地行号，避免 Windows 盘符被当成 URL scheme。优先支持结构明确的 Markdown 文件链接与真实工具目标，用户显式文件链接也走同一入口；普通文本和代码中的路径不随意猜成可操作文件。

本课已支持的引用示例（以下是输入文本）：

```text
[MessageList.tsx](src/renderer/src/features/chat/MessageList.tsx:58)
[api.ts](D:/AiTools/ZoneCodex/ZoneCodex/src/shared/api.ts#L45)
[一段源码](<D:/我的项目/a b.ts#L12-L18>)
[课程记录](/D:/AiTools/ZoneCodex/ZoneCodex/ZoneCodex学习计划/59-第四十六课-文件引用与源码查看.md)
```

路径含空格时遵循 Markdown 地址写法，例如使用 `<...>` 包围目标或正确编码；路径规范化由主进程完成。明确支持 `path:12`、`#L12` 与 `#L12-L18`；从末尾识别行号，不能按第一个冒号切掉 `D:`。行号为正整数，结束行不小于起始行；纯 `#标题` 不识别为本地文件，沿用现有锚点处理。

链接显示名称、真实目标和文档标题分别处理。上述“课程记录”是 `children` 显示名，点击使用地址中的真实文件，不把显示名当作路径；源码面板标题为主进程返回的实际文件名 `59-第四十六课-文件引用与源码查看.md`，文档内部的一级标题则是“第四十六课：文件引用与源码查看”。悬停提示显示解码后的真实路径和行号。共享链接解析器兼容 Codex 的 `/D:/...`，仅将明确的单个前导斜杠盘符形式转为 `D:/...` 后交给既有主进程校验，不放开网络路径或设备路径。

实际共享的最小引用结构：

```ts
type FileReference = {
  path: string
  startLine?: number
  endLine?: number
}
```

实际 `FileViewRequest` 包含 `requestId`、`conversationId`、`reference` 和 `source`。本地来源为 `{ kind: 'local', workspaceId?, executionId? }`，快照来源为 `{ kind: 'snapshot', snapshotId }`。消息通过 `ToolRun.userId` / `assistantId` 关联原运行范围；主进程以只读方式解析当前上下文，相对路径必须匹配原 `executionId`，不相信 renderer 的根目录。本地绝对路径沿当前读取规则处理；四字段 `ExecutionInfo` 与版本6均保持。

**练习与预期：**列出网页、本地绝对路径、相对路径、盘符、空格/中文和无效行号的解析结果。原 HTTP/HTTPS 点击不变，本地引用进入文件查看，不进入 `shell.openExternal`。

**常见错误：**用 `new URL()` 的失败作为全部文件判定；接受任意协议；把 `file://` 或 `vscode://` 交给浏览器作为查看器。

### 步骤二：主进程确定实际读取目标

本地文件使用 `canonicalLocalPath` 等现有路径依据，再核对普通文件、文件身份、读取规则与本机权限。相对路径使用引用所属的可信运行目录；历史记录保存的 cwd 是来源提示，不是恢复授权。当前范围失效或无法可靠关联时提示明确结果，不能把旧会话的相对路径悄悄拼到新目录。

普通本地引用查看**点击时的磁盘内容**，不是模型以前读到的正文。`read_workspace_file` 的实际结果中若已有规范化 `output.path`，优先将它作为工具引用目标；无完整结果时只使用已有、可核对的参数。

`read_project_file` 是快照 alias，须通过 `captureProjectAccess(windowId, conversationId, snapshotId)` 查到对应快照。本课快照引用查看该快照文本，并用简短来源标签说明；不能将 alias 当成本地 cwd 下文件，不能静默改为当前磁盘版本。快照失效时给出结果，不恢复旧 grant。

**练习与预期：**同名文件分别存在于工作区、默认目录和快照时，正确显示被点击来源；绝对路径按当前读取规则处理，不因位于可写根外就要求目录级批准。

**常见错误：**相信 renderer 传来的 root；把只读根等同可写根；用旧工具输出正文冒充当前文件；让快照 alias 绕过快照绑定。

### 步骤三：形成有界、真实的文本结果

不要直接把模型工具的返回 JSON 当成源码查看器。现有 `read_workspace_file` 有128KiB、最多100行和约11000字符结果限制，长行也会截断；它不能代表整份文件。

查看器采用独立的 **1MiB 字节上限与20000行上限**；UTF-8（含 BOM）文本可查看，BOM 不显示为源码字符。无法可靠解码、二进制、目录或超限文件返回简短说明，超限不显示部分内容。读取最多获取上限加1字节，读取前后核对文件身份、大小、时间及最终路径，变化时明确失败，避免无限读取增长中的文件。分行使用 CRLF / LF / CR，空文件显示1行，末尾换行保留尾部空行；原始换行作为文本节点保留。

文本以 React 文本节点显示，保留空行、缩进和换行语义。高亮沿用现有预算；未知语言、超长代码或解析失败回退纯文本，不能隐藏内容或误称完整。行号定位超过实际末尾时显示文件和简短定位提示，不能编造空白行。

**练习与预期：**空文件、中文 CRLF 文件、无末尾换行、二进制、非法编码、大文件和超长行均有准确结果。显示限额与模型工具限额分别说明，产品不显示内部 IPC 诊断。

**常见错误：**只检查扩展名就认定文本；完整 `readFile` 后才检查无限增长的文件；截断后不说明；把源码 `.md` 再渲染成 Markdown 页面。

### 步骤四：接通严格的只读 IPC 与 preload

共享请求/结果采用可判别状态，如 `ready` / `error`，结果包含匹配的请求 ID、会话、实际目标和文本来源。main 使用 `getIpcWindow` 核对主页面来源，解析载荷，再根据对应来源核对执行上下文或快照；preload 同样解析返回并核对身份。

实际调用链为正文/工具控件 → `useFileView` → 平铺 `window.api.readFileView` → `projectAPI` 严格解析 → `project:read-file-view` → `getIpcWindow` → 当前本地或快照读取 → 严格结果校验 → `FileViewPanel`。`app-runtime.ts` 注册接口与窗口清理。查看器解析默认目录时设置 `createDefaultDirectory: false`，不会因查看创建目录；其他执行入口保持原默认行为。文件内容不写回聊天库，也不发送给模型；没有新增写入、命令或批准入口。

**练习与预期：**有效读取沿 renderer → preload → IPC → main → 结果返回。无效 ID、载荷、非主 frame、失效 workspace/snapshot 返回明确失败，不读取错误来源。

**常见错误：**renderer 导入 Node `fs`；主进程只检查路径字符串而不检查来源；旧缓存内容让失效请求仍显示成功。

### 步骤五：建立查看状态与迟到结果保护

独立 Hook 管理 `idle → loading → ready/error`，记录 generation、请求 ID、会话和对应 workspace/snapshot。打开新目标、关闭、会话切换、相关上下文失效或卸载时使旧请求失效，迟到返回不能覆盖新文件或重新打开面板。

源码查看是用户阅读动作，不沿用修改预览的 `selecting` 全局互斥；只读面板不因此阻塞已有回复流式输出。保持单个当前查看目标即可，临时路径和内容不写入版本6会话库；刷新后不恢复旧执行许可或旧读取结果。

**练习与预期：**先点 A 再点 B，A 后返回仍保持 B；读取中关闭不重开；切到另一会话不显示前一会话文件。正在生成时也能查看已存在的引用，未建立可信上下文时明确不能读取。

**常见错误：**只在组件卸载时防迟到，遗漏同组件切会话；显示 loading 时还保留旧文件正文；把查看动作当新 Agent 任务计时。

### 步骤六：添加实际右侧源码面板

在工作台内容区域组装聊天和只读面板，App 继续负责组装。面板包含文件名、简短来源/路径、关闭按钮、加载/错误状态、行号与源码；需要定位时等待真实文本和对应行节点出现，再滚到目标行并做清晰标记。

引用采用现有文件图标和下划线，正文可使用已有蓝色链接语义；工具文件控件保持原摘要的紧凑外观。字体、背景、分隔线、按钮和焦点沿用现有设计。面板自身滚动，不因定位源码行拉动聊天记录；窄窗口调整布局，关闭按钮和输入区仍可使用。

高亮复用现有语言与安全文本渲染，不把文件 HTML 插入 DOM，不自动执行源码或加载远程内容。现有修改预览和命令审查继续属于各自功能，文件查看不触发它们。

**练习与预期：**无行号从开头查看，单行/行范围定位准确；长行可以横向阅读。窄窗口下文件与聊天均不挤坏输入、批准浮窗或左侧列表。

**常见错误：**误称现有差异面板已经是右侧源码面板；把整个应用改为编辑器；给查看流程添加用户未请求的功能按钮。

### 步骤七：正文和工具共用入口，保留键盘与折叠

Markdown 的 `urlTransform`、`components.a` 及 `UserMessageContent` 链接筛选要一起分流。用户其余原文、空格和代码字面继续保持，网页 URL 不受文件识别影响。传递引用所属会话与来源，不在各消息组件内各建查看状态。

工具文件控件位于 `<summary>` 时，鼠标及 Enter/Space 开文件不能同时改变工具折叠；summary 自身仍可正常开合。保留第45课稳定调用/分组 key、一次自动收起和手动开合。目录/搜索目标或尚无文件的失败调用按真实类型处理，不把所有摘要都改成可查看源码的文件。

Escape 只关闭当前查看面板，消费事件后避免同时触发 App 的左栏关闭。关闭返焦点到仍存在、可见的原引用；触发器已经被折叠或会话切换时使用当前可用目标，不返回旧会话节点。

**练习与预期：**点击工具文件名打开源码但工具开合状态保持；按 summary 的 Enter 仍展开详情；Tab 可到文件控件，Enter/Space 可查看。关闭后继续在原阅读位置操作。

**常见错误：**只处理鼠标冒泡；文件按钮点击顺便折叠父节点；Escape 同时关闭左侧栏；生成完成抢走面板焦点。

### 步骤八：接入公开说明与真实文件引用提示词
