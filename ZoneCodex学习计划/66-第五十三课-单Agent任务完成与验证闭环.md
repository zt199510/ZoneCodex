## 1. 本课目标与前置条件

证明当前一个Agent能从明确的任务输入出发，通过已有工具完成一个真实、受控且可独立核对的任务：**搜索定位 → 按需读取 → 局部修改已有业务源码 → 实际运行测试 → 根据失败反馈必要时继续修正 → 重读与重测 → 汇报真实结果 → 整进程重开核对。**先建立任务验收基线，再安排UI与Agent逻辑拆分和无界面入口。

“模型回答完成”“工具返回成功”“内部任务状态为completed”和“用户要求已经完成”分别记录。当前`agent-runner.ts`在工具循环正常返回后会更新任务状态，它没有独立验证业务测试、修改范围或用户全部验收条件。本课用预先固定的测试和外部文件核对证明完成，不为此新增自动评分器、任务完成判定UI或另一套Agent引擎。

若现有能力已经满足，主要产物就是可复跑的隔离任务、真实运行证据和验收文档；只修复验收实际暴露的必要问题，不为了课号强行修改业务源码。若需结构更新，按[未发布阶段约定](05-后续课程编写约定.md#未发布阶段的结构更新约定2026-10-08)采用唯一当前契约，不恢复旧兼容或迁移链，不自动清空用户库、搬动工作目录、提交或重置Git。

保持默认`gpt-6.1-sol`、首次请求后最多五次模型自动重试、第45–52课交互、计划只读与明确执行、三种授权、停止与迟到隔离、设置页与侧栏、多图、文本附件、目录绑定及已有未提交改动。第52课已取消固定8次工具/9轮请求和任务4分钟总时限，不能恢复它们；这不意味着单个命令、网络请求、审批或历史容量无限。

跨轮工具历史选取/发送原300项、64000字符门槛已按第52课第15节新增授权取消，不能在本课恢复；当前仍保留每轮内部协议记录160项（含预留项）、逐轮128000字符和整份输入序列化后128000字符等容量保护。本课选择短小、明确、可复跑的任务，**上下文整理与任务续接后置**。代表性短任务若频繁触发仍保留的历史/完整输入上限，应记为阻塞及未通过项，不删除这些上限、清空协议、切会话或拆成若干人工修复后宣称一次Agent任务完成。

本课不实施UI与Agent拆分、无界面命令行入口、MCP、SSH、并发Agent、长任务压缩或任意大小文件事务。后续第54课安排UI与Agent逻辑拆分，第55课安排无界面Agent命令行/脚本入口，二者目前只是安排，不在本课提前创建或实施。

## 4. 按依赖顺序安排练习

### 步骤一：核对基线和可观察的任务合同

先读取本课、编写约定、结构地图、学习进度和第52课相关片段，核对当前源码、Git状态及已有未提交改动。记录HEAD、相关源码和配置hash，不提交、重置或覆盖已有改动。按需读取即可，不要求为了核对累计读完整个工程。

先写出任务允许修改的业务文件、预期行为、禁止修改的测试与夹具、实际测试命令、完成条件及证据位置。创建时没有真实验收结果；实施时不能沿用第51/52课通过数。

**预期效果：**一次任务的输入、允许改动和完成证据清楚可查。**常见错误：**先让模型随意做点事，事后挑选成功结果；把completed作为唯一验收条件；未保存基线就运行可能写文件的任务。

### 步骤二：准备隔离数据、自制业务项目和固定测试

开发版和Windows目录包分别使用新的UUID数据目录、会话与自制项目，不读取用户原会话库，不上传此前用户截图。至少一个主任务包含已有UTF-8业务源码、预先固定的可执行测试以及应保持原字节的旁路文件。可采用小型价格计算或文本解析项目，不用只改注释、标记或拼写代替业务完成验收。

主任务至少包含一个数百行、超过32 KiB且不超过128 KiB的已有源码文件，目标只需相关片段；记录UTF-8、BOM、LF/CRLF和尾换行数量。模型不必完整读取或累计覆盖全文。原字节与最终编码候选分别最多128 KiB，patch6000字符、参数及读取/输出原预算保持；`create_workspace_file`仍80行/2000字符，附件及原全文提案保持现有范围。较大测试项目由验收准备阶段生成，不能因此扩大模型新建文件工具。

测试与预期在模型开始前固定，保存测试/夹具hash。明确只允许修改业务目标；模型不得改测试、删断言、改期望、跳过检查或改测试入口来通过。验收前后独立核对受保护文件。可通过夹具权限限制写入，并保留hash核验；不能只相信模型说“没有修改测试”。

先在原项目上真实运行测试，保存红测试、真实退出码和失败输出，证明故障存在。此处是验收器验证初始夹具，**不是模型修改后失败并继续修正的证据**。测试要求短、输出足够诊断且在现有单命令时限内，不设计依赖无限日志、额外网络下载或shell拼接的任务。

**预期效果：**任务确有业务故障，测试能判断修复且不会被模型改题。**常见错误：**把整个夹具的创建算作Agent成果；测试和源码一起交给模型改；用验收器代改目标；把初始红测试记成模型迭代。

### 步骤三：真实模型先计划，再明确执行

保持默认真实`gpt-6.1-sol`，先发送计划请求。核对搜索和按需读取真实发生，计划输出足够明确；计划期间业务文件、测试与旁路文件的原字节不变，不能运行测试命令或提交可执行修改。信息充分时可直接给方案，需要确认时按现有计划提问卡处理；回答问题不能成为写入批准。

明确切到执行并发送实施要求；切换模式本身不发送请求。执行本请求重新取得必要片段、原字节hash和真实可见行，不从计划或历史继承补丁凭据。允许采用本轮相关窗口生成单已有文件的精确局部补丁，沿现有三授权/准备/提交链运行，不放宽精确匹配、版本、格式、取消与备份保护。

每个完整主任务及失败迭代专项都须在同一次明确执行请求内完成，记录execute requestId及其中真实工具/完成模型轮和传输重试。计划请求单独计数；不通过人工追加多轮修正提示、切会话或外部修代码拼成一次Agent自主闭环。有限独立场景各自使用新UUID和自己的单次执行请求，不跨场景合并成果。

保存模型实际请求/响应状态、原始工具参数和返回、公开过程消息及最终答复；日志不得包含密钥。真实主模型、独立标题请求和自动审批请求分开计数，标题网络失败不能替换主任务结果。

**预期效果：**完整任务由真实模型决策和调用现有工具完成，计划保持只读。**常见错误：**只在测试脚本里直接调用工具；把计划回答当批准；验收器伪造模型输出或提前给执行凭据；标题成功代替任务成功。

### 步骤四：由Agent实际运行测试并处理真实失败

使用现有`run_workspace_command(program, args, cwd, sandbox_permissions, justification)`。先核对程序路径和参数数组，例如已验证的Node程序加固定测试脚本参数；`cwd`是自制项目目录。工具没有新增`command`或无限等待参数，不假设它接受多条shell命令、管道或复杂复合文本。权限保持原策略，需要范围外访问时给具体理由，拒绝或沙箱失败不能自动转为非沙箱重试。

核对Agent实际调用测试、收到真实stdout/stderr、退出码及截断/超时状态，随后重读修改位置并在必要修正后重测。当前命令非零退出以`failed`结果返回模型，不等于必然中断整个Agent；超时结果另含进程树停止状态，不能当作普通红测试。验收器另外运行固定测试作为最终独立检查，但这次运行不能替代Agent本应完成的测试调用。

建立独立的“失败反馈后继续修正”专项：模型已经进行至少一次实际业务修改，随后实际测试失败；模型收到该失败结果，继续按需读取、修正业务文件并重新运行同一受保护测试，最终由外部核验。该失败必须是实际命令与实际业务结果，不能注入虚假输出、在运行中偷偷改测试、回写模型答案或由验收器修代码。

可预先准备含两处相互独立故障的可重复任务与固定测试，提高观察失败后修正的机会。每版最多使用3个预先固定的独立自制场景，不无限重跑直到模型犯错。如果模型一次修对，记录一次成功，不编造迭代；在这个有限集合内另开新UUID的自制专项任务验收。若仍未观察到真实失败→进一步修正→重验，该专项记未覆盖/待补，不能用初始红测试或历史第50课纠错代替，也不故意指示错误补丁或注入假失败。

**预期效果：**看到真正的执行、反馈和修正闭环。**常见错误：**退出码0就宣布所有要求满足；测试被截断却推测通过；命令超时也写成功；把传输自动重试、补丁语法失败或原项目红测试当成测试失败后的业务修正。

### 步骤五：独立核对完成、未完成与副作用

验收器比较目标原字节hash、最终hash与精确diff，核对业务预期、固定测试和测试/旁路文件hash、未读正文及原BOM/换行/尾换行格式。根据工具原始输出列出实际读取范围，证明没有要求模型读完整文件，也没有把内部整文件候选发送给模型。只要测试被改、范围越界、未读正文变化或结果不确定，不能判主任务完成。

对停止、授权拒绝、工具错误、上下文/目录失效、冲突及网络失败分层检查，保留当前实际文件与进程结果。已经写过文件或启动命令后失败，应先核对副作用，再决定是否继续；不自动重放整轮，不依赖“重新请求”覆盖旧结果。取消后迟到输出不能恢复请求、授权或修改文件。

三种授权分别沿现有策略验收：真实主闭环至少记录实际使用模式；其他批准/拒绝/取消及异常可以用隔离合成专项覆盖，但必须标明真实模型、真实主进程或合成传输的范围。不能仅因完全访问成功就宣称三种模式全都联网通过，也不为了本课要求额外上传图片或完整重跑所有历史场景。
