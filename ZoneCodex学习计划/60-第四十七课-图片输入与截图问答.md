## 1. 本课目标与前置条件

完成一个可观察的闭环：**在同一个聊天输入框选择或粘贴一张截图，预览后附带文字问题发送，AI 实际收到图片并回答，用户消息显示所发送的同一张图片。**保留第45课公开过程、工具树、最终答复、计时与三种授权模式，以及第46课文件引用、右侧源码与键盘焦点。

### 模型与网关依据

已读取 OpenAI Docs 的[图像输入指南](https://developers.openai.com/api/docs/guides/images-vision)和[`gpt-6.1-sol` 模型页](https://developers.openai.com/api/docs/models/gpt-6.1-sol)。官方模型页列明 text/image 输入、text 输出与 Responses 支持；图像指南给出 `input_image`、`image_url` 及 Base64 data URL 输入。本课继续使用用户当前默认模型 `gpt-6.1-sol`，不自动修改模型配置。

官方支持不等于当前网关已经兼容。创建时没有调用模型、上传图片或读取模型凭据；实施时须在现有 Responses SSE 链路上用合成截图核对真实兼容性。网关拒绝图像时明确返回失败，不静默改为只发送文件名、文字或 OCR 摘要，也不另建产品模拟聊天入口。

前置复习：能够解释 `ChatComposer → useChatRequest → agent-runner → tool-loop → response-client` 的实际链路，区分文本附件快照、用户消息展示元数据和模型协议历史。第46课已获用户完成确认，自测仍待作答；第45课网络探测5次连接成功的未通过项、沙箱命令真实模型端到端及真实证书待验收继续保留。

## 4. 按依赖顺序实施

### 步骤一：先确定输入范围、资源限额与失效规则

将“用户文字”“文本附件快照”“图片快照”分别建模。首版每条消息最多1张 PNG/JPEG，要求非空文字；添加即允许本轮随问题发送到已配置模型。用户只需看到图片、格式/超限错误和“图片不随历史保存”的简短说明，不展示 imageId、IPC 或内部授权参数。

实际采用本地有界预算：单图压缩编码字节最多5 MiB、每边最多4096像素、总像素最多1600万；每窗口图片编码字节合计最多20 MiB，最多1000个资源，缩略图最长边160像素且最多256 KiB。主进程先检查PNG/JPEG结构、CRC和尺寸，再通过专用非持久session的独立sandbox窗口解码。PNG额外在同一沙箱窗口中按1024字节压缩输入分块、逐解压chunk核对扫描行预算、filter和完整zlib/Adler32，支持Adam7且不保存全部解压数据。5秒超时销毁窗口并停止等待，成功、失败和取消都清理；这不等同于强制终止独立OS进程，Chromium工作线程由引擎管理。它们是本课产品限额，不是官方API上限；不自动缩小发送原图或淘汰仍可预览/重试的图片。

图片只存在本次会话的内存资源中。替换或移除只释放对应待发图，已经发送的图片按自己的消息绑定保留；切换会话、清空/归档当前会话、刷新、窗口导航/关闭或资源显式撤销时使相关图片失效并释放。重新进入旧会话显示文字说明，重新问图须再添加。遇到总量上限明确提示，不静默使用另一张图。

**练习与预期：**列出待发、已冻结、已发送、可重试和已失效五种状态及其拥有者；文档和产品说明与首版临时保存策略一致。

**常见错误：**给 `.png` 放开文本文件扩展名；把旧 `ChatAttachment.lines` 当成图像属性；预览成功就标为识图成功；隐式扩大历史资源能力。

### 步骤二：主进程导入并拥有同一张图片

文件选择使用主进程原生对话框，核对实际路径、普通文件及身份，按上限加1字节有界读取，读取前后核对变化，不信任 renderer 给出的任意磁盘地址。剪贴板入口由用户在输入框的 paste 事件触发：提取支持的图片候选，先检查大小，再将有界字节送到严格接口，主进程重新核对；普通文字粘贴照常处理，不轮询剪贴板。

核对真实 PNG/JPEG 格式和解码结果，限制编码字节、尺寸、像素及处理时间；扩展名或候选 MIME 不能单独作为依据。裁定格式前不为任意格式调用无界解码；尽量在实际解码前核对可获得的尺寸。剪贴板图按确定格式编码后再次检查，损坏/空图/超限明确失败。

主进程生成不可猜测的图片身份并保存不可变字节、实际 MIME、尺寸、有限显示名和归属。接口每次核对 `getIpcWindow` 主页面来源、窗口、会话与目标图片；无会话时先沿现有控制器建立有效会话，再导入，不把 `null` 会话当通配授权。预览结果不能成为任意读文件、远程取图或写文件入口。

**练习与预期：**选择后修改/删除原磁盘图片，已确认快照仍一致；损坏图、伪扩展名、超限、跨会话/窗口与过期 ID 得到明确结果。图片入口取消或失败不替换已有合法图片。

**常见错误：**模型请求时重新读取已经变化的磁盘路径；直接信任 data URL/MIME；renderer 自选 `imageId`；把本轮图片授权与写入/命令权限混用。

### 步骤三：严格接通共享类型、IPC 与清理

定义最小图片描述，如 `imageId`、`name`、`mime`、`bytes`、`width`、`height`，不混进文本 `ProjectSelection.files`。统一请求上下文可增加严格的可选图片引用，renderer 只传引用与会话，不把图片像素或路径当成执行授权；图片不增加工具白名单或新的 `ToolScope` 权限。

在 `api.ts → preload/project-api.ts → project-ipc.ts → image-access` 接通导入、预览、撤销等必要方法；实际 Agent 请求经过 `project.ts`、preload/agent、main 解析与捕获。取消、导航、窗口关闭和卸载清理在 `app-runtime` 完整配置，图片导入纳入既有 `useOperation` 与主进程互斥检查，生成期间不能替换或移除本轮图。

**练习与预期：**严格校验额外字段、错误类型、错误来源、重复释放与迟到结果；真实 renderer/preload/IPC/main 能完成一次导入和预览，清理后不能恢复旧身份。

**常见错误：**只增加 TS 类型没有运行时解析；只配置导入没有导航清理；用字符串 ID 或保存的说明文字恢复图片授权。

### 步骤四：输入框选择、粘贴、缩略图与只读预览

在原“＋”浮层新增“图片”入口，保留文本文件、权限按钮和批准浮窗位置。图片卡片位于输入框内部，提供有限名称、缩略图、预览与移除。首版一次粘贴多张图明确提示只支持一张，不默默选择某张；普通文字粘贴、中文输入法、Enter/Shift+Enter 和原文字限制保持。

Hook 以图片导入代次和会话核对 A/B、取消与切换，后到的旧结果不能覆盖新图。只有主进程确认后才原子替换待发图片；失败时保留旧图和文字。对象 URL 在替换、失效和卸载时撤销，缩略图使用固定有界尺寸，不能因加载改变聊天阅读锚点。

预览优先使用原生 `dialog`；打开后焦点在弹窗内，Tab、关闭、Escape 只处理当前预览，并合法返回仍可见触发器。与第46课源码面板及已有 popover 共存，不让同一次 Escape 同时关闭图片、源码和侧栏；移除/预览按钮不得触发表单发送。

**练习与预期：**文件选择与粘贴走同一个确认链；取消保留草稿；中文文字粘贴仍正常；窄窗口、键盘操作和关闭返焦点均可用。

**常见错误：**整个输入框粘贴一律 `preventDefault`；图片按钮使用默认 submit；图片显示原本文件路径而非快照；预览关闭时抢走源码焦点。

### 步骤五：冻结发送、消息显示、重试与编辑

发送前同步冻结文字、图片身份、文本快照、工作区、运行环境与权限。现有 `useChatRequest.send` 的 boolean 只表示 renderer 本地接受，不代表主进程已确认图片；图片流程须接入准备/确认阶段或等效主进程回执，先核对同一图片的归属、有效性及预算，再回到现有发送入口。等待时记录草稿版本和请求代次，迟到确认不能清掉用户随后输入的新内容。

准备确认或本地提交被拒绝时保留文字及待发图；只有对应发送被接受才清理该份草稿。正式主进程任务与每次传输仍复核原图和既有执行上下文，接受后的模型/上下文错误按原终态流程保存，不将准备成功当作模型发送成功。首次会话标题仍依据用户问题，避免图片保存说明成为标题。

请求接受后清待发卡片和文字，将同一图片关联到确定的用户消息；生成、停止或失败后消息图片仍依据原图绑定。图片只用运行时映射，不从当前草稿、聊天里的文件名或最新选择读取。

失败/取消重试保存原图引用，原图失效时明确要求重新添加；不能使用新草稿图，也不能把原图请求降为纯文字。叠加原 execution/workspace/snapshot/permission 与 `sideEffectStarted` 保护。编辑最后用户问题时，先验证原图仍可用及新问题长度，再裁剪旧历史并发起；失效时不破坏现有消息。

**练习与预期：**发图A失败后待发区选图B，重试仍是A；A已失效则拒绝。编辑重发保留A，接受后才清草稿。清空/切会话导致迟到响应丢弃，并正确释放资源。

**常见错误：**只保存展示元数据就声称可重试；先删除旧回答才发现图片失效；图片导入后自动发送；请求拒绝仍清空草稿。

### 步骤六：真实发送 `input_image`，保持统一工具循环

图片数据只在主进程实际网络发送前组装。本课首版可使用经校验快照产生的 data URL，无需额外 Files API 上传。Responses 用户项的结构示意如下；`confirmedImageDataUrl` 必须来自主进程已捕获的图片，不是用户输入的 URL：

```ts
{
  role: 'user',
  content: [
    { type: 'input_text', text: checkedPrompt },
    { type: 'input_image', image_url: confirmedImageDataUrl }
  ]
}
```

现有 `runToolLoop` 的文字记录继续用于工具与结果校验。实时传输适配器克隆输入，仅将确定 `turnStart` 的当前用户项投影为多模态；本轮每次模型调用仍使用同一已捕获图片，保留后续实际助手、推理和工具输出，不凭“最后一个 user”猜位置，也不原地污染返回的 `items`。无图时保留原请求行为。

文字协议的128000/64000字符上限保持，图片编码字节、Base64 增量与 HTTP 载荷按独立上限检查；不能为容纳图片而放开全部历史限额。沿用 Responses SSE、取消信号、计时、工具次数与超时、`store: false` 和原授权链，不增加第二个聊天模式或绕过模型工具循环。

图片中的文字属于不可信内容，不能自行赋予文件/命令权限。回答基于实际可见内容，读不清时坦诚说明；简单看图问题无需伪造“图片读取工具”。需要本地工具的任务继续遵循第46课工具前公开说明与实际结果规则。

**练习与预期：**离线传输检查观察实际 `input_image`，核对 MIME/尺寸/快照摘要，不把完整 data URL 写进日志；真实网关验收确认只能从图片得出的文字或布局。图片＋文本附件仍使用原只读快照工具。

**常见错误：**只把路径或文件名塞进 prompt；发 Chat Completions 的 `image_url` 嵌套对象冒充 Responses schema；一次工具后续请求丢图；放宽历史上限而没有独立图片预算。

### 步骤七：保持版本6，明确审计与不可重放边界

本课采用**内存图片＋版本6文字记录**，不新增持久图片字段或版本7。给图片轮用户文字追加统一固定说明，例如：

```text
[本轮附有一张临时图片；图片不随历史保存，重新问图请再次添加。]
```

用户原问题保持；说明文字计入2000字符上限及保存容量，发送前预检。`active.prompt`、保存用户 `content`、结果预期 prompt 和 `ToolRun.items[0].content` 使用同一完整字符串，保持现有消息关联与完整/未完成记录核对。它是明确的文字审计投影，不能称为完整多模态原始请求；图片身份、像素、预览 URL 和授权不写入会话库、工具 `items`、任务、trace 或标题请求。

编辑器展示原问题，将系统说明作为独立状态处理；是否属于图片轮依据原保存消息与运行时图片绑定核对，不能让用户删除或改写编辑框中的标记就解除原图身份。编辑重发再次由系统构造说明，原图失效仍拒绝；普通用户自己输入相同文字也不能获得图片授权。

图片轮在后续 `selectToolHistory` 的逆向选择中构成边界：**在跳过 failed/cancelled 分支之前核对图片标记，遇到即停止**，不选择该轮，不跨过去复用更早轮次。主进程在解析历史后独立拒绝带图片标记的旧轮重放，不能只依赖 renderer 截断；存档解析仍接受合法文字审计，不因不可重放使版本6加载失败。后续纯文字轮可形成新的连续历史。

该标记只用于说明与拒绝复用，不授予图片能力；真正发送仍须主进程有效图片授权。旧图的 encrypted reasoning 不在缺图时重新发送。重启后的消息保留问题和明确说明，缩略图失效；旧图重试/编辑不静默降级，图片追问须重新添加。主进程可记录不含像素的实际发送证据，但不以文字投影证明完整 wire payload。

**练习与预期：**图片轮后继续文字聊天、失败图片轮夹在历史中、刷新和版本1–5迁移均不恢复旧图或其推理。检查保存文件无 Base64、data URL、运行时图片 ID；伪造标记不能获得图像授权。

**常见错误：**返回带 Base64 的 `items` 导致 strict parser/容量失败；只处理完成图片轮，失败轮却被跳过后跨越边界；恢复消息文件名就重新读盘；脱敏了图片却复用其推理。

### 步骤八：异常、释放、键盘与既有交互回归

分别处理选择取消、剪贴板无图/多图、损坏/超限、上下文变化、资源失效、网关不支持、HTTP/SSE错误、超时和用户停止。导入失败保留当前草稿；任务失败保存如实终态和已有公开输出。运行中禁止变更本轮图，来源失效按已有任务取消路径处理；每次实际发送前复核引用，结束解绑任务引用。

清空、切会话、归档当前会话、刷新/导航/窗口关闭与卸载均释放图片、预览 URL 和相关重试来源。达到内存上限给出简短提示，不靠永久缓存或无界引用计数维持表面正常。消息复制保持文字语义，不复制图片 bytes；模型 Markdown 图片仍占位。

核对第45课计时、过程/最终顺序、工具分组与手动展开、三模式与批准浮窗；第46课文件来源、summary 内文件键盘、源码定位和 Escape；原文本附件的多选/追加/移除、文字草稿、首次标题及保存关闭保护。

**练习与预期：**预览与源码共存、生成中阅读旧消息、上滚后图片加载、窄窗口及键盘关闭都保持合法焦点和阅读位置。无图聊天与原文本附件照常工作。

**常见错误：**全部异常统一吞成“成功”；图片源失效但任务继续；旧请求返回重新打开卡片；改图片流程时顺便改三模式或文件读取规则。

### 步骤九：分层验收与同步实际记录

先做有意义的共享契约、图片格式/预算、来源及历史边界检查，再做真实 Electron 导入、预览、消息和生命周期观察。离线合成传输只证明载荷构造与界面；识图能力需要真实模型/网关及图片问题的独立证据。

沿用类型检查、定向 lint/格式、构建和实际目录打包；开发与打包分别核对真实 preload/IPC/main 与图像处理，记录替身和拦截范围。真实识图验收使用合成截图和明确问题，通过现有配置发送，日志不保存图片字节或密钥。若联机条件不足，明确记录待验收，不用组件/fixture结果代替。

按第5节更新课程、进度、实际结构地图、导航和能力对照；新增源码只有完整接线模块。必要检查与原始证据可放在忽略的 `.ui-check/lesson47/`，不新增一批 tracked `.cjs`，不覆盖第45/46课旧记录。

**练习与预期：**区分方案、组件、真实IPC、合成传输、真实识图与用户反馈，各有准确状态和证据。

**常见错误：**运行构建就标识图通过；测试绕过 preload/main；把本课通过改记为沙箱网络修复；课程自测未作答却标已掌握。
