# 第二十九课：真实 Agent 工具调用与权限闭环

创建日期：2026-09-23。状态：实现已完成，待真实模型桌面验收。

前一课：[明确确认与单条命令受控执行](38-第二十八课-明确确认与单条命令受控执行.md)。第28课已经完成固定 `npm run typecheck` 的一次性确认、执行、输出、取消、超时和清理。本课把模拟命令提案替换为真实 Agent 产生的工具调用，验证完整的 Codex 类权限链路。

## 1. 本课目标

完成以下流程：

```text
用户请求检查项目
  → 真实模型决定是否提出 propose_command
  → 主进程校验固定工具参数
  → 命令审查面板展示提案和目录影响
  → 用户选择目录并检查准备
  → 用户明确确认一次
  → 执行固定 npm run typecheck
  → 输出和终态回到面板
```

本课关注 Agent 是否能正确进入既有工具和权限闭环，不重新设计第28课的执行器。正式界面不提供“真实模型/模拟/流式”选择；Agent 根据当前授权和可用工具处理。mock 仅保留为离线回归入口。

## 2. 与 Codex 的对应关系

Codex 类工作流通常由 Agent 判断是否需要检查、修改或运行命令，再依据权限策略决定是否需要用户批准。这里学习的是这个边界：模型可以提出工具调用，但不能因为提出调用就获得目录、进程或执行许可。

本课不追求复刻 Codex 的全部权限模式，只验证一个最小策略：固定工具、固定参数、用户明确确认、一次性执行和可观察结果。

## 3. 明确边界

允许：

- 真实模型调用现有 `propose_command`。
- 只接受 `npm_typecheck` 模板。
- 复用第27、28课的目录准备和执行接口。
- 将命令提案、执行状态和结果显示在当前会话中。

不允许：

- 模型传入命令字符串、程序名、参数、cwd 或环境变量。
- Agent 自动确认或绕过审查面板。
- 执行历史提案或刷新后恢复执行许可。
- 将命令结果伪装成文件修改结果。
- 增加任意命令、命令队列、自动重试、SSH 或 MCP。

## 4. 先核对当前调用链

先从源码画出实际调用链，不要先改提示词：

```text
ChatWorkspace
  → useConversation / Agent 请求
  → main/agent/agent-ipc.ts
  → propose_command 工具和结构化结果
  → commandProposals 派生卡片
  → CommandReviewPanel
  → command-directory IPC
  → command-execution IPC
```

重点确认：

1. 真实模型的工具参数经过 `parseCommandProposalArgs`，而不是只相信模型 JSON。
2. 提案来源包含当前会话、请求、助手消息、调用和快照标识。
3. 历史中的提案只是展示数据，不能恢复 `grantId`、`preparedId` 或执行权限。
4. 第28课的执行接口仍只从主进程取得目录、程序和参数。

## 5. 实现步骤

### 第一步：真实模型提案

使用当前真实 Agent 入口提出“检查项目类型”的请求。确认模型可以返回普通文本，也可以返回 `propose_command`；两种结果都不能让主进程自动启动命令。

为真实工具调用增加清晰的系统约束：

- 只可提出 `npm_typecheck`。
- 不得声称已经执行。
- 不得传目录、命令文本或环境变量。
- 提案原因必须来自工具参数并限制长度。

### 第二步：提案与面板关联

确认真实模型返回的调用能派生到当前助手消息，而不是只显示一张脱离会话的卡片。切换会话、开始新请求、撤销文件授权或刷新页面后，旧提案不能继续获得执行准备。

### 第三步：接入第28课权限链

在真实提案入口复用现有流程：选择目录、读取脚本、检查准备、明确确认、执行一次。不要在真实模型分支另写一套执行器，也不要把 `preparedId` 放进聊天历史。

### 第四步：错误和拒绝

分别观察以下结果：

- 模型返回非法工具参数：拒绝提案并显示可理解的错误。
- 模型只给出文本：不出现执行按钮。
- 用户关闭审查面板：不执行命令。
- 用户未确认：不启动子进程。
- 目录配置变化：旧准备失效，要求重新检查。
- 命令失败、取消或超时：显示对应终态，不自动重试。

## 6. 验收场景

| 场景 | 必须观察 |
|---|---|
| 真实模型提出固定工具 | 卡片关联当前助手消息，参数不能扩展 |
| 真实模型只回答文本 | 不出现命令执行入口 |
| 用户打开提案 | 显示固定程序、参数、目录影响和确认提示 |
| 未确认直接关闭 | 没有子进程启动 |
| 明确确认 | 只执行一次 `npm run typecheck` |
| 重复点击或旧 ID | 主进程拒绝，不能多开进程 |
| 修改 package.json 后执行 | 准备冲突，旧记录失效 |
| 刷新或切换会话 | 不恢复执行许可 |
| 执行失败/取消/超时 | 状态和输出清楚，不自动重试 |

入口拦截仍应确认：没有调用 `node-pty`，没有写入 `terminal:write`，没有启动第二个 Agent 任务，也没有修改测试目录之外的文件。
