# 第五十课：计划模式与执行切换

创建与实施日期：2026-10-09。状态：**已实施并通过分层验收；用户完整手工确认待补，八道自测待作答。**承接[第49课](62-第四十九课-设置界面与配置持久化.md#第50课建议计划模式与执行切换)。第49课已完成（用户实测确认），设置基础已补齐；本课回到“先研究、形成方案，再明确切换执行”的流程。本课已按用户明确要求直接实施；创建时基线和第7、8节说明保留，实际实现及结果见第9节。

## 1. 本课目标与前置条件

完成一个可观察的闭环：**在现有输入框选择“计划”，读取项目并给出方案；目标项目文件不变。用户明确选择“执行”，发送“按上面的方案实施”，沿用原工具与授权流程完成修改和检查。**

工作方式与授权模式分开：计划决定本轮只研究，执行允许进入已有行动流程；“请求批准 / 帮我批准 / 完全访问权限”继续决定执行批准方式。完全访问权限也不能让计划请求写文件或运行命令，计划不是第四种授权模式。

保持默认 `gpt-6.1-sol`、真实模型 SSE、三种授权模式、第45–49课已验收交互、文本附件、多图及合法历史图片关联。聊天、图片和设置仍正常保存，计划只读不表示应用全盘不写数据。保留全部现有未提交改动、会话目录绑定、设置页右内容区和左侧栏、执行校验、取消与迟到结果隔离。

按[未发布阶段约定](05-后续课程编写约定.md#未发布阶段的结构更新约定2026-10-08)统一必要的当前结构，不恢复旧版本迁移或旧单图 `image` 兼容。创建时为配置版本1、会话版本7及 `defaultDirectory`；实施后配置仍为版本1，会话统一唯一版本8，必需会话 `agentMode` 和消息 `mode`。全部当前读写方已同步，原版本1–7明确拒绝且不自动覆盖、迁移或清空。

本课只做两种工作方式及其完整调用链，不增加独立计划页面、计划管理器、任务排队、自动执行计划、额外全局设置或第四种权限。集成终端入口与会话cwd、密钥管理、外部编辑器、主题、MCP、Skills、SSH和并发后置。

## 2. 用 Vue 经验理解本课

| Vue 中的经验       | React / Electron 中的对应做法         | 本课中的应用                                   |
| ------------------ | ------------------------------------- | ---------------------------------------------- |
| 表单选择值         | 当前输入框的工作方式状态              | 选择计划或执行，不改变授权偏好                 |
| 提交时复制表单     | 接受发送前捕获本轮参数                | 后续界面变化不能改变正在准备或执行的请求       |

| 服务端权限判断     | 主进程工具清单及执行前检查            | 即使模型调用隐藏工具，计划也不能写入或启动命令 |

菜单当前值、本轮捕获值、历史消息模式分别有自己的用途。用户改下一轮模式，不应改变已保存的计划或失败请求的语义。

## 4. 按依赖顺序实施

### 步骤一：明确两种工作方式及共享契约

实际定义为 `AgentMode = 'execute' | 'plan'`，产品显示“执行 / 计划”，初始采用执行；将它与 `ExecutionInfo.mode` 三种授权明确区分。理顺当前 `AgentMode`、`ToolRun.mode` 和真实模型入口的关系，不让保存记录叫计划而实际请求仍按执行处理。

行为模式必须进入本轮真实请求，shared、preload和main均严格解析。未知值明确拒绝，不能无声降为执行；同一轮只有一个确认后的模式。需要的消息或运行元数据随当前会话格式统一更新，避免请求成功却保存失败，或无工具的计划回答重开后丢失模式。

**练习与预期：**列出计划/执行与三种授权的组合，说明为何计划＋完全访问仍只读。

**常见错误：**把`live`改显示名就宣称已贯通；新枚举只在React存在；把计划当成默认权限设置。

### 步骤二：捕获本轮模式，接通保存、重试与编辑

发送被接受前捕获行为模式，与本轮文字、图片组、附件、会话和权限来源一起进入请求快照。等待目录或图片准备期间不读取后来的菜单值；主进程校验后将模式固定给这一轮工具循环与执行器。复用现有busy、保存和关闭确认互斥，不新增请求队列。

用户消息与完成、失败、取消的运行记录保持同一模式。失败重试从原请求来源取得原模式；用户此时选择执行，重试原计划仍是计划。原消息编辑先呈现原模式，用户重新发送前可以明确改为另一模式，编辑发送是新的一轮；原图片组、附件和原有重试范围检查继续生效。

模式元数据不保存执行批准。重开后能恢复消息与方案，不恢复旧授权或自动开始实施；停止仍使用现有requestId/taskId取消链，迟到事件只能更新所属请求。

**练习与预期：**计划失败后切执行再重试，仍按计划运行；编辑时明确改执行，则新轮按执行运行。

**常见错误：**重试读当前菜单；异步准备中模式漂移；只为成功有工具轮保存模式。

### 步骤三：在主进程实现计划只读

计划工具表仅保留已有时间、目录列出、文件搜索和读取能力，按当前工作区/附件范围提供。不给模型文件创建、编辑、运行命令或可执行文件/命令提案工具；方案用正常文字表达，不生成可以点“应用”的计划写入卡片。

工具清单过滤之外，工具循环和执行器也必须检查本轮固定模式，在进入行动、审批、提案、写入或命令启动前明确拒绝。模型伪造调用、附件指令或完全访问模式都不能绕过；拒绝路径不能先启动命令或触发批准后再返回失败。执行模式沿用原行动能力及官方命令执行链。

保留主进程当前目录、scope、revision、取消及执行前复核。读取项目的范围不扩大；历史工具记录只是上下文，不给这一轮授权。这里不重写沙箱、不新增只读权限模式，也不尝试解析“看起来只读”的任意Shell命令。

**练习与预期：**对计划执行器定向尝试写入、命令与两种提案，均拒绝，目标文件、批准及进程启动均不发生。

**常见错误：**只改提示词；只隐藏工具声明却留分发入口；认为完全访问能覆盖计划约束。

### 步骤四：计划方案与执行历史衔接

计划提示词应让模型先研究任务、使用已有只读证据，给出简洁可实施的方案，说明必要假设和待确认问题。计划选中时，即使用户文字说“修改”，也只形成方案，不受现有行动提示词驱动而执行。保持公开commentary、工具活动和最终回答交互，不展示内部推理。

切回执行并发送实施请求后，同一会话中的已完成计划必须成为可用的文字上下文。当前 `selectToolContext` 会在不同模式的运行记录处中断，不能只替换硬编码 `live` 后任由方案消失。沿现有规则保留用户任务与最终方案的语义上下文；跨模式工具协议不擅自重放，旧范围和批准不复用。失败/取消历史仍按原规则处理。

有图片的计划继续携带实际当前及合法历史原图，文本附件沿原快照规则处理；不能为了模式切换少发图片、重排图片或把附件正文当授权。执行阶段重新核对目标文件，计划时读过的内容不替代执行轮的完整读取、冲突检查与批准。

**练习与预期：**计划指出目标文件及修改步骤，切执行只发送“按上面的方案实施”，模型能理解方案并重新读文件后实施。

**常见错误：**计划文本可见但未进入模型上下文；跨模式复制整段工具协议；把计划时的读取证据或用户方案当写入批准。

### 步骤五：同一输入框的简洁入口

在现有附件和权限入口附近增加工作方式选择，显示当前是执行还是计划；两种菜单分别有清楚名称，不挤成一套权限选项。复用现有菜单、键盘、外部关闭和窄窗处理方式，不增加新页面或模态流程。必要时用轻量标记识别计划轮，方案仍是正常Markdown回复，不开发计划管理界面。

运行、准备、审批、保存或关闭确认期间按现有互斥限制修改；切模式不清空文字、图片或附件。键盘发送、中文输入法、粘贴/拖放、图片预览、消息编辑、源码面板及第49课设置导航保持。

用户从计划切到执行只影响下一次明确发送，不自动执行已有方案，不自动发送“实施”。本课不增加全局默认工作方式设置。

**练习与预期：**鼠标和键盘均能选择，窄窗可用；切模式后草稿和附件保持，切执行本身不产生请求。

**常见错误：**选执行立即执行计划；切模式卸载输入框；只在宽窗能打开菜单；改变三种授权的含义。

### 步骤六：完成有意义的分层验收

实施后运行必要的Node/Web类型检查、lint、改动文件格式、构建和Windows目录打包。共享解析、模式快照、跨模式上下文、非法工具拒绝和取消用针对性检查；开发与目录包分别实际观察同一输入框、计划/执行切换及保存恢复。

用隔离数据和自制小项目完成真实模型闭环：计划研究并输出方案，核对目标项目文件不变；用户明确切执行并要求实施，核对实际改动和必要检查。若联机验证无法完成，保留失败与原因，不以固定合成响应宣称模型理解方案或真实实施通过。图片回归使用自制图片，不上传此前用户截图；不读取或输出密钥，不拿用户真实会话库做故障注入。

记录静态、离线逻辑、真实桌面、真实模型和用户反馈各自范围；不把前课通过计数合并为本课验收，不提前标记八题掌握。

**练习与预期：**各层有对应证据，项目改动能区分来自计划还是明确实施，原目录包没有验收注入。

**常见错误：**只有构建就称只读有效；只有一次模型遵循计划就称执行器可靠；把聊天库正常保存算作计划违规写项目。

## 5. 验收条件与手工测试方法

| 场景             | 应观察的结果                                                               |
| ---------------- | -------------------------------------------------------------------------- |
| 入口与三种授权   | 输入框可选择执行/计划，授权菜单独立；计划＋完全访问仍只读                  |
| 主进程只读       | 写入、命令及可执行提案的定向非法调用被拒绝，没有审批、项目副作用或命令启动 |
| 本轮固定模式     | 准备、运行中不漂移；未知模式明确拒绝，不默认执行                           |
| 计划到执行       | 同一会话的完整方案仍可理解；切模式不发请求，明确发送后才实施               |
| 重试、停止与编辑 | 重试固定原模式；编辑重发采用明确选择；取消和迟到事件不串轮                 |
| 保存与重开       | 模式、计划文本、当前图片组保持，不恢复批准或自动执行                       |
| 前课回归         | 多图、文本附件、源码、三种授权和第49课设置页及侧栏保持                     |
| 开发与目录包     | 两版分别完成观察与闭环，真实模型与合成结果区分记录                         |

手工验证采用隔离会话数据和自制项目：

1. 准备小目录和一个含明确待改文字的`note.txt`，记录目标文件内容/哈希；选工作区。计划模式发送“查看这个项目，给出把旧标题改为新标题的方案”，确认真实读取和最终方案，目标项目文件不变。聊天本身可正常保存。
2. 保持计划选择，把授权改为完全访问，再要求修改目标；结果仍只能研究和给方案。对隐藏写入与命令调用的强制拒绝用主进程定向检查，不依赖模型恰好主动调用违规工具。
3. 手动切执行，确认没有自动发送；再发送“按上面的方案实施”。确认沿原三模式授权、必要的重新读取与冲突检查完成真实改动，并能查看源码。
4. 在隔离检查中让计划失败，切执行后点击原请求重试，确认仍为计划；停止不产生跨轮结果。编辑原消息时确认显示原模式，明确改执行再发送按新模式处理，原图组保持。
5. 保存并退出整个程序重开，确认计划与执行消息模式、方案及图片恢复；不会恢复批准或自动执行。以新轮追问方案内容，再检查设置页返回聊天、文字/多图/文本草稿及窄窗菜单。
6. 开发版和最终目录包分别复核；真实模型、自制图片资源、系统手势、合成SSE与替身检查单独记录。原用户会话库、原包和此前未提交改动不作为可随意覆盖的验收素材。

## 9. 实施与验收记录（2026-10-09）

### 实际调用链与结构

输入框和消息编辑共用`ComposerMode`，工作方式是`execute/plan`，三种授权仍是`ExecutionInfo.mode`。切换只更新下一轮选择，不发送、自动实施或清空草稿附件。会话`agentMode`记录输入框选择，每条消息`mode`和对应`ToolRun.mode`一致；无工具成功、失败、取消也有模式。未知/缺失/旧`live`请求拒绝，shared、preload和主进程分别校验。

发送及编辑在目录/图片准备前捕获模式；失败重试从原请求来源取模式，当前输入框改执行不改变原计划重试。编辑先显示原消息模式，明确改选后产生新轮，原图组和文本附件保持。忙碌、保存、关闭及批准期间沿原互斥限制；取消和迟到事件按requestId隔离。

计划仅提供时间、列出、搜索和读取；工具循环及执行器在动作、批准、提案或命令启动前拒绝计划写入和两种可执行提案。附件指令及完全访问不能绕过，提示词要求用正常文字形成方案；共享协议校验和提案派生也拒绝计划行动记录。执行沿现有工具、授权、范围/revision、完整重新读取和冲突保护。

跨模式只传完整用户任务及最终方案文字，保留合法原图顺序和协议位置；不重放旧工具、推理或批准。执行首请求实际携带上轮方案，重新读取目标后实施。原同模式/同范围规则保持。只读源码查看补必需`mode: plan`，仍走原读取接口。

会话当前唯一版本8，设置仍版本1，目录绑定保持。旧库1–7或损坏库拒读及拒保存，原字节保持；没有迁移、清空或自动覆盖，用户原库与工作目录未作为测试素材。全部原未提交课程文档及附录保持，未提交或重置Git。
