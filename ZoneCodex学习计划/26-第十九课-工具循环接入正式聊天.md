## 1. 本课要做出的效果

同一个聊天输入框提供三种模式：

| 模式          | 请求路径                      | 页面表现                                                   |
| ------------- | ----------------------------- | ---------------------------------------------------------- |
| 普通聊天      | 原 startModelStream           | 保留多轮文本上下文与流式文字                               |
| 时间工具·模拟 | startAgentPractice，mode=mock | 本地模拟模型响应，真实执行时间工具，显示执行记录与最后结果 |
| 时间工具·真实 | startAgentPractice，mode=live | 模型自主选择时间工具，显示执行记录与最后回答               |

模拟模式固定查询香港，保持第十八课行为。工具模式在工具执行期间实时显示进度，最后一次性显示回答；本课不实现工具参数/最终回答的 SSE 流式解析。不要把模拟输出逐字播放冒充真实流。

在会话 A 发送时，提前记录 conversationId、requestId、userId、assistantId 和本次模式。随后所有事件都更新 A 的对应助手消息，不读取回调执行时“当前选中的会话”。界面运行中禁止切换/新建/清空，逻辑仍保留归属检查，防止迟到结果串到其他消息。

第十七课终端恢复到正式工作台中，作为用户手动操作入口。工具循环不调用终端，时间工具没有执行命令权限。本课没有项目目录选择，因此也不宣称终端已自动绑定聊天项目。

## 2. 先说清楚哪些内容保存，哪些不保存

本课不升级会话库版本 2，也不修改 ChatMessage。分三层存放：

| 数据                                                                  | 位置                                       | 生命周期                                             |
| --------------------------------------------------------------------- | ------------------------------------------ | ---------------------------------------------------- |
| 用户问题、助手最终文字及消息状态                                      | 原会话库 messages                          | 沿用自动保存与恢复                                   |
| 工具执行记录                                                          | 前端独立 toolActivity，按 assistantId 对应 | 当前页面内临时显示；切换/新建/清空会话时清除，不落盘 |
| 完整 Responses output、call_id、function_call_output、reasoning/phase | runToolLoop 内部 input                     | 本次任务内保留，任务结束后不延续到下一次提问         |

所以本课工具模式只处理当前问题，不接收旧聊天历史。比如“那换成 UTC 呢”缺少完整的本轮问题，不能保证理解上一轮工具上下文；请直接问“查询 UTC 当前时间”。第二十课再设计跨轮工具协议历史和持久化。

普通聊天继续使用 buildContext，只取已完成的问答文本；其中可能包含之前工具模式生成的最终文字，但它只是历史文字，不能据此继续旧 call_id 或声称恢复了工具任务。刷新后没有执行记录，并不代表旧工具从没运行；也不能自动重放工具来补记录。

## 4. 第一步：定义独立的进度事件

在 shared/agent.ts 末尾追加，保留现有 AgentMode、AgentResult、isAgentId 和 parseAgentResult：

```ts
export type AgentProgress = { requestId: string; message: string }

export function parseAgentProgress(value: unknown): AgentProgress | null {
  if (
    typeof value !== 'object' ||
    value === null ||
    !('requestId' in value) ||
    !isAgentId(value.requestId) ||
    !('message' in value) ||
    typeof value.message !== 'string' ||
    value.message.length > 500
  )
    return null
  return { requestId: value.requestId, message: value.message }
}
```

这里的 message 是应用生成的“第 1 次模型请求”“执行工具……”等执行说明，不是隐藏思维过程，也不是助手正文。

## 5. 第二步：让已有循环报告进度

打开 main/agent/tool-loop.ts，将 runToolLoop 的最后一个参数从 `trace: string[]` 扩展为：

```ts
  trace: string[],
  onProgress: (message: string) => void = () => undefined
```

在函数体开头、`const input` 之前加入：

```ts
function record(message: string): void {
  const line = message.slice(0, 500)
  trace.push(line)
  onProgress(line)
}
```

把函数原有的四处 `trace.push(...)` 改成 `record(...)`：每轮请求、最终回答、工具执行、工具结果。注意不要把新 record 函数里的 trace.push 也替换，否则会递归调用自己。

例如原来的：

```ts
trace.push(`第 ${round} 次模型请求`)
```

改为：

```ts
record(`第 ${round} 次模型请求`)
```

完整工具结果仍原样追加到 function_call_output；只截断用于界面显示的记录。本课只用有限的时间工具，不增加文件内容输出。

在 main/agent/agent-ipc.ts 的 runToolLoop 调用中增加第 5 个参数：

```ts
const answer = await runToolLoop(
  prompt.trim(),
  mode === 'mock' ? createMockResponse() : sendLiveResponse,
  controller.signal,
  trace,
  (message) => {
    if (controller.signal.aborted || sender.isDestroyed()) return
    sender.send('agent:progress', { requestId: id, message })
  }
)
```

沿用当前的 90 秒总超时、窗口销毁/刷新取消、Map 互斥和 finally 清理，不另注册第二份 agent:start。第十八课独立面板即使不监听进度，也仍可通过最终结果里的 trace 展示记录。

实时事件与 start 返回的最终结果是两个通道。成功、失败或停止后，前端以最终 result.trace 覆盖临时记录，补齐在订阅时序边缘可能漏掉的说明；请求结束后的迟到事件会被忽略。

## 7. 第四步：统一正式聊天的请求生命周期

替换 features/chat/useModelStream.ts：

```ts
import { useEffect, useRef, useState } from 'react'
import type { ChatMessage } from '../../../../shared/conversation'
import type { OperationControl } from '../conversation/useOperation'
import { buildContext } from './context'

export type ChatMode = 'chat' | 'tool-mock' | 'tool-live'
export type ToolActivity = Record<string, string[]>

type ActiveRequest = {
  conversationId: string
  requestId: string
  userId: string
  assistantId: string
  mode: ChatMode
  text: string
}
type UpdateMessages = (
  conversationId: string,
  update: (previous: ChatMessage[]) => ChatMessage[]
) => void
type StreamOptions = {
  conversationId: string | null
  messages: ChatMessage[]
  updateMessages: UpdateMessages
  operations: OperationControl
  mode: ChatMode
}
type ModelStream = {
  error: string | null
  toolActivity: ToolActivity
  send: (rawContent: string) => boolean
  stop: () => Promise<void>
  clearError: () => void
  clearActivity: () => void
}

export function useModelStream({
  conversationId,
  messages,
  updateMessages,
  operations,
  mode
}: StreamOptions): ModelStream {
  const { begin, finish } = operations
  const [error, setError] = useState<string | null>(null)
  const [toolActivity, setToolActivity] = useState<ToolActivity>({})
  const activeRequest = useRef<ActiveRequest | null>(null)
  const subscribed = useRef(false)

  useEffect(() => {
    const offDelta = window.api.onModelDelta((event) => {
      const active = activeRequest.current
      if (!active || active.mode !== 'chat' || active.requestId !== event.requestId) return
      active.text += event.delta
      updateMessages(active.conversationId, (previous) =>
        previous.map((message) =>
          message.id === active.assistantId && message.status === 'pending'
            ? { ...message, content: message.content + event.delta }
            : message
        )
      )
    })
    const offProgress = window.api.onAgentProgress((event) => {
      const active = activeRequest.current
      if (!active || active.mode === 'chat' || active.requestId !== event.requestId) return
      setToolActivity((previous) => ({
        ...previous,
        [active.assistantId]: [...(previous[active.assistantId] ?? []), event.message].slice(-30)
      }))
    })
    subscribed.current = true
    return () => {
      subscribed.current = false
      offDelta()
      offProgress()
      const active = activeRequest.current
      activeRequest.current = null
      if (!active) return
      if (active.mode === 'chat')
        void window.api.cancelModelStream(active.requestId).catch(() => undefined)
      else void window.api.cancelAgentPractice(active.requestId).catch(() => undefined)
    }
  }, [updateMessages])

  function finishTurn(active: ActiveRequest, status: ChatMessage['status'], answer?: string): void {
    updateMessages(active.conversationId, (previous) =>
      previous.map((message) => {
        if (message.id !== active.userId && message.id !== active.assistantId) return message
        return {
          ...message,
          status,
          content:
            message.id === active.assistantId && answer !== undefined ? answer : message.content
        }
      })
    )
  }

  async function run(
    active: ActiveRequest,
    content: string,
    history: ReturnType<typeof buildContext>
  ): Promise<void> {
    try {
      if (active.mode === 'chat') {
        const result = await window.api.startModelStream(active.requestId, history)
        if (activeRequest.current?.requestId !== active.requestId) return
        if (result.status === 'done' && active.text.trim()) finishTurn(active, 'complete')
        else if (result.status === 'cancelled') finishTurn(active, 'cancelled')
        else {
          finishTurn(active, 'failed')
          setError(result.status === 'error' ? result.error : '未收到有效的回复文字。')
        }
      } else {
        const result = await window.api.startAgentPractice(
          active.requestId,
          content,
          active.mode === 'tool-mock' ? 'mock' : 'live'
        )
        if (activeRequest.current?.requestId !== active.requestId) return
        setToolActivity((previous) => ({ ...previous, [active.assistantId]: result.trace }))
        if (result.status === 'done') finishTurn(active, 'complete', result.answer)
        else if (result.status === 'cancelled') finishTurn(active, 'cancelled')
        else {
          finishTurn(active, 'failed')
          setError(result.error)
        }
      }
    } catch {
      if (activeRequest.current?.requestId === active.requestId) {
        finishTurn(active, 'failed')
        setError('回复连接中断，请稍后重试。')
      }
    } finally {
      if (activeRequest.current?.requestId === active.requestId) {
        activeRequest.current = null
        finish('generating')
      }
    }
  }

  function send(rawContent: string): boolean {
    const content = rawContent.trim()
    if (!subscribed.current || !conversationId || !content || activeRequest.current) return false
    const limit = mode === 'chat' ? 4000 : 2000
    if (content.length > limit) {
      setError(`当前模式请输入不超过 ${limit} 个字符的消息。`)
      return false
    }
    if (!begin('generating')) return false
    const active: ActiveRequest = {
      conversationId,
      requestId: crypto.randomUUID(),
      userId: crypto.randomUUID(),
      assistantId: crypto.randomUUID(),
      mode,
      text: ''
    }
    activeRequest.current = active
    setError(null)
    if (mode !== 'chat') {
      setToolActivity((previous) => ({ ...previous, [active.assistantId]: ['等待工具任务开始…'] }))
    }
    const history = mode === 'chat' ? buildContext(messages, content) : []
    updateMessages(active.conversationId, (previous) => [
      ...previous,
      { id: active.userId, role: 'user', content, status: 'pending' },
      { id: active.assistantId, role: 'assistant', content: '', status: 'pending' }
    ])
    void run(active, content, history)
    return true
  }

  async function stop(): Promise<void> {
    const active = activeRequest.current
    if (!active) return
    try {
      if (active.mode === 'chat') await window.api.cancelModelStream(active.requestId)
      else await window.api.cancelAgentPractice(active.requestId)
    } catch {
      if (activeRequest.current?.requestId === active.requestId) {
        setError('停止请求失败，请等待回复结束或超时。')
      }
    }
  }

  return {
    error,
    toolActivity,
    send,
    stop,
    clearError: () => setError(null),
    clearActivity: () => setToolActivity({})
  }
}
```

注意四点：

1. mode 在发送时保存在 active 中，停止时看 active.mode，不能看后一次渲染的下拉框值。
2. 两种模式都先 begin('generating')，结束后才 finish，所以生成时不能切换会话、保存或清空；按钮禁用之外还有同步 ref 互斥。
3. 订阅回调按 requestId 筛选，更新消息时按 active.conversationId 和 assistantId 定位。切换被禁止不代表可以省略归属。
4. 取消请求发出后不立即把状态改为空闲，等 start 返回 cancelled 或其他终态。若任务先完成、取消请求晚到，显示完成是合理结果；AbortController 不保证撤销已经做完的工作。

普通流新增 active.text 检查，避免服务返回 done 但没有文字时写入空的 complete 消息，导致现有存储校验失败。工具模式的结果已经由 preload 的 parseAgentResult 校验，再统一结束本轮用户和助手消息。

```tsx
    <option value="chat">普通聊天（流式）</option>
    <option value="tool-mock">时间工具·模拟</option>
    <option value="tool-live">时间工具·真实</option>
  </select>
</label>
{
  conversation.chatMode !== 'chat' && (
    <p className="composer-footnote">
      {conversation.chatMode === 'tool-mock'
        ? '模拟模式不联网，固定查询香港时间。'
        : '真实模式会调用已配置的模型服务与时间工具。'}
      工具模式仅处理本轮问题，执行记录暂不保存。
    </p>
  )
}
```

ChatInput 的 send/stop/isSending/disabled 不改，继续走 conversation 控制器。同一个发送按钮按当前模式分流，不添加第二个“发送工具问题”的输入框。工具模式最多 2000 字，普通模式仍为 4000；超限时 send 返回 false，原输入草稿不清空。

## 11. 保存与退出在本课怎样工作

工具事件只改变 toolActivity，不改变 snapshot，所以执行记录不会让保存签名反复变化。问题与助手占位改变 snapshot，但 operation=generating，自动保存暂时等待。终态更新消息后 finish('generating') 回到 idle，再按原 10000ms 防抖保存。

成功时保存问题和最终回答；失败/停止时消息状态分别为 failed/cancelled，不计入后续普通聊天上下文。临时执行记录不进入版本 2 校验器，也不误写一个校验器不认识的 tool 字段。

已有关闭保护在 generating 时阻止正常关闭，用户应先停止或等待，再执行原来的保存/关闭流程。页面刷新或 renderer 崩溃仍由 main 的取消钩子兜底。刷新可能丢失尚未保存的问题和答案；本课没有新增崩溃恢复能力。

第二十课需要解决：完整工具协议历史的数据结构、跨轮关联、保存/迁移、运行中断恢复，以及如何区分可展示记录和必须回传的协议项。本课不提前把它们压成字符串存进 content，也不通过重启后重放工具来“恢复”。

## 14. 八道自测题

1. 为什么正式聊天只保留一个输入框，却需要在发送时区分普通流与工具任务？
2. conversationId、requestId、assistantId 分别用于哪一层定位？只靠“当前会话”有什么问题？
3. 为什么 active 中保存 mode？停止按钮为什么不能总调用同一个取消接口？
4. 为什么工具执行记录不拼到 message.content？它与最终回答、协议历史有什么区别？
5. begin('generating') 与 finish('generating') 怎样影响切换、清空、保存和关闭保护？
6. 发送取消请求后为什么不能立即解锁输入？迟到的进度/结果如何避免影响新消息？
7. 本课重启能恢复什么、不能恢复什么？为什么不能自动重放工具补回记录？
8. 本课哪些地方是真正融合，哪些能力仍留给第二十课？手动终端为什么没有自动变成 AI 命令工具？

---

第十九课先记为你已完成实现。下面按八道自测题讲解，重点是理解“一条问题怎样经过工具循环，最后回到原来的聊天消息”。

**1. 为什么只有一个输入框，却要区分普通流与工具任务？**

输入框只负责收集问题，发送后的处理方式不同：

- **普通聊天**：携带历史问答，通过 `startModelStream` 接收文字增量，边收到边显示。
- **工具模式**：通过 `startAgentPractice` 发起工具循环，可能经历“模型请求调用工具 → 应用执行 → 结果交回模型 → 最终回答”。

所以共用输入框和消息区，但发送时要根据 `mode` 选择不同的处理路径。

**2. conversationId、requestId、assistantId 分别有什么用？**

| ID               | 用途                   | 可以理解成         |
| ---------------- | ---------------------- | ------------------ |
| `conversationId` | 确定回复属于哪个会话   | 哪一本笔记         |
| `requestId`      | 判断事件属于哪一次请求 | 哪一次任务         |
| `assistantId`    | 确定更新哪条助手消息   | 笔记中的哪一条回答 |

发送时就把这些 ID 存进 `active`。

异步结果可能晚到，回调执行时“当前选中的会话”不一定还是发送时的会话。根据保存的 ID 更新，才能保证结果回到原位置。

另外，`userId` 用来找到本轮用户消息，使问题和回答一起更新为完成、失败或已停止。

**3. 为什么 active 中保存 mode？停止按钮为什么不能固定调用一个接口？**

`active.mode` 记录的是**这次正在运行的请求采用什么模式**。

停止时必须取消对应任务：

```ts
if (active.mode === 'chat') {
  await window.api.cancelModelStream(active.requestId)
} else {
  await window.api.cancelAgentPractice(active.requestId)
}
```

普通流和工具任务由不同的后台逻辑管理。工具任务运行时调用普通流的取消接口，不能停止工具任务。

即使界面已经禁止切换模式，也应该根据请求自身保存的信息处理它。

**4. 为什么工具记录不拼到 message.content？三种数据有什么区别？**

| 数据         | 示例                                               | 用途                           |
| ------------ | -------------------------------------------------- | ------------------------------ |
| 工具执行记录 | “第 1 次模型请求”“执行工具……”                      | 给用户观察进度                 |
| 助手最终回答 | “香港当前时间是……”                                 | 正式聊天内容                   |
| 工具协议历史 | `function_call`、`call_id`、`function_call_output` | 让模型理解调用和结果的对应关系 |

本课中：

- 执行记录放在临时的 `toolActivity`。
- 最终回答放在 `message.content`，沿用会话保存。
- 完整协议历史放在 `runToolLoop` 的 `input` 中，只用于本次任务。

如果把记录拼进正文，它们就会被保存，还可能作为普通聊天上下文发送出去。**展示用的文字记录也不能代替完整工具协议。**

**5. begin('generating') 和 finish('generating') 如何影响其他操作？**

它们管理整个聊天请求的忙碌状态。

```text
发送
  → begin('generating')
  → 普通流或工具循环运行
  → 更新本轮消息的最终状态
  → finish('generating')
  → 恢复 idle
```

生成期间：

- 禁止重复发送、切换模式、新建或切换会话、清空及保存。
- 自动保存等待任务结束。
- 关闭保护提示当前仍然忙碌。

这里有两层保护：`disabled` 禁用界面按钮；控制器的同步检查阻止函数重复进入。仅靠按钮禁用不够。

**6. 为什么发送取消请求后不能立即解锁？怎样处理迟到事件？**

**请求停止，不等于已经停止。**

取消信号发出后，后台可能还在结束网络请求和清理资源。如果立即解锁，新任务可能在旧任务尚未退出时启动。

所以流程是：

```text
点击停止 → 发出取消请求 → 等待 start 返回终态 → 恢复空闲
```

进度事件先检查请求身份：

```ts
if (!active || active.requestId !== event.requestId) return
```

旧请求的事件与新请求 ID 不同，就会被忽略。任务结束后 `activeRequest.current` 清空，后续事件也不再更新消息。

如果任务已经完成，取消才到达，显示“完成”也是合理的；取消不能撤销已经完成的工作。

**7. 重启能恢复什么？为什么不能重放工具补记录？**

**已经保存成功的**用户问题、助手最终文字和消息状态可以恢复。

本课不会恢复：

- 临时工具执行记录。
- 上次工具循环的完整协议历史。
- 上次尚未结束的任务。
- 模式选择；重启默认普通聊天。

不能重新执行工具冒充恢复记录。例如昨天查询香港时间，今天重放得到的是今天的时间，并不是昨天的执行结果。以后工具涉及写文件或执行命令，重放还可能重复产生实际影响。

恢复历史应该读取保存的数据，不能靠重新执行来伪造过去。

**8. 本课真正融合了哪些能力？哪些留给下一课？终端为什么还不是 AI 工具？**

本课融合的是：

- 同一个输入框和消息区。
- 工具进度与助手消息的对应关系。
- 普通流与工具任务的发送、停止、错误处理。
- 会话归属、操作互斥，以及最终文字的保存。

第二十课再处理完整工具协议历史的保存与恢复、跨轮关联及中断恢复。因此当前工具模式每次只接收本轮问题，“那换成 UTC 呢”不能保证理解，应该明确写“查询 UTC 当前时间”。

手动终端目前由你输入命令。AI 当前可调用的只有时间工具，代码没有把终端执行能力注册给模型。**界面上出现终端，不代表模型获得了执行命令的权限。**
