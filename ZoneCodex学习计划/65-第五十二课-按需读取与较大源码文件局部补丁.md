## 1. 本课目标与前置条件

完成一个可观察的闭环：**模型搜索定位较大的源码文件，按需读取相关片段；计划阶段只研究和输出方案，用户明确切执行并发送实施请求后，执行本轮读取必要上下文，提交小范围补丁，主进程验证版本与匹配位置并沿原授权提交，最后重读修改位置并核对磁盘字节。**数百行文件无需全部发送给模型。

前置第51课原实现要求从第1行完整读取、取得小文件`fullText`，源文与候选最多80行、2000字符。第52课替换这个模型整文件读取门槛：**不要求模型读完整文件，也不要求累计全文覆盖。**主进程仍可有界读取完整原字节，用于hash、精确唯一匹配、候选生成、备份和提交校验。这两种读取职责要分清。

按需读取与局部补丁的方向依据[Codex prompting guide](https://developers.openai.com/cookbook/examples/gpt-5/codex_prompting_guide)中“read enough context before changing a file”、搜索/读取工具及单文件`apply_patch`建议，并参照[官方apply_patch说明](https://developers.openai.com/api/docs/guides/tools-apply-patch)。这些资料没有要求累计同hash整文件覆盖，也没有给出本课文件容量规则；前者是第51课后续建议中需要修正的ZoneCodex设计，后者及下文片段凭据是本项目自己的工程保护。指南面向GPT-5系列，不能据此宣称所有Codex版本或默认`gpt-6.1-sol`具有固定相同限额。

本课范围为一个已有UTF-8文件的单份Update补丁，可含多个不重叠修改块。继续使用`apply_workspace_patch(path, expectedSha256, patch)`、裸`@@`、精确唯一旧文与可选末块EOF；不实现Add/Delete/Move、多文件事务、模糊匹配、二进制、编码或显式BOM/换行/尾换行转换。可编辑后缀及路径规则沿现有范围，空原文无锚点和隐式尾格式变化继续拒绝。

保留默认`gpt-6.1-sol`、第45–51课交互、执行/计划与三种授权分离、计划提问卡、原模式手动重试和编辑发送、五次模型自动重试、设置页及侧栏、多图、文本附件、目录绑定、源码查看、取消及迟到隔离。计划＋完全访问仍由主进程禁止写入、命令和可执行提案；切执行本身不发送请求。执行能理解此前方案，但计划/历史读取不成为执行凭据。

遵循[未发布阶段约定](05-后续课程编写约定.md#未发布阶段的结构更新约定2026-10-08)：允许必要的唯一当前契约更新，不恢复旧全文编辑工具、旧字段、迁移或兼容链；不自动清空用户记录、覆盖不支持的会话库、搬动工作目录或覆盖已有未提交改动。当前会话版本9、设置版本1，是否需要调整契约由实际实施决定，不为本课预先强制升版本。MCP、SSH、并发、终端入口和目录包标题超时排查不扩入主线。

## 2. 用 Vue 经验理解本课

| Vue中的经验             | React / Electron中的对应做法      | 本课用途                           |
| ----------------------- | --------------------------------- | ---------------------------------- |
| 列表按需分页获取        | 搜索命中后按行读取相关窗口        | 减少无关正文和工具轮次             |
| 服务端维护请求上下文    | 主进程保存本轮片段证据            | 界面历史不能授予本轮执行能力       |

| 表单只提交改动字段      | 模型发送少量补丁旧文/上下文和新行 | 主进程负责整体生成候选             |
| 不同接口有不同校验策略  | 补丁专用容量与附件/新建容量分开   | 复用准备和提交代码而不扩大其他功能 |

用户是否批准、模型看到了什么、磁盘是否还是同一文件，是三个独立问题；片段证据不能替代权限或提交前冲突检查。

## 4. 按依赖顺序安排练习

### 步骤一：核对源码和设计边界

先读取本课、编写约定、结构地图、学习进度及第51课，再核对Git未提交改动和全部调用方。将“模型片段窗口”“主进程原字节读取”“内部候选编码”“工具/历史输出”分别标出，特别检查`change-commit.ts`的再次准备和恢复核验。

**预期效果：**说明一个超过32 KiB的文件怎样从读取到真实提交全部通过，而附件和新建不被扩大。**常见错误：**只改80/2000两个常量，最终读回或备份仍被32 KiB拒绝；只改后端，模型还遵循旧全文提示。

### 步骤二：登记模型实际看到的片段

执行本请求按规范绝对路径保存当前原字节hash、`totalLines`、`format`（包括`trailingNewlines`）及实际返回的完整行号/文字。读取结果来自本轮真实`read_workspace_file`，经过最终序列化和裁剪后，只有确实返回给模型且行自身未截断的行才登记。请求范围不是证据；搜索摘要、附件摘录、用户粘贴、计划轮和历史协议均不能登记为工作区补丁凭据。

同路径同hash可合并相关片段；观察到不同hash时替换该路径旧证据，不能把不同版本凑在一起。结果整体`truncated`不必使仍完整返回的行全部失效，但未返回行和逐行截断行必须无效。若工具循环还会再次裁剪或替换输出，凭据必须以最终模型可见结果为准，不能在裁剪前乐观登记。证据自身有界，只存最多128 KiB文件对应的可用行，不存无限请求历史。

**预期效果：**读两个小窗口即可记录两处目标附近的行，其他几百行不必覆盖。**常见错误：**把`fullText !== null`作为唯一条件；只记录请求的起止行；凭据跟随聊天库恢复；获取新hash却保留旧范围。

### 步骤三：精确定位后核对所需旧文

先对当前真实规范LF原文解析整份补丁、精确唯一定位各块并拒绝重叠，复用同一份解析/定位结果检查证据。每块所有空格上下文行与`-`删除行，应落在该路径同hash的已读完整行中，行号和文字均一致；`+`新增行不需要提前读取。纯插入仍须已读旧锚点，EOF结合真实末端、格式与总行数校验，不引入整文件覆盖门槛。工具`totalLines`包含尾换行产生的空行，而匹配器先移除连续尾LF；应由当前规范正文的实际定位结果映射工具行号，不能直接把`totalLines`当作最后可匹配正文行。

一次补丁中的任一块缺少必要旧文证据、缺失/重复上下文、重叠或语法非法，整份拒绝，不先落盘成功块。错误提示应告诉模型读取目标附近缺少的范围或增加唯一上下文，不要求它机械地从第1行读到末行。生成候选后继续交原准备链，不能凭片段直接拼成完整文件。

**预期效果：**同一较大文件中两处局部修改可一次应用，未读取的正文保留。**常见错误：**只要读过任意一行就允许改全文件；以补丁自己提供的旧文充当读取；不同解析器对EOF或空行含义不一致。

### 步骤四：贯通补丁专用容量

由主进程固定选择局部补丁的容量策略，随快照/准备内容贯穿再次读取、prepare、commit、暂存与备份核验、最终读回和恢复检查；模型和renderer不能通过新参数选择更宽容量或关闭检查。默认附件全文建议仍走原小文件策略，`create_workspace_file`仍为80行/2000字符，不全局替换公共常量。

原始文件与最终编码候选分别最多131072字节。规范LF字符串可以使用131072字符的内部保护，但真正编码后须再次校验，计入原BOM、CRLF和原尾换行。保留原UTF-8解码、非法控制字符/Unicode检查、可编辑后缀、父目录和文件身份约束；混合换行/孤立CR继续拒绝修改。精确上限文件应可作等长修改，超过1字节应在写入前拒绝。

**预期效果：**64–128 KiB文件能完成真实备份、暂存、替换、读回，失败保留原字节和实际恢复状态。**常见错误：**只看JavaScript字符数；把完整候选返回模型；提案界面/共享解析仍静默裁剪较大正文；恢复读回使用旧默认限制。

### 步骤五：沿用原授权、冲突和重试

计划只读护栏保持在参数解析、审批、行动之前。明确执行发送后，本轮重新读取目标附近并取得自己的hash/片段；计划方案文字保留为任务上下文。提交前核对当前hash、原身份与原字节，等待批准后再次核对权限、取消、父目录和目标。`no_change`、`conflict`、`cancelled`、`error`、`uncertain`及applied的真实语义保持。

现有审批每份before/after允许128 Ki字符；风险评估器整份JSON却有128 KiB边界，较大文件两份正文或JSON转义可能超限，按原流程回落人工批准。应验证回落、拒绝和取消，不扩大评估预算、不宣称大文件一定可自动评估批准。权限范围内直接写入、范围外按原策略批准，片段证据不改变授权范围。

补丁成功后旧证据不能自动获得新hash；同请求再改该文件应重读相关片段。临时模型失败仍仅重发冻结的当前模型请求，不重放已经成功的补丁；整轮手动重试、副作用保护、停止及迟到结果保持。

**预期效果：**外部编辑或取消不会被“已读过片段”绕过，临时502恢复也不重复修改。**常见错误：**把回答计划问题当批准；给成功后的证据直接换hash；大正文评估超限时静默扩大权限或自动通过。
