## 3. 保留了什么

- AppAPI 方法名、IPC 通道、请求参数和返回结果不变。
- 模型请求、超时、停止与窗口销毁时取消的行为不变。
- 聊天 JSON 的版本、位置、迁移备份及保存队列不变，不搬动用户聊天文件。
- renderer 的 App、features、components 目录不变，第十六课面板仍在 features/terminal 新建。
- useOperation 的互斥状态、useConversation 的数据归属不变；自动保存仍为用户当前的 10000ms。
- 关闭保护的页面 Hook 仍位于 features/conversation，挂载位置仍在 ChatWorkspace。这里只把主进程对应文件分组，不提前重构退出协调。
- 非流式 askModel 与 ping 接口仍保留；独立学习组件也保留。

preload/index.ts 和 shared/api.ts 中失效的模拟流注释接口已清除，main/model/model.ts 中旧的单字符串校验注释已清除。模拟流整份历史实现归档到 main/learning，旧课程正文可用于复习；归档代码不是可以直接打开开关运行的正式模块。

## 4. 现在如何找代码

```text
App / features/chat
  → window.api（shared/api.ts 声明）
  → preload/index.ts
  → main/index.ts 注册非流式和存储接口
    或 main/model/model-stream.ts 注册流式接口
  → 对应模型请求 / 存储实现
```

例如排查“停止回复”：先看 features/chat/useModelStream.ts，再看 preload 的 cancelModelStream，最后看 main/model/model-stream.ts 的 model-stream:cancel。

排查“重启后记录不对”：先看 features/conversation/useConversationStorage.ts，再看 main/storage/conversation-store.ts 和 shared/conversation-library.ts。

本次没有统一抽取 IPC 文件夹。当前注册代码还很少，流式模块仍同时负责接口与执行；引入 Agent 循环时再学习分离请求入口、模型访问、任务管理和工具执行。

## 5. 对已有课程和第十六课的影响

第一至十五课保留当时的完整代码与路径，作为学习历史；复习时先查本页迁移表，不按旧路径另建第二份模块。第17份文档记录此前前端拆分，本页记录后续主进程分组，两次迁移可以对照使用。

第十六课仍然是显示层入门：xterm 输入事件、模拟输出、尺寸和资源释放。它不修改本次迁移的主进程文件，也不连接真实 shell。

下一课实现真实终端时再新建 main/terminal 和 shared/terminal.ts；不是把 PTY 放进 renderer，也不是把执行逻辑塞进 model-stream.ts。之后进入最小 AI 工具循环、项目文件工具、差异审查和命令授权，再扩展 MCP/SSH 等能力。

终端面板是用户手动操作入口；AI 命令工具需要明确的任务 ID、输出、退出码、超时及取消。两者以后可以复用部分进程能力，但接口和生命周期需要分别设计。xterm 不负责执行模型提出的工具调用。
