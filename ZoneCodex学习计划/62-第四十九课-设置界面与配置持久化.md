## 1. 本课目标与前置条件

完成一个可观察的闭环：**点击头像打开菜单，再点“设置”，保留聊天侧栏并在同一窗口右侧进入常规设置页；修改无项目任务文件夹、默认授权模式和集成终端 Shell，退出重开后设置仍在，任务根目录、默认授权和Shell分别用于新会话、新窗口和新PTY。**

设置不是只做几个表单。主进程统一读取、校验和保存配置，执行上下文、权限初始化和终端启动从同一来源取值；界面显示保存后的真实状态。

保留默认 `gpt-6.1-sol`、三种授权模式、第45/46/47/48课已验收交互、多图、文本附件及全部现有未提交改动。按[未发布阶段约定](05-后续课程编写约定.md#未发布阶段的结构更新约定2026-10-08)直接统一当前配置、会话格式和接口，不保留版本1–6迁移、旧单图 `image` 或废弃接口的兼容链。当前一张图、无图和多图仍是产品能力，统一使用当前图片组结构。

本课不接入模型密钥管理、外部编辑器、主题、通知、快捷键定制、计划模式或第50课。模型连接继续使用现有主进程环境配置，不建立第二套模型配置，也不读取或展示密钥。界面不显示内部存储版本、协议或执行校验细节。

### Codex 对齐依据与边界

本课参考用户提供的“常规”设置截图：权限区、无项目任务文件夹、默认文件打开位置和集成终端 Shell。优先接入已确认的目录、权限和 Shell 范围；默认文件打开位置留到外部编辑器课程，现有应用内源码查看保持。

## 2. 用 Vue 经验理解本课

| Vue 中的经验                     | React / Electron 中的对应做法                    | 本课中的应用                                     |
| -------------------------------- | ------------------------------------------------ | ------------------------------------------------ |
| Pinia 管共享偏好                 | 主进程服务管理有效配置，Hook 管界面加载与编辑    | 不在多个组件各保存一份默认目录或权限             |
| 表单值与服务端结果分开           | 临时编辑值与保存成功的设置快照分开               | 写盘失败不能显示已保存，也不能先让执行器使用新值 |
| 组件挂载读取配置                 | 应用启动先加载设置，再初始化消费者               | 首个请求不能抢在设置恢复前使用错误默认值         |
| 动态 `computed` 与一次性参数不同 | 默认设置可变，任务与终端捕获本次有效参数         | 改 Shell 不重启旧终端，改偏好不改变运行任务      |
| `v-show`保留实例，`v-if`会卸载   | 保持组件挂载，以`hidden/inert`切换可见和可交互页 | 设置导航保留聊天草稿与资源，隐藏页不响应交互     |

renderer 负责交互；目录选择、配置持久化、Shell 路径解析和执行上下文仍由主进程负责。设置不是新的执行批准或目录授权凭证。

## 4. 按依赖顺序实施

### 步骤一：定义一套设置及生效规则

只包含本课需要的字段：无项目任务根目录、默认权限模式、终端 Shell，以及设置文件自身的格式标识。默认目录沿用当前位置，默认权限为“请求批准”，默认 Shell 为 Windows PowerShell。路径由主进程确定，权限复用现有枚举；Shell 采用有限选项，先支持系统自带 PowerShell 与命令提示符，不接受任意命令字符串。

设置文件与会话格式分别管理，只有一套当前设置格式，不建立旧格式迁移。缺少设置文件时使用默认值；已存在但损坏、格式不支持或读取失败时给出准确错误，不静默覆盖原文件。保存前做运行时解析，未知字段、非法模式或不可用 Shell 不进入有效配置。

明确三条生效规则：根目录用于后续新建的无项目会话；默认权限用于新窗口初始化；Shell 用于下一次创建终端。现有会话目录、当前窗口手动选择的模式和已启动 PTY 不被设置修改替换。首次加载完成前阻止依赖设置的创建或执行，避免先用默认值、随后突然切换。

当前契约是 `AppSettings = { version: 1, taskRoot, defaultPermissionMode, terminalShell }`。`SettingsChange`只允许一个默认模式或一个Shell字段，根目录只能通过主进程选择器修改。这里的设置版本1与会话版本7分别表示两个文件的格式，不是应用发布版本。

**练习与预期：**用默认配置和三种合法模式说明消费者何时取值；不支持的字段和 Shell 有确定失败结果。

**常见错误：**把默认模式当作当前执行模式；用 `localStorage` 成为配置主来源；把每项内部常量都开放成设置。

### 步骤二：主进程持久化与可信 IPC

设置独立保存到 `userData/settings.json`。复用现有存储风格，串行保存、临时文件写入再替换；只有写盘成功后发布有效配置并向界面返回成功。保存失败保留此前配置和文件，不让消费者先使用未落盘的新值。

设置服务在窗口和请求消费者初始化前完成读取尝试，由主进程提供读取、修改和目录选择接口；坏配置仍允许创建窗口显示原错误，依赖设置的操作保持不可用。IPC 复用主页面来源检查，preload 对参数和结果严格解析；renderer 不直接使用文件系统，不传入可执行命令、执行授权或自行计算的可写根范围。

目录更换使用系统目录选择器，由主进程核对真实绝对目录；取消选择不改配置。目录不可访问、创建会话子目录失败或实际路径变化时明确返回错误，不悄悄退回另一工作目录。保存设置与发送准备、执行、审批及其他现有互斥保持一致，忙碌时允许查看，修改控件和主进程均按同一规则拒绝。

实际调用为 `getSettings / updateSettings / selectTaskRoot` → preload严格解析 → `settings:get / settings:update / settings:select-task-root` → 服务与存储。`index.ts`先等待`initializeAppSettings`，再注册模块、创建窗口。保存成功才更新服务快照；坏配置保留原字节并显示错误，依赖设置的会话创建、执行与终端启动不抢跑。

`app-runtime.ts`把执行、审批、选择、准备、保存及关闭确认纳入设置忙碌判断。`conversation-ipc.ts`以`try/finally`维护保存计数，设置正在写盘时返回明确保存失败；关闭确认只阻止设置修改，不阻止“保存后退出”自身的保存。

**练习与预期：**保存后再次读取得到同一配置；模拟写盘失败时界面和消费者仍使用原值；取消选目录不造成变化。

**常见错误：**界面先显示成功再异步写盘；只有前端禁用按钮；坏文件被自动覆盖成默认值。

### 步骤三：无项目会话目录接入统一配置

按所选根目录继续为各无项目会话生成独立目录，例如 `<root>/<conversationId>/workspace`，不让不同会话直接共享根目录。为当前会话格式增加必要的目录绑定，由主进程确定并保存；renderer 中保存的展示值不能自行变成目录授权。

新会话采用创建时的配置，已经绑定目录的当前格式会话在刷新、切回和退出重开后继续使用该目录。更换全局根目录作用于以后新建的会话，不自动搬移原目录。显式选择的项目工作区仍优先；清除工作区后回到该会话已绑定的默认目录。

新建会话（包括首次发送时自动创建）先从主进程取得并确认目录绑定，将返回结果同步到当前会话快照并通过保存链落盘，再允许执行。不能等待自动保存或首次执行时才用最新设置决定目录；现有 `saveConversation` 只返回保存结果，不会带回主进程补入的字段，因此绑定请求与结果同步必须有完整接线，避免后续前端保存丢掉绑定。

`useConversation.createId`持有`selecting`，依次执行`bindConversationDirectory(id)`、构造含`defaultDirectory`的版本7快照、`storage.saveSnapshot(next)`，全部成功才返回ID。首次发送随后使用显式目标会话提交；绑定或保存失败不发送，原输入文字保留。`snapshotRef`在布局Effect同步，避免读取旧渲染快照。

主进程返回目录先记为pending，成功保存后才记为saved；执行只接受saved绑定。恢复从当前本地库重建绑定，renderer自行伪造路径不能成为授权。显式工作区存在时验证实际项目目录，无项目才验证默认目录；默认目录被外部删除时不偷偷重建或改位置。

运行目录继续经主进程真实路径和状态检查；原有 `scopeId`、权限 revision、运行前复核和副作用后重试保护保留。正在准备或执行时不得通过设置改变本轮目录。设置中的任务根目录、会话 JSON 存放位置和 `conversation-images` 三者分开，图片组恢复、追问和清理不因更换任务根目录而丢失。

**练习与预期：**根目录A创建会话1，再设置根目录B创建会话2；两者分别在独立目录工作，重开后仍保持。选择项目时实际使用项目目录。

**常见错误：**每次运行都用最新全局根目录重算旧会话路径；把设置目录当作整个目录树的执行授权；搬聊天库来实现工作目录选择。

### 步骤四：默认授权与终端 Shell 接入

持久化默认权限只初始化新窗口的内存权限状态。输入框原三模式菜单继续改变当前窗口模式并更新 revision，换会话仍沿用当前窗口状态；设置页修改默认值不覆盖当前模式。一次批准、待审批记录、preparedId、grant 或旧任务授权均不写入设置文件。

权限设置复用现有三模式名称；选择“完全访问权限”应保留现有清楚的权限说明，不新增与当前模式含义冲突的两个独立开关。默认偏好和本次有效模式能分别确认，保存错误不能造成实际权限与界面不一致。

手动终端创建时由主进程读取 Shell 枚举并解析系统可执行路径及独立参数数组。先支持 Windows PowerShell 与命令提示符；不可用选项明确提示。保留现有终端初始目录策略及生命周期，已启动终端保持原进程，重新创建后使用新 Shell。此偏好只影响手动集成终端，不替换 AI 命令的单次计划、官方沙箱或审批执行链。

`initializeExecutionPermissionState`在窗口挂载时捕获默认模式，后续`getExecutionPermissionState`读取该窗口值；刷新页面也不重新套用全局默认。Shell分别使用系统`powershell.exe`与`['-NoLogo', '-NoProfile']`、`cmd.exe`与`['/d']`，PTY仍从用户home启动。现有`TerminalPanel`组件与API保持，本课没有把它额外挂到当前聊天页；桌面验收经现有API启动真实PTY，不宣称新增了终端界面入口。

**练习与预期：**保存默认模式后重开窗口才看到它作为初始模式；已有终端不重启，新终端确实运行所选 Shell。

**常见错误：**保存全局默认值就提升当前任务权限；把上次批准永久化；通过 `exec` 拼接 Shell 命令；把终端选择器误接到 AI 沙箱执行器。

### 步骤五：简洁设置界面与现有聊天共存

侧栏底部保留头像按钮，点击先打开 popover 菜单，再点“设置”，只把同一窗口右内容区换成设置页；Windows `Ctrl+,` 直接进入同一页面。左侧聊天侧栏与标题栏展开/收起按钮继续可用，侧栏收起时设置使用剩余内容区，窄窗口复用原抽屉与遮罩。只做本课需要的“常规”页：默认三模式、无项目任务文件夹与更改按钮、终端 Shell 选择器。控件修改后通过统一接口保存，读取或保存失败使用简短就地提示，不显示假成功，不增加账号、诊断面板或未实现菜单。

设置页支持返回聊天、Escape 和正常 Tab 顺序，返回后焦点回到头像入口或其他有效位置。与现有图片预览、文件面板及审批浮窗协调，不抢占已有弹窗的快捷键和焦点。切换页面不能卸载聊天控制器或清理未发文字、多图草稿、文本附件及源码查看状态；正在运行时可查看，按主进程的同一互斥规则禁止修改。

加载和保存中的控件有明确状态，重复修改不让旧回执覆盖新值；关闭后迟到结果不重新弹出设置或更改另一会话。窄窗口布局保持可用，不把内部配置、存储版本和授权记录作为产品操作步骤。

`App.tsx`维护右侧聊天与设置的页面导航，二者保持挂载，隐藏的右内容区域使用`hidden/inert`停止交互；原聊天控制器、草稿和`useFileView`继续存活。侧栏沿用原展开状态和布局，标题栏开关继续工作；点击会话或新建会话返回聊天。`SettingsPage`按是否为当前页读取设置，`useSettings`用代次、读写标记与确认快照处理读取/保存，离开再返回时等未结束写入完成后回读主进程。头像菜单使用原生popover承担入口选择，侧栏和设置控件采用正常Tab顺序；`Ctrl+,`避让已有dialog和浮层，返回或Escape离开设置并恢复有效入口焦点。

`useSettings`开始保存时同步通知`onSavingChange(true)`，只在保存实际结束的`finally`通知false，不因设置页隐藏提前清除。`App.tsx`用同步ref在懒调用新建/切换/恢复前拒绝，归档、重命名和置顶也先查该ref；因此设置保存期间可见侧栏不会先释放原图片或文本附件。控件禁用负责提示，调用前检查负责互斥，不新增后端字段。

设置修改与聊天存储就绪分开：`useConversation`的`canChangeSettings`只依据当前操作是否idle及关闭确认；`canNavigate`还必须要求`storage.ready`。`App.tsx`把独立条件传给设置页，旧库或损坏会话库被拒绝时仍能保存有效设置，但不会放开聊天创建、切换或发送。设置自身加载、保存、配置错误和主进程忙碌检查继续生效。

`ProfileMenu`点“设置”时先同步收起popover，再调用页面导航并保留头像返焦目标；头像菜单自身支持箭头、Escape和外部关闭。设置页只隐藏原右侧聊天和源码交互，左侧栏保持可用；若审批或关闭确认的真实dialog出现，先回聊天显示所属弹窗，下一帧只在焦点尚未进入dialog时聚焦可用控件，避免隐藏区域阻止原焦点处理。`useFileView`在设置页停用聊天Escape处理，避免一个按键同时关闭源码和设置。

聊天隐藏期间暂停滚动测量，返回后沿用阅读位置；已有审查面板只在可见时处理Escape。这里保留组件实例和资源归属，不重新套用默认权限或重新创建会话。

**练习与预期：**鼠标和快捷键均能进入设置；改值后关闭再打开能读回，聊天草稿及图片保持；键盘关闭与窄窗口正常。

**常见错误：**只保存组件 state；切设置导致聊天重新挂载；每次返回聊天重新套用默认权限；Escape 同时关闭设置和其他面板；设置修改直接复用要求会话库ready的聊天导航门控。

### 步骤六：统一当前会话和图片契约，完成必要验收

与目录绑定一起确定新的唯一会话存储格式；删除版本1–6迁移入口和旧 `image` 分支，消息、当前轮请求、保存和恢复统一使用 `images` 图片组；历史请求继续通过合法的 `imageHistory` 关联位置。更新全部调用方、preload 和严格解析，保留无图、单张和多张输入；删除真正废弃的兼容入口，不删除仍有职责的当前工具历史或协议检查。

不开发旧库或旧目录迁移链。旧格式按不支持返回清楚的结果，不自动覆盖或删除原库，不把重建空库称为成功恢复。使用独立测试 `userData` 与自制目录验证新格式保存恢复；现有文件和未提交改动保留，不用真实用户历史做故障注入。

当前`ConversationLibrary.version`唯一为7，各会话必需`defaultDirectory`。`conversation.ts`改用`parseMessages`，消息和当前轮请求只接受`images`，历史图保留当前`imageHistory`位置关联；旧消息/请求的单图`image`即使显式值为`undefined`也拒绝。删除版本1–6解析迁移、旧工具历史迁移、旧临时图标记、无调用的单图绑定包装及不可达旧图提示。逐资产导入/预览结果中的合法`result.image`仍保留：它表示一张资源，不是旧消息格式。

实施时运行必要的 Node/Web 类型、完整 lint、定向格式、构建和目录打包检查。开发版和打包版分别观察真实设置写盘、目录选择与创建、权限初始化和 PTY 启动；替身测试只证明对应逻辑，不替代真实生效或 Windows 系统手势。多图、文本附件、原图组重试/编辑、源码查看和现有三模式做与本课改动相关的回归。

本课设置闭环无需模型请求。若实现后的回归需要真实模型，使用自制文本/图片和隔离目录，不上传此前用户截图，不因课程创建就调用模型。分别记录文档检查、组件/离线检查、桌面观察、模型请求及用户反馈。

**练习与预期：**新格式在开发/包中退出重开后保持设置、会话目录和图片组；旧格式被明确拒绝且原文件未删除。

**常见错误：**口头允许破坏性更新，源码仍留下双格式兼容；删除旧单图字段时连单张图片功能一起删除；只通过构建就宣称目录和 Shell 已生效。
