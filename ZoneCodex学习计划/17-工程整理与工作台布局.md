## 1. 为什么在这里整理

第十一课之后，App 同时承担加载、保存、流事件、目录选择、输入、状态提示和页面布局。用户提出先整理，再做类似 Codex 的工作台布局，之后继续课程。本次按这个方向直接调整工程，不作为要求学习者重新手写一遍的第十二课。

目标是让每个文件的职责可以用一句话说明。保留 React + TypeScript + Electron 和原有 JSON 数据格式，没有新增运行依赖或状态库。

## 2. 新的页面结构

- 左侧：品牌、工作目录、当前对话、可展开的使用说明；侧栏可以收起。
- 顶部：当前对话、保存状态、立即保存/重试保存、清空入口。
- 中间：空状态引导或独立滚动的聊天记录。
- 底部：多行输入框、目录提示、发送/停止按钮；消息很长时输入区仍保留。
- 窄窗口：侧栏以遮罩方式展开，不挤压消息和输入区。

这里采用类似 Codex 的空间划分，并使用 ZoneCodex 自己的浅色样式。只有一段真实对话，不制作没有功能的历史任务、模型选择器或设置按钮。

启动窗口调整为 1280×840，最小为 680×560，保留系统窗口标题栏。快捷引导只填写草稿，不自动发送。Enter 发送、Shift+Enter 换行；中文输入法确认候选词不会误发送。

## 5. 三条需要读懂的调用链

### 发消息

ChatInput → ChatWorkspace → useConversation → useModelStream → window.api → preload → main/model-stream。

返回的增量经订阅进入 useModelStream，再通过 updateMessages 更新唯一 snapshot，MessageList 随状态重新渲染。上下文仍只取最近成功问答。

### 自动保存

snapshot 变化 → useConversationStorage 比较基线 → 空闲 800 毫秒 → saveConversation → 原主进程存储模块 → 成功后更新本次快照的基线。

保存失败暂停自动重试。首次文件缺失显示“尚未保存”，不因为基线已建立就假称文件存在。

### 操作互斥

useOperation 中 state 用于禁用控件，ref 用于立即拒绝第二个操作：

```text
loading → idle
idle → generating → idle
idle → saving     → idle
idle → selecting  → idle
```

加载失败虽然释放 loading 操作，storage.ready 仍是 false，所以编辑和保存仍被禁止。停止生成是对正在进行的生成操作发取消请求，不需要再申请一把锁。返回终态后才释放 generating。

相较旧代码，现在目录选择期间也暂时禁止生成，状态组合更少，便于后续课程解释。clear 在空闲时同步更新内存，不开启额外异步操作。

## 6. 这次一起修复的交互

1. 加载、生成、保存和选择目录的禁用条件统一，页面与函数入口都检查。
2. send 同步返回 boolean，只有请求被接收，输入框才清空草稿。修复旧版“被拦截仍清草稿”的问题。
3. 草稿提升到 ChatWorkspace，空状态卡片与输入框共享它；确认清空时在同一个事件中清草稿，不再保留 key 卸载实验按钮。
4. 清空前显示确认，说明自动保存会替换旧记录；默认焦点放在保留按钮。
5. 消息可选中复制，保留换行、长文本自动折行；阅读上方历史时，新片段不会强行滚到底部。
6. 移除模板背景与首页排版，建立固定输入区、独立滚动和窄窗口侧栏。

## 7. 如何运行与验证

正常开发：npm run dev，或者 VS Code 的 Debug All。主进程窗口尺寸变化需要完整重启才生效。

常规检查：npm run typecheck、npm run lint、npm run build。

新增检查：npm run check:workspace。先构建，然后在隐藏 Electron 窗口加载真实编译页面，用测试专用 preload 连接内存替身。结果和截图位于 .ui-check/，不在正式应用入口导入测试能力，不读取真实 userData、密钥或调用网关。

本次已验证：

- Node/Web 类型检查、生产构建、全项目 ESLint 通过。
- 隔离 UI 检查通过：加载禁用、首次不写盘、建议仅填草稿、中文输入法/Shift+Enter 不误发送、普通 Enter 发送。
- 流事件按请求 ID 定向更新；生成停顿时不写盘；成功、停止和错误终态处理正确；停止轮次不进入后续上下文。
- 保存失败无重试循环，手动重试成功；目录选择自动保存，取消保留原路径且不保存。
- 清空确认与取消、窄窗口侧栏与固定输入区、加载失败禁止写入均通过。

验证边界：这些是实际 Electron 渲染下的模拟业务交互；没有新增真实模型、真实目录对话框或真实聊天文件读写的验收结论。受限环境首次阻止 Electron 子进程启动，随后通过自动授权在限制外运行同一隔离检查并通过。

整理前的 renderer 和主进程入口备份在 .local-backups/before-workspace-layout/，不包含密钥。该目录与测试产物已从格式化和代码检查范围中排除。正式源码按原 Prettier 规则统一格式。旧教学组件仅保留其原本同步设置订阅就绪状态的 lint 例外；正式功能仍启用完整 Hooks 规则。CommonJS 测试脚本使用对应 JavaScript 规则。

## 8. 后续课程建议

先花一次复习读懂 App → useConversation → 两个业务 Hook 的关系，用断点走一遍发送和保存。自定义 Hook 可以类比 Vue composable，但它的状态仍遵守 React 渲染与闭包语义。

之后建议按以下顺序安排，每次只扩展一个能力：

1. **退出保护**：未保存、生成中和保存失败时如何处理关闭，保存成功后再退出。
2. **多会话**：先设计会话 ID、活动会话和磁盘版本迁移，再让侧栏承载真正的列表、新建与切换。
3. **消息展示**：独立安排 Markdown、代码块与复制，处理模型文本作为不可信内容的渲染边界。
4. **终端面板**：在工作台预留的主内容布局下加入可调整底部区域，单独学习终端生命周期。
5. **SSH 与 MCP**：基于清楚的工作区、会话和任务边界继续扩展。

当前不需要引入全局状态库、路由或 UI 大型组件库。先在现有结构上做小功能；需要跨页面共享或多个会话时再判断。建议把这次结果建立为 Git 学习基线，之后一课一个提交，便于对照变化。

当前仍未实现多会话、退出拦截、Markdown 渲染、终端或设置页。没有保留空模块来假装这些能力已经完成。
