## 2. 用 Vue 经验理解状态

会话库相当于包含多篇文章的响应式对象；`activeConversationId` 是选择值；当前会话和消息是派生结果，类似 computed。

```text
library（唯一 state，保存整个库）
  ├─ activeConversationId ──► 当前会话
  └─ conversations[]           └─ messages → 消息列表 / 本次请求上下文

新建：追加一个会话并选择它
切换：只修改活动 ID
追加消息：先定位会话 ID，再更新其 messages
保存：提交整个 library，而不是当前 messages
```

React 里修改嵌套数组必须返回新对象。不要另建 `activeMessages` state，也不要 `library.conversations.push(...)`。

## 5. 主进程：先备份，再迁移落盘

本课采用明确规则：首次加载合法版本 1 时，先备份原始字节，再写入版本 2，成功后才交给界面。这样立即重启也不会重新生成历史会话 ID。版本 2 读取不重建 ID。

备份名包含 UUID，以 `wx` 创建，绝不覆盖已有备份。迁移失败返回失败，页面保持不可编辑。未知版本和坏 JSON 同样不能冒充空库。只有文件不存在才返回空库。

用下面内容替换 `src/main/conversation-store.ts`：

```ts
import { mkdir, readFile, writeFile, rename, rm } from 'node:fs/promises'
import { join } from 'node:path'
import { randomUUID } from 'node:crypto'
import { parseLibrary, readLibrary } from '../shared/conversation-library'
import type { ConversationLibrary, LoadLibraryResult } from '../shared/conversation-library'
import type { SaveConversationResult } from '../shared/conversation'

type Existing = { bytes: Buffer; library: ConversationLibrary; legacy: boolean }

export function createConversationStore(directory: string): {
  load: () => Promise<LoadLibraryResult>
  save: (value: unknown) => Promise<SaveConversationResult>
} {
  const file = join(directory, 'conversation.json')
  let queue: Promise<unknown> = Promise.resolve()

  function serial<T>(work: () => Promise<T>): Promise<T> {
    const next = queue.then(work, work)
    queue = next.catch(() => undefined)
    return next
  }

  async function readExisting(): Promise<Existing | null> {
    let bytes: Buffer
    try {
      bytes = await readFile(file)
    } catch (error: unknown) {
      if (typeof error === 'object' && error !== null && 'code' in error && error.code === 'ENOENT') {
        return null
      }
      throw error
    }
    if (bytes.length > 8_000_000) throw new Error('文件过大')
    const value: unknown = JSON.parse(bytes.toString('utf8'))
    const legacy = typeof value === 'object' && value !== null &&
      'version' in value && value.version === 1
    const library = readLibrary(value, legacy ? randomUUID() : '')
    if (!library) throw new Error('文件格式或版本不支持')
    return { bytes, library, legacy }
  }

  function recoverPending(library: ConversationLibrary): ConversationLibrary {
    return {
      ...library,
      conversations: library.conversations.map((conversation) => ({
        ...conversation,
        messages: conversation.messages.map((message) =>
          message.status === 'pending' ? { ...message, status: 'failed' } : message
        )
      }))
    }
  }

  async function writeLibrary(library: ConversationLibrary): Promise<void> {
    const text = JSON.stringify(library, null, 2)
    if (Buffer.byteLength(text, 'utf8') > 8_000_000) throw new Error('文件过大')
    const temporary = join(directory, `conversation-${randomUUID()}.tmp`)
    try {
      await mkdir(directory, { recursive: true })
      await writeFile(temporary, text, { encoding: 'utf8', flag: 'wx' })
      await rename(temporary, file)
    } finally {
      await rm(temporary, { force: true }).catch(() => undefined)
    }
  }

  return {
    load: () => serial(async (): Promise<LoadLibraryResult> => {
      try {
        const saved = await readExisting()
        if (!saved) {
          return {
            ok: true, missing: true,
            snapshot: { version: 2, activeConversationId: null, conversations: [] }
          }
        }
        const snapshot = recoverPending(saved.library)
        if (saved.legacy) {
          const backup = join(directory, `conversation-v1-${randomUUID()}.bak`)
          await writeFile(backup, saved.bytes, { flag: 'wx' })
          await writeLibrary(snapshot)
        } else if (JSON.stringify(snapshot) !== JSON.stringify(saved.library)) {
          // 将启动恢复结果持久化，返回值可以直接作为已保存基线。
          await writeLibrary(snapshot)
        }
        return { ok: true, missing: false, snapshot }
      } catch {
        return { ok: false, error: '读取或迁移失败：请检查文件格式、备份权限和磁盘。不要删除原记录。' }
      }
    }),
    save: (value: unknown): Promise<SaveConversationResult> => {
      const snapshot = parseLibrary(value)
      if (!snapshot) return Promise.resolve({ ok: false, error: '会话库格式或长度不符合保存要求。' })
      return serial(async (): Promise<SaveConversationResult> => {
        try {
          const existing = await readExisting()
          // 版本 1 必须先走 load 的备份迁移流程，save 不绕过它。
          if (existing?.legacy) throw new Error('请先加载旧记录')
          await writeLibrary(snapshot)
          return { ok: true }
        } catch {
          return { ok: false, error: '保存失败：请检查权限、磁盘或已有文件格式。未主动删除原文件。' }
        }
      })
    }
  }
}
```

注意四点：

1. `readExisting` 只读取和校验；保存前调用它不会将生成中的 pending 改掉。
2. `recoverPending` 只在加载流程执行，遍历所有会话，恢复结果写入成功后才返回。
3. `save` 先用 `parseLibrary` 复制可信字段，再排队；只接受版本 2，不允许未知数据覆盖文件。
4. 所有 load/save 共用原来的串行队列。若备份成功而替换失败，备份可能保留，下一次尝试也可能再生成一份，这是可接受的恢复痕迹。

临时文件与目标在同一目录，继续使用原课的 rename 替换策略；本课仍是单窗口、单进程管理数据，不解决外部编辑器同时改文件或断电持久性问题。

## 7. 保存 Hook：比较整个库

在 `useConversationStorage.ts` 中，将 `ConversationSnapshot` 的导入替换为 `ConversationLibrary`（来自 `../../../../shared/conversation-library`），并将本文件内两处类型引用一起替换。参数名 `snapshot`、`setSnapshot` 保留，它们现在表示整个库。

其他机制仍使用原实现：

- `JSON.stringify(snapshot)` 比较整个库，包括当前活动 ID。
- 加载返回值成为 `savedSignature`；主进程已完成迁移/启动恢复的落盘。
- 保存成功使用提交时的 `submittedSignature`，不能把后来状态误标成已保存。
- 正常保存受 `isClosePending()` 限制，退出专用的 `save('close')` 保留。
- 自动保存延迟恢复 `800`；依赖保留 `closePending`，失败暂停和手动重试保留。

因此切换会话也会 dirty，并保存当前选择。无需为切换单独执行磁盘读取或保存当前消息。

## 8. 会话控制器：只有一份库

用下面内容替换 `useConversation.ts`。此时流式 Hook 的参数还未升级，下一节接齐后再运行类型检查。

```ts
import { useCallback, useRef, useState } from 'react'
import type { ChatMessage } from '../../../../shared/conversation'
import { getActiveConversation } from '../../../../shared/conversation-library'
import type { Conversation, ConversationLibrary } from '../../../../shared/conversation-library'
import { useModelStream } from '../chat/useModelStream'
import { useConversationStorage } from './useConversationStorage'
import { useOperation } from './useOperation'
import type { Operation } from './useOperation'
import type { ConversationStorage } from './useConversationStorage'

export type ConversationController = {
  conversations: Conversation[]
  activeConversationId: string | null
  messages: ChatMessage[]
  operation: Operation
  canEdit: boolean
  canSend: boolean
  canNavigate: boolean
  storage: ConversationStorage
  chatError: string | null
  create: () => boolean
  select: (id: string) => boolean
  clear: () => boolean
  send: (content: string) => boolean
  stop: () => Promise<void>
  setClosePending: (value: boolean) => void
  getOperation: () => Operation
}

export function useConversation(): ConversationController {
  const [snapshot, setSnapshot] = useState<ConversationLibrary>({
    version: 2, activeConversationId: null, conversations: []
  })
  const [closePending, setClosePendingState] = useState(false)
  const closePendingRef = useRef(false)
  const setClosePending = useCallback((value: boolean): void => {
    closePendingRef.current = value
    setClosePendingState(value)
  }, [])
  const isClosePending = useCallback(() => closePendingRef.current, [])
  const operations = useOperation()
  const storage = useConversationStorage({
    snapshot, setSnapshot, operations, closePending, isClosePending
  })
  const active = getActiveConversation(snapshot)
  const messages = active?.messages ?? []

  const updateMessages = useCallback((
    conversationId: string,
    update: (previous: ChatMessage[]) => ChatMessage[]
  ): void => {
    setSnapshot((previous) => ({
      ...previous,
      conversations: previous.conversations.map((item) =>
        item.id === conversationId ? { ...item, messages: update(item.messages) } : item
      )
    }))
  }, [])

  const stream = useModelStream({
    conversationId: active?.id ?? null, messages, updateMessages, operations
  })

  function canChange(): boolean {
    return storage.ready && !closePendingRef.current && operations.isIdle()
  }

  function create(): boolean {
    if (!canChange() || snapshot.conversations.length >= 100) return false
    const id = crypto.randomUUID()
    setSnapshot((previous) => {
      if (previous.conversations.length >= 100) return previous
      return {
        ...previous,
        activeConversationId: id,
        conversations: [...previous.conversations, {
          id, title: `新会话 ${previous.conversations.length + 1}`, messages: []
        }]
      }
    })
    stream.clearError()
    return true
  }

  function select(id: string): boolean {
    if (!canChange() || !snapshot.conversations.some((item) => item.id === id)) return false
    setSnapshot((previous) => previous.activeConversationId === id ? previous : {
      ...previous, activeConversationId: id
    })
    stream.clearError()
    return true
  }

  function clear(): boolean {
    if (!canChange() || !active) return false
    updateMessages(active.id, () => [])
    stream.clearError()
    return true
  }

  const canNavigate = storage.ready && operations.operation === 'idle' && !closePending
  const canEdit = canNavigate && active !== null
  return {
    conversations: snapshot.conversations,
    activeConversationId: snapshot.activeConversationId,
    messages,
    operation: operations.operation,
    canNavigate, canEdit, canSend: canEdit,
    storage, chatError: stream.error, create, select, clear,
    stop: stream.stop, setClosePending, getOperation: operations.getOperation,
    send: (content) => canChange() && active !== null && stream.send(content)
  }
}
```

`canNavigate` 允许空库新建；`canEdit` 要求已有活动会话。按钮的 disabled 用于显示，函数入口再次检查 ref 用于即时互斥。`updateMessages` 用空依赖的 useCallback 保持稳定，不从闭包里读取“当前活动 ID”。

标题先使用“新会话 1”等稳定文字，不自动由消息推导；重命名留到之后。达到 100 条禁用新建。库总消息/正文超限时沿用保存失败提示与暂停，不静默截断；可清理当前会话后手动重试。

增量回调、`finishTurn`、发送时追加占位消息：这三处原来都是 `updateMessages((previous) => ...)`，全部改为：

```ts

```

上面是调用形状示意，不要把 `previous` 原样返回覆盖原逻辑。完整的增量更新应当是：

```ts
updateMessages(active.conversationId, (previous) =>
  previous.map((message) =>
    message.id === active.assistantId && message.status === 'pending'
      ? { ...message, content: message.content + event.delta }
      : message
  )
)
```

### 9.5 保留结束身份检查

`run` 的 Promise 返回、catch、finally 仍检查 `activeRequest.current?.requestId === active.requestId`。调用停止只发出取消请求，不立即 `finish('generating')`；等原 Promise 确认取消或结束，再解除操作锁。

会话 ID 防止消息找错位置，requestId 防止旧生成结果混入新请求。这两层都需要，不能因为禁用了切换按钮就删除请求身份检查。


本课明确切换就丢弃未发送草稿，不对草稿做 dirty 或退出保存。点击当前会话不会改变 ID，所以不清草稿。不要给整个 `ChatWorkspace` 加活动 ID 的 key：它包含 CloseGuard，整块重挂载会重建关闭订阅。

为窄屏侧栏收起时也能从空库开始，在 `chat-scroll-area` 内将原来的 `messages.length === 0 ? ...` 条件整体替换为：

```tsx
{conversation.activeConversationId === null ? (
  <div className="empty-state">
    <p>还没有会话，先新建一个。</p>
    <button type="button" disabled={!conversation.canNavigate}
      onClick={() => { conversation.create() }}>
      新建会话
    </button>
  </div>
) : messages.length === 0 ? (
  <EmptyState disabled={!conversation.canSend} onSuggestion={suggest} />
) : (
  <MessageList messages={messages} />
)}
```

清空确认弹窗和 `CloseGuard` 保留原位置。保存按钮现在保存全库，退出的 dirty 也已经覆盖所有会话，不能改成仅检查活动会话是否有未保存内容。

## 11. 先做不接触真实聊天的存储验收

新建 `scripts/check-conversation-store-v2.cjs`，内容如下。它只在系统临时目录创建测试文件，finally 只删除自己创建的目录，不读取真实 userData。

```js
const assert = require('node:assert/strict')
const fs = require('node:fs/promises')
const { join } = require('node:path')
const { tmpdir } = require('node:os')
const { createConversationStore } = require('../.ui-check/lesson14-build/main/conversation-store.js')

async function main() {
  const directory = await fs.mkdtemp(join(tmpdir(), 'zonecodex-lesson14-'))
  const file = join(directory, 'conversation.json')
  const store = createConversationStore(directory)
  try {
    const empty = await store.load()
    assert.equal(empty.ok, true)
    assert.equal(empty.missing, true)
    assert.equal(empty.snapshot.activeConversationId, null)
    await assert.rejects(fs.readFile(file), { code: 'ENOENT' })

    const old = { version: 1, workspacePath: null, messages: [
      { id: 'm1', role: 'assistant', content: '原来的半条回复', status: 'pending' }
    ] }
    const bytes = Buffer.from(JSON.stringify(old, null, 2))
    await fs.writeFile(file, bytes)
    // save 不能绕过旧文件迁移。
    assert.equal((await store.save(empty.snapshot)).ok, false)
    assert.deepEqual(await fs.readFile(file), bytes)

    const loaded = await store.load()
    assert.equal(loaded.ok, true)
    assert.equal(loaded.missing, false)
    assert.equal(loaded.snapshot.conversations[0].messages[0].status, 'failed')
    assert.equal(loaded.snapshot.conversations[0].messages[0].id, 'm1')
    const backups = (await fs.readdir(directory)).filter((name) => name.endsWith('.bak'))
    assert.equal(backups.length, 1)
    assert.deepEqual(await fs.readFile(join(directory, backups[0])), bytes)
    const disk = JSON.parse(await fs.readFile(file, 'utf8'))
    assert.deepEqual(disk, loaded.snapshot)
    assert.deepEqual((await createConversationStore(directory).load()).snapshot, disk)
    assert.equal((await fs.readdir(directory)).filter((name) => name.endsWith('.bak')).length, 1)

    const firstId = disk.activeConversationId
    const two = { ...disk, activeConversationId: 'second-chat', conversations: [
      disk.conversations[0],
      { id: 'second-chat', title: '第二条', messages: [
        { id: 'm1', role: 'assistant', content: '第二条半成品', status: 'pending' }
      ] }
    ] }
    assert.equal((await store.save(two)).ok, true)
    // 正常保存不改 pending；下一次启动加载才恢复。
    assert.equal(JSON.parse(await fs.readFile(file, 'utf8')).conversations[1].messages[0].status, 'pending')
    const recovered = await createConversationStore(directory).load()
    assert.equal(recovered.snapshot.activeConversationId, 'second-chat')
    assert.equal(recovered.snapshot.conversations[0].id, firstId)
    assert.equal(recovered.snapshot.conversations[1].messages[0].status, 'failed')
    assert.deepEqual(JSON.parse(await fs.readFile(file, 'utf8')), recovered.snapshot)

    assert.equal((await store.save({ ...two, activeConversationId: 'missing' })).ok, false)
    for (const bad of ['{broken', '{"version":99}', 'null']) {
      await fs.writeFile(file, bad)
      assert.equal((await store.load()).ok, false)
      assert.equal((await store.save(two)).ok, false)
      assert.equal(await fs.readFile(file, 'utf8'), bad)
    }
    // 上次失败不应让队列永久失效。
    await fs.writeFile(file, JSON.stringify(recovered.snapshot))
    const results = await Promise.all([store.save(two), store.load()])
    assert.equal(results[0].ok, true)
    assert.equal(results[1].ok, true)
    assert.equal((await fs.readdir(directory)).some((name) => name.endsWith('.tmp')), false)
    console.log('第十四课存储通过：备份迁移、稳定 ID、整库恢复、损坏保护与队列恢复。')
  } finally {
    await fs.rm(directory, { recursive: true, force: true })
  }
}
main().catch((error) => { console.error(error); process.exitCode = 1 })
```

## 12. 正式交互验收与断点

所有代码接齐后，完整停止并重新启动开发应用；main/preload 改动不能只靠页面热更新。第一次启动会按第 5 节规则迁移旧记录并留下备份。可在调试器中检查 `directory`、`backup` 和 `file` 的实际路径，不要猜 userData 位置。

| 操作 | 预期现象 |
|---|---|
| 第一次读取旧格式 | 历史会话可见；原始字节备份存在；正式文件为版本 2 |
| 新建第二条会话 | 列表新增且选中；消息为空；不会清掉历史会话 |
| 两个会话分别发送不同问题，再切换 | 各自显示自己的消息，模型上下文只来自当前会话 |
| 空闲切换后等待自动保存再重启 | 所有会话和最后活动 ID 恢复；会话 ID 不改变 |
| 在 A 写草稿后切 B 再回 A | 草稿清空；已发送消息保留 |
| 生成中点击新建/切换，点击停止后立即再点 | 请求终态前均不可切换；结束后恢复可用 |
| 清空 B，切回 A | 只清 B 的消息；A 不变；B 这个会话仍在列表中 |
| 读取/保存中或关闭确认出现时 | 新建、切换、发送均不可用，函数入口也拒绝 |
| 保存失败 | 显示错误且自动保存暂停；手动重试成功才清除错误 |
| 退出保护的三个选择 | 继续编辑恢复操作；保存后关闭保存全库；不保存关闭放弃未落盘变更 |
| 侧栏收起且库为空 | 消息区域的新建入口可用 |

退出弹窗不一定出现：若自动保存已经成功，空闲关闭会直接退出。需要观察未保存窗口时，可临时延长计时器做实验，结束后恢复 800ms。

三个断点练习：

1. 在 `load` 的旧版分支暂停：观察先完成备份再调用 writeLibrary，返回 ID 与磁盘 ID 一致。
2. 在 `select` 暂停：切换只改变活动 ID，没有搬运消息；观察整库 signature 如何变化。
3. 在增量回调暂停：观察 requestId 筛选、active.conversationId 定位会话，再定位 assistantId。旧 requestId 的事件应被忽略。

常见错误：仅升级类型不改 preload 校验；保存当前消息导致其他会话消失；更新回调依赖活动 ID 导致订阅重建；点停止立即放开切换；用整个 ChatWorkspace 的 key 清草稿；读取失败仍将 ready 置 true。这些都要结合调用链排查。

## 13. 自测题

1. 为什么本课要保存整个库？只保存当前会话会丢掉什么？
2. 为什么迁移必须先备份再替换文件？为什么迁移成功后立即落盘会话 ID？
3. 什么情况才可以返回空库？未知版本和坏 JSON 为什么不能这样处理？
4. 为什么新建需要 canNavigate，而发送还需要活动会话存在？
5. 为什么按钮 disabled 之外，函数入口还检查 closePendingRef 和 isIdle？
6. active.conversationId 与 requestId 分别阻止哪一种写错？为什么点停止后不能立即放开切换？
7. 切换为何会 dirty？为什么此时不需要“先把当前消息复制回库”？
8. pending 在什么时候恢复？为什么不能在每次保存或通用解析中恢复？

不要求背术语，用“历史会话 A”和“新会话 B”举例；遇到不理解的题，把对应函数里的变量值写出来再解释。
第十四课的 8 道自测题，可以这样理解：

**1. 为什么保存整个库？只保存当前会话会丢掉什么？**

库里不仅有当前会话，还有其他会话和当前选择的 ID。

例如有 A、B 两条会话，只用 B 覆盖整个文件，A 就丢了。所以保存的是整个 `snapshot`，界面只显示其中一条。

**2. 为什么先备份再替换？为什么迁移后立即保存会话 ID？**

备份保留原始旧记录，迁移出问题时还有恢复依据。

旧格式没有会话 ID，迁移时新增一个并立即保存，下次启动就读取这个 ID。否则每次启动重新迁移，同一条历史会话的身份会不断变化。

**3. 什么情况可以返回空库？**

本课只有**文件不存在**时，才把它当作首次使用，返回默认空库。合法文件本身保存了空库，也可以正常读取。

坏 JSON、未知版本表示“无法读取”，不表示“没有聊天”。如果当作空库继续保存，可能覆盖原来的记录。

**4. 为什么新建只需 `canNavigate`，发送还要求活动会话存在？**

空库时没有活动会话，但必须允许用户新建。

发送则需要明确消息放进哪个会话，因此必须同时满足：

```text
已加载 + 当前空闲 + 没有关闭确认 + 存在活动会话
```

**5. 按钮已经 disabled，为什么函数入口还检查 ref？**

按钮禁用需要 React 更新界面后才生效；ref 可以立即改变。

例如开始生成时，操作 ref 已经变成 `generating`，即使按钮尚未重新渲染，另一次调用也会被 `isIdle()` 拦住。

所以 disabled 负责界面反馈，入口检查负责真正阻止操作。

**6. 会话 ID 和 requestId 分别防什么？为什么停止后不能立即切换？**

- `active.conversationId`：确定消息属于 A 还是 B。
- `requestId`：确定增量属于当前请求，防止旧请求的迟到结果混进来。

点击停止只是**发出取消请求**，请求可能尚未结束，还有增量或结束结果在路上。本课要等请求确认结束，再解除生成锁、允许切换。

**7. 为什么切换会 dirty？为什么不用先把消息复制回库？**

切换修改了 `activeConversationId`，整个库的内容因此变化，与上次保存的签名不同，所以会 dirty。保存后，重启才能恢复最后选择的会话。

消息本来就在库里的 `conversations[i].messages` 中。页面展示的是从库里找到的消息，并没有另一份需要“复制回去”的独立状态。

**8. pending 什么时候恢复？为什么不能每次保存时恢复？**

启动加载时，将所有会话中遗留的 `pending` 改为 `failed`：上次进程已结束，原来的生成任务不能继续了。

正常运行时的 `pending` 可能正在生成，保存或解析时把它改为 `failed`，就会误判正常请求。

因此本课分工是：**解析检查数据，迁移转换结构，启动加载处理上次中断的状态。**
