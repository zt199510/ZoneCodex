## 1. 目标与范围

本课完成一个可观察的小功能：用户审查建议后点击“检查写入条件”，主进程重新读取磁盘，将当前原始字节与选择文件时保存的原始字节比较。未变化则打开具体内容的确认面板；已变化则提示冲突，并要求重新选择文件、重新生成建议。

本课是实际写入之前的准备阶段，所有源文件访问仍为只读。按钮不得叫“应用修改”，结果不得显示“写入成功”。下一课再加入备份、实际提交、失败恢复和提交后的授权失效处理。

继续限定单文件、原文与候选各最多 80 行、2000 个 JavaScript 字符。沿用现有聊天入口、建议卡片和差异面板；不新增模型工具、不新增依赖、不把磁盘路径或原始字节发送给模型，不改会话库版本 4。

准备检查通过只证明检查时没有发现变化，不代表获得长期写入许可，也不保证稍后磁盘仍然相同。

## 5. 练习一：保存真正的磁盘基线

在主进程快照中新增内部文件记录，至少包含：

```ts
type SourceBaseline = {
  absolutePath: string
  originalBytes: Uint8Array
  hasUtf8Bom: boolean
  newline: 'lf' | 'crlf' | 'none' | 'unsupported'
}
```

实际类型还应保留现有读取验证用到的文件身份和元信息，例如 dev、ino、size、mtimeMs、ctimeMs。文件时间与大小是辅助检查，不能替代字节比较。

修改现有 `readSelectedFile`，从同一次成功读取中生成原始字节副本和文本行数组。不要关闭文件后再读一次来构造基线，否则两份内容可能来自不同版本。原始字节不得包含预分配缓冲区中尚未读取的尾部空间。

明确检测 UTF-8 BOM 后再解码；继续拒绝非法 UTF-8。识别纯 LF、纯 CRLF、无换行和不支持的混合/孤立 CR 换行。不支持准备写入的文件仍可保持原有只读使用能力，不必扩大读取拒绝范围。

基线只存在主进程内存，不能加入 `ProjectSelection`、preload 返回值、模型清单、工具结果或持久化聊天库。新增、刷新和移除附件时同步维护这份记录；旧快照和测试快照缺少基线时返回“请重新选择文件”，不要凭规范化文本补造基线。

预期：规范化后内容相同的 LF 和 CRLF 文件，其原始字节仍然不同。

## 6. 练习二：明确编码与换行策略

模型候选采用规范化的 LF 文本。准备阶段根据基线生成拟写入字节：

1. 校验候选原始字符串上限，再规范化 CRLF/CR 为 LF，检查行数和字符数。
2. 保留原文件的 UTF-8 BOM 策略；候选开头出现 U+FEFF 时明确拒绝，避免重复 BOM 或把它当成普通源码。
3. 原文纯 CRLF 则将候选 LF 转成 CRLF；纯 LF 则使用 LF。
4. 原文无换行时，本课明确采用 LF；面板显示该策略。
5. 原文为混合换行或孤立 CR 时返回 unsupported，说明本课暂不准备此类文件。
6. 保留候选自身是否带末尾换行的决定；不要额外 trim，也不要自动追加换行。

最后检查候选编码后的字节上限。空候选合法；若原文件带 BOM，本课策略会生成只有 BOM 的文件内容。面板应显示“正文为空，保留 UTF-8 BOM”，不能把它描述成零字节。

如果候选字节与基线完全相同，返回 no_change，不创建准备记录。

预期：同一候选在 LF 与 CRLF 基线上得到不同的字节数组，未要求变化的编码标记得到保留。

## 7. 练习三：检查当前磁盘是否冲突

实现只读准备服务，输入可信快照、附件别名、候选和 AbortSignal。真实路径只能从该快照内部记录获取，不接收 renderer 提供的绝对路径。

复用现有路径、符号链接/目录联接、普通文件和非硬链接检查。重新打开目标文件，只读、有界读取；核对读取前后文件身份和元信息，发现替换、变化、删除、权限错误或无法确认时明确失败。

核心顺序：

```text
检查取消 → 取得基线 → 验证路径与文件身份 → 只读打开
→ 有界读取与前后状态核对 → 比较原始字节 → 构造候选字节
→ 再次检查取消 → 返回准备所需数据 → finally 关闭句柄
```

原始字节不同就返回 conflict，即使大小、修改时间或规范化文本一样。冲突提示为“文件在生成建议后发生变化，请重新选择文件并生成建议”；不得自动刷新基线后继续接受旧候选。

此服务不写源文件、不创建备份、不创建临时替换文件。它也不保证检查完成后文件不会再次变化：检查与将来的提交之间存在时间间隔，下一课提交时必须重新验证，不能只看准备时间或 ID。

## 8. 练习四：主进程绑定短期准备记录

定义严格的请求解析器：字段必须恰好匹配，拒绝数组、访问器、未知字段、非法别名和超限内容。请求可包含 conversationId、snapshotId、path、proposedText，以及用于关联消息的 requestId、callId；后两者只是关联信息，不能据此宣称主进程已经验证了历史成功轮次。

结果使用可区分联合：ready、conflict、no_change、unsupported、error。ready 返回不透明 preparationId、会话/快照/别名、字节数、编码换行说明和过期时间；绝对路径与原始字节始终留在主进程。

主进程内部记录绑定：窗口、会话、快照、来源关联、原始基线、精确候选文本、精确候选字节及有效期。每窗口最多一份，建议有效期两分钟。过期后删除；替换记录时清除旧定时器。记录仅用于准备，不会在本课被消费为写入操作。

IPC 必须检查所属窗口和 main frame，使用 `captureProjectAccess` 获取现有授权。所有异步步骤完成后，再次核对当前授权仍指向捕获的快照且请求仍是最新请求，然后才能发布 ready。仅持有开始时取得的快照引用不够。

通过主入口注入回调建立互斥，避免新增模块互相导入形成循环：

- 准备期间，开始生成、选择、移除和主动撤销均明确拒绝；renderer 复用 selecting 操作状态。
- 刷新、窗口销毁等强制清理必须能取消准备任务，删除准备记录。
- 授权变化、切换会话、关闭准备面板、替换建议时清除对应记录；取消接口只能清理所属窗口的匹配任务/记录。
- finally 必须释放任务占用；取消异常不能转成 ready，迟到结果不得重新登记。

不要创建第二套文件授权 Map。准备记录保存的是一次检查结果，其有效性仍依赖原有授权系统。

## 9. 练习五：在现有差异面板加入准备入口

只对当前可用的成功消息建议显示“检查写入条件”；手填调试预览本课不进入准备流程。

点击前重新核对当前会话、建议来源、快照、别名和空闲状态。准备过程禁用重复入口，显示“正在检查磁盘版本…”。主进程检查成功后显示：

- 文件名和附件别名。
- 与当前建议完全一致的差异内容。
- UTF-8/BOM 与换行策略、预计字节数。
- “检查通过，尚未写入；实际提交前仍需再次检查”。

本课面板只有“返回审查/关闭”，不提供假装可用的确认写入按钮。冲突时保留旧差异供阅读，但禁止使用本次准备结果，提示重新选择并重新提出修改要求。

候选、来源、会话或快照变化时立即清空准备状态。复用请求序号、挂载标记和上下文比较处理迟到结果。关闭、Escape 和丢弃必须同步取消准备，保持第 23 课关闭与隐藏建议的不同语义。

预期：关闭后再次检查会重新读取磁盘；重启后不会恢复准备状态；历史卡片不代表仍有当前授权。

## 10. 验收与排错

用自己创建的 `greet.ts` 副本练习，不使用重要文件。记录准备前后原始字节，全部场景都应保持源文件未被本功能修改。

| 场景 | 预期 |
|---|---|
| 文件未变化 | ready，显示具体候选和编码策略 |
| 编辑器保存了不同内容 | conflict，即使修改后字节数相同 |
| 只改变 LF/CRLF 或 BOM | conflict，不能只比较规范化文本 |
| 文件删除、替换或变为链接 | 明确拒绝，不换一个同名文件继续 |
| 原始快照没有字节基线 | 要求重新选择文件 |
| 候选完全相同 | no_change，不生成准备记录 |
| 空候选 | 合法，并准确说明 BOM 与字节数 |
| 超限或混合换行 | 明确拒绝，不截断内容 |
| 检查中关闭、刷新或销毁窗口 | 取消并清理，迟到结果不恢复面板 |
| 伪造窗口、会话、快照或绝对路径 | 主进程拒绝 |
| 检查成功后又改磁盘 | 旧 ready 不代表可直接提交，下一课重新比对 |

在现有离线检查脚本中补充基线、编码、冲突、取消与失效断言，不要求另建测试框架。涉及文件状态的检查使用隔离临时目录，清理只针对本次创建的目录。

运行 `npm run typecheck`、`npm run build`，并适配后运行 `npm run check:workspace`。检查失败要记录原因；类型通过不等于异步与磁盘检查通过。实际观察 680×560 窗口下的面板、错误提示与输入框是否可操作。
