# 第二十七课：工作目录授权与命令执行准备

创建日期：2026-09-18。状态：课程已创建，待学习者实现与验收。

前一课：[单条命令提案与执行前审查](36-第二十六课-单条命令提案与执行前审查.md)。第26课已实现并通过模拟、界面及历史刷新验收；真实模型待验收，参考答案不代表学习者已掌握。

## 1. 本课目标与范围

完成一个可观察的小功能：打开当前有效的命令提案，主动选择命令工作目录，查看该目录真实的 npm 脚本与配置，然后生成一份短期的“执行准备”记录。目录或配置改变后，准备记录失效，要求重新审查。

完整路径：附加文件 → 模拟命令提案 → 查看命令提案 → 选择命令工作目录 → 查看脚本 → 检查执行准备 → 显示准备完成 → 关闭并释放。

第26课提出的后续方向包含目录授权和受控执行。本课先完成目录与审查上下文，下一课再做 Windows 启动方式、明确执行确认、输出、超时、取消和进程树清理，避免一课同时引入两套生命周期。

本课不启动 npm，不安装依赖，不向手动终端输入，不提供“确认执行”按钮。界面明确显示：**准备完成，尚未执行；实际执行仍需单独确认。** 本课产生的 ID 不是执行许可，未来执行接口不得仅凭它启动命令。

## 2. 课前核对与授权边界

当前代码中的事实：

- `src/shared/command-proposal.ts` 固定映射 npm、参数 run/typecheck，目录状态为 unbound。
- `propose_command` 只接受 template/reason，每任务一份；模型不能提供 cwd、命令字符串或环境变量。
- `useCommandReview.ts` 只保留最小来源标识，从当前消息和快照重新派生有效提案；历史记录不恢复附件授权。
- `CommandReviewPanel.tsx` 目前只展示原因、未绑定目录、固定影响说明与关闭按钮。
- `project-access.ts` 管附件快照，附件的虚拟路径不是磁盘路径，更不是目录执行授权。
- `local-terminal.ts` 为用户手动启动 PowerShell，cwd 使用用户主目录；它的授权和输入接口不能复用为本课命令入口。
- 文件写入准备已有独立主进程记录与互斥机制，可参考生命周期，但不能把单文件写入令牌用于命令准备。

目录选择只表示允许应用为这份提案读取指定目录的有限配置并显示审查信息，不授权上传目录内容、不授权遍历全部文件，也不授权执行。界面应在打开选择器前说明用途。

本课允许用户选择与附件不同的目录，但必须明确显示二者是独立来源，不能暗示附件内容就是所选目录当前内容。不要通过附件父目录、同名文件或应用启动目录自动补全授权。

## 3. 用 Vue 经验理解本课

| Vue 经验 | React / Electron 对应 | 本课用途 |
|---|---|---|
| computed 派生可用状态 | 根据来源、目录记录与操作状态派生 | 减少重复的 ready/approved 布尔值 |
| composable 管异步请求 | Hook + 请求 ID + 过期结果丢弃 | 旧目录选择结果不能覆盖新提案 |
| 服务端 session | 主进程窗口归属的内存 Map | renderer 拿 ID，主进程保管路径与基线 |
| 表单前后端都校验 | UI 禁用 + IPC 主进程复核 | 防止绕过按钮直接调用 |
| onUnmounted 清理 | Effect cleanup 加主进程导航/销毁清理 | 刷新不能依赖页面一定送达撤销请求 |

先画出四种状态：未绑定 → 读取中 → 已绑定并展示 → 准备完成。取消、来源变化、超时和错误如何返回可解释的状态，由你补全。

## 5. 第一步：定义来源和最小接口

先写类型草图，再实现严格解析；不要直接照抄文件写入接口。

```ts
type CommandSource = {
  conversationId: string
  requestId: string
  assistantId: string
  callId: string
  snapshotId: string
  template: 'npm_typecheck'
}
```

建议接口职责：

1. `selectCommandDirectory(source)`：只接收来源；主进程打开单目录选择器。renderer 不传目录路径。
2. `prepareCommand({ source, grantId, checkId })`：重新读取并比较配置，返回短期准备记录或明确失败原因。
3. `releaseCommandDirectory(grantId)`：只释放当前窗口拥有的记录；重复释放幂等。
4. `cancelCommandPreparation({ source, operationId })`：取消尚未返回 grantId 的选择/检查任务。为异步操作分配代际 ID，避免关闭面板时无 ID 可撤销，也避免旧取消请求伤及新任务。

结果用可区分联合表达 selected/cancelled/ready/conflict/expired/error，不把取消当错误；错误文本限制500字符。参数只接受普通对象、准确字段和受限 ID。preparedId、grantId 均由主进程随机生成，不从路径推导。

主进程保存窗口 ID、来源、规范化真实目录、目录身份、配置原始字节摘要和创建时间。renderer 只得到用于显示的目录绝对路径、有限脚本信息、不透明 ID 和失效时间；以后不能凭展示路径重新获得授权。

注意：第26课完整 ToolRun 主要由 renderer 保存，主进程现有任务表不是提案登记表。不要声称主进程能仅凭 requestId 证明该提案已成功。当前应严格检查来源格式、现有附件窗口/会话/快照授权、固定模板以及登记后的来源一致性；UI 仍从当前完整协议派生。下一课在执行前必须另行确定可信提案登记或独立完整执行审查，不能把本课来源检查称为执行授权验证。

## 6. 第二步：由主进程选择并读取真实目录

用 Electron 原生单目录选择器，不恢复早期课程中的任意路径输入框。打开前占用窗口选择状态，防止重复点击；等待选择器期间若来源或窗口失效，迟到结果必须丢弃并释放占用。

本课限制为本机普通目录：拒绝 UNC 网络路径、符号链接/目录联接等重定向入口，规范化后再读取；核对 lstat/realpath 与可用的目录身份信息。不要用简单字符串 startsWith 判断路径包含关系。若当前平台无法可靠判定，应返回不支持，不能默默放宽。

只读取根目录 `package.json` 及可选根目录 `.npmrc`，不递归、不读取 node_modules、不运行任何探测命令。每个文件最多64 KiB；使用有上限的读取，不能只检查 stat 后再无限制 readFile。要求普通文件，拒绝链接，检查读取前后身份与字节基线；缺失、权限、删除和替换都要有明确结果。

package.json 以 UTF-8 读取，允许开头 BOM，拒绝无效编码、非法 JSON、数组根节点或不是对象的 scripts。提取：

- `scripts.typecheck`：必需且为非空字符串。
- `scripts.pretypecheck`、`scripts.posttypecheck`：若存在必须为字符串，明确区分未配置和空字符串。
- `packageManager`：存在时展示受限长度的声明文本，不视为已定位 npm 程序。

三个脚本分别按纯文本展示，单项超过2000字符则拒绝本次准备；不得截断关键脚本后仍标记准备完成。不要按危险关键词判断脚本是否安全。

`.npmrc` 可能含令牌，不能把全文传 renderer、写 trace、截图或发送模型。仅在主进程保留摘要与存在状态，对允许展示的配置采用明确白名单和长度校验；最小实现只显示“根目录 .npmrc 存在/不存在，内容未展示”即可。

审查说明必须写清：这里只读取根目录有限配置，npm 还可能受到用户/全局配置、环境变量、工作区及脚本引用文件影响。本课没有解析最终有效 npm 配置，不能承诺后续进程的全部行为已经审计。不得为读取配置调用 `npm config`，那也是启动程序。

预期：选择隔离练习目录，能显示真实绝对目录与三个脚本；无 package.json、无 typecheck 或内容非法时返回明确错误，仍没有进程启动。

## 7. 第三步：生成可失效的准备记录

首次读取完成后展示脚本，不自动进入“准备完成”。用户点击“检查执行准备”，主进程重新读取目录及配置，比较原始字节摘要、存在状态和身份；特别检查 `.npmrc` 从不存在变为存在的情况。

如果发生变化，返回 conflict，清除旧 preparedId，并让用户重新选择/读取和审查。不要自动接受新脚本再保留旧准备状态。

只有目录和基线仍一致，才生成 preparedId，绑定窗口、完整来源、grantId 与基线。建议目录审查记录5分钟到期，准备记录60秒到期，均由主进程时钟判定；界面倒计时只是提示，不能作为授权依据。

准备记录不占用长期“正在执行”操作状态，检查结束后要释放短期占用；同一窗口只保留一份目录审查记录和一份准备记录。替换、关闭或来源失效时主动释放，TTL 负责兜底，不能只靠 TTL。

复查前后仍可能存在文件系统竞态，脚本引用文件也未被完整冻结。因此“准备完成”仅表示本次有限检查成功，不是目录快照、只读保证或未来执行许可。未来真正启动前必须重新检查并取得具体确认。

## 8. 第四步：接入现有审查面板

保留第26课的逻辑程序、逐项参数、模型原因、固定影响和未执行状态。在工作目录区域增加：

| 状态 | 展示与操作 |
|---|---|
| 未绑定 | 说明选择只用于本次读取与审查；“选择命令工作目录” |
| 读取中 | “正在读取目录配置”，禁止重复选择 |
| 已绑定 | 真实目录、pretypecheck/typecheck/posttypecheck、配置读取范围；“检查执行准备”“重新选择目录” |
| 准备完成 | 有效时间、“尚未执行；实际执行仍需单独确认” |
| 冲突/过期 | 原因与“重新选择目录”，不能继续沿用旧 ID |

所有状态均保留关闭方式；长脚本区域和面板正文能滚动，680×560 窗口关闭按钮仍可见。Escape 关闭后回到原卡片按钮，原按钮已失效时回输入框。

当前 `commandTemplate.cwdStatus` 描述模型原始提案，不要将全局模板改为 bound。绑定目录属于这一次审查会话的独立临时状态，也不要修改原历史卡片来保存路径或“已批准”。

来源变化时复用第26课派生校验，但注意 Hook 已清空 UI 状态并不意味着主进程 Map 已释放。异步取消要有实际撤销路径，迟到的 selected/ready 响应也必须释放其资源。

接线时尤其核对 `useConversation.ts` 传给 `useCommandReview` 的 available：当前条件要求 operation 为 idle。若新目录选择也占用 selecting，却不区分“本面板自己的操作”，会导致刚点击选择就关闭面板。应把提案来源有效性与外部操作互斥分开派生：自己的目录选择/准备可以保留面板并显示忙碌，外部新任务或文件操作才关闭；不要简单删除全部互斥判断。

## 9. 第五步：完成生命周期与互斥

按以下顺序实现并验证：

1. 检查/选择期间阻止本窗口重复准备、启动 Agent、附件选择和文件提交；必要互斥同时放在主进程，不能只有按钮 disabled。长时间有效的 ready 状态不阻塞整个应用。
2. 开始新任务、切换/删除会话、清空消息、替换/撤销附件、进入文件准备/提交时关闭命令面板，并释放对应目录/准备记录。
3. 第25课提交撤销旧快照时，同步使对应命令准备记录失效；不能只把 renderer 卡片变灰。
4. 关闭审查、Escape 或重新选择时释放旧 ID；释放请求只影响所属窗口及对应记录，不误删新一代记录。
5. 页面导航/刷新、renderer 崩溃、窗口销毁时由主进程清理。原生目录选择器不能被强行取消时，返回后丢弃失效结果。
6. 重启恢复版本4消息与提案说明，不恢复目录绑定或准备状态。重新选同名目录也必须生成新 grantId，并重新读取配置。

当前关闭保护与文件提交已有特殊等待行为。本课没有子进程，不增加进程停止分支，也不要破坏已有提交收尾流程。

## 10. 常见错误

| 现象 | 检查方向 |
|---|---|
| 一打开提案就显示附件所在目录 | 把文件授权错误升级成了目录授权 |
| 模型传 cwd 后能绕过选择器 | propose_command schema 或新 IPC 接收了不应有的字段 |
| scripts 变了仍显示准备完成 | 只比较文件大小/mtime，或未比较原始字节 |
| `.npmrc` 创建后准备仍有效 | 未把文件缺失状态纳入基线 |
| 关闭面板后主进程仍留记录 | 只做 React 状态清理，没有发送撤销或主进程失效通知 |
| 老选择器结果覆盖新提案 | 缺少来源/请求代际检查及迟到结果释放 |
| 界面出现令牌 | 输出了完整 `.npmrc`，应立即移除并使用脱敏夹具验收 |
| 准备完成后自动运行 | 混淆准备记录与一次明确执行确认 |

## 11. 验收清单

实现后运行 `npm run typecheck`、`npm run build`、相关文件 lint 和 `npm run check:workspace`。不新增依赖或测试框架，复用现有隔离脚本和 Electron 验收方式。

先创建可丢弃练习目录，package.json 使用仅供展示的 typecheck/pretypecheck/posttypecheck 字符串。测试不得真的运行这些脚本。`.npmrc` 只用明显的假测试值，不使用个人配置。

| 场景 | 应观察到的结果 |
|---|---|
| 当前有效提案 + 正常目录 | 显示真实脚本和目录，检查后短期 ready，尚未执行 |
| 用户取消选择 | 不生成新授权；首次选择仍未绑定，替换时旧状态按预先定义的规则一致处理 |
| 缺脚本、非字符串、超长、非法编码、过大文件 | 有界失败，无 ready |
| 链接目录/文件、UNC、读取时替换 | 拒绝或冲突，不静默跟随 |
| package.json 同长度改写、`.npmrc` 新建/删除 | 准备复查冲突，旧 preparedId 失效 |
| 重复点击、跨窗口 ID、伪造来源、过期 ID | 主进程拒绝，不产生重复记录 |
| 关闭/替换/新任务/文件提交/刷新 | 面板和主进程记录均失效，迟到响应不复活 |
| 重启及重新选择同名目录 | 历史说明仍在，目录与准备授权不恢复 |
| 680×560 与长脚本 | 无横向溢出，脚本可读，关闭和 Escape 可用 |
| 所有选择、读取、准备和关闭动作 | child_process、node-pty、utilityProcess 启动及 terminal:write 计数均为零 |

无进程验证继续采用第26课的入口拦截加源码调用链核对。新增目录服务只读配置；在测试前后比较隔离目录文件，确认没有生成锁文件、安装目录或修改 package.json。

本课不依赖真实模型调用，使用“模拟命令提案”即可验收；不要因此改写第26课“真实模型待验收”的记录。
