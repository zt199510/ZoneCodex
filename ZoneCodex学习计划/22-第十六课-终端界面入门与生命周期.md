## 2. 用 Vue 经验理解终端

### 2.1 终端界面不等于 shell

| 名称 | 负责什么 | 所在位置 |
|---|---|---|
| xterm.js | 绘制字符、光标、颜色，产生键盘输入数据 | renderer |
| FitAddon | 根据容器大小计算终端的列数和行数 | renderer |
| node-pty（下课） | 创建和管理伪终端进程，传递输入、输出及尺寸 | main |
| PowerShell（下课） | 解释命令并运行程序 | 操作系统子进程 |

最终调用链会是：

```text
键盘 → xterm.onData → preload → main → PTY → PowerShell
屏幕 ← xterm.write  ← preload ← main ← PTY ← PowerShell
```

本课先把中间部分替换成局部演示：输入在面板上显示为可读记录，输出由计时器提供。输入 `Get-Location` 不会查询目录。

### 2.2 第三方对象放在哪里

Vue 中你可能在 onMounted 后用模板 ref 初始化编辑器，再在 onBeforeUnmount 中销毁。React 中对应的思路是：

1. 用 useRef 获取容器 DOM。
2. 在 useEffect 中创建 Terminal 并 open 到容器。
3. Effect 返回清理函数，取消订阅、计时器、尺寸监听，最后 dispose 终端。

这里的 Effect 用于连接外部对象，不是为了把 Props 复制成 state。Terminal 自己维护屏幕缓冲区，不需要把每个输出字符都保存进 React state；state 只保存面板状态、尺寸和最近一次输入等少量界面信息。

当前 main.tsx 启用了 StrictMode。开发时 React 会额外执行一次 setup → cleanup → setup，帮助发现清理遗漏。不能靠删除 StrictMode 来修复重复输出。

### 2.3 终端面板与 AI 命令工具的关系

本课的 onData 面向人的键盘操作；后续 AI 工具调用接收结构化请求，由后台校验和执行，再返回输出、退出码和状态。不能把模型生成的 Markdown 代码块直接写进终端执行，也不能只靠读取终端画面判断命令是否完成。

xterm 实例和容器监听归 TerminalPanel 所有；真实 PTY 会话归主进程所有；未来 Agent 的任务生命周期由后台任务模块管理。这三个生命周期需要分别设计。当前课程仍采用“关闭面板即销毁显示实例”，后台持久任务不在本课引入。

## 4. 创建 TerminalPanel

新建 src/renderer/src/features/terminal/TerminalPanel.tsx：

```tsx
import { useEffect, useRef, useState } from 'react'
import { Terminal } from '@xterm/xterm'
import { FitAddon } from '@xterm/addon-fit'
import '@xterm/xterm/css/xterm.css'

type Controls = {
  start: () => void
  stop: () => void
  focus: () => void
}

export function TerminalPanel({ onClose }: { onClose: () => void }): React.JSX.Element {
  const hostRef = useRef<HTMLDivElement>(null)
  const controlsRef = useRef<Controls | null>(null)
  const [ready, setReady] = useState(false)
  const [running, setRunning] = useState(false)
  const [size, setSize] = useState('等待测量')
  const [lastInput, setLastInput] = useState('尚未输入')
  const [error, setError] = useState('')

  useEffect(() => {
    const element = hostRef.current
    if (!element) return
    // 保留非空的 DOM 引用，供后续异步回调使用。
    const host = element

    let disposed = false
    let timer: ReturnType<typeof setInterval> | null = null
    let frame: number | null = null
    let observer: ResizeObserver | null = null
    let inputSubscription: { dispose: () => void } | null = null
    const term = new Terminal({
      cursorBlink: true,
      fontSize: 13,
      fontFamily: "Consolas, 'Cascadia Mono', monospace",
      scrollback: 1000,
      theme: { background: '#18201c', foreground: '#e2e9e4' }
    })
    const fit = new FitAddon()

    function clearTimer(): void {
      if (timer !== null) clearInterval(timer)
      timer = null
    }

    function stop(): void {
      if (disposed || timer === null) return
      clearTimer()
      setRunning(false)
      term.writeln('\r\n[模拟输出已停止]')
    }

    function start(): void {
      // ref/闭包中的资源状态能立即挡住重复点击。
      if (disposed || timer !== null) return
      let count = 0
      setRunning(true)
      term.writeln('\r\n[开始模拟输出]')
      timer = setInterval(() => {
        if (disposed) return
        count += 1
        term.writeln(`第 ${count} 段：这只是终端显示练习。`)
        if (count === 10) {
          clearTimer()
          setRunning(false)
          term.writeln('[模拟输出完成]')
        }
      }, 300)
      term.focus()
    }

    function scheduleFit(): void {
      if (disposed || frame !== null) return
      frame = requestAnimationFrame(() => {
        frame = null
        if (disposed || host.clientWidth === 0 || host.clientHeight === 0) return
        try {
          fit.fit()
          setSize(`${term.cols} 列 × ${term.rows} 行`)
        } catch {
          setError('终端尺寸调整失败，请关闭面板后重新打开。')
        }
      })
    }

    try {
      term.loadAddon(fit)
      term.open(host)
      term.writeln('\x1b[32mZoneCodex 终端练习\x1b[0m')
      term.writeln('尚未连接 PowerShell，输入不会执行。')
      term.writeln('点击“模拟输出”；在终端按 Ctrl+C 可以停止。')
      term.writeln('键盘数据会显示在下面的“最近输入”区域。')

      inputSubscription = term.onData((data) => {
        if (disposed) return
        // 只展示本次事件，不积累全部输入，避免无限增长。
        setLastInput(JSON.stringify(data.slice(0, 120)))
        if (data === '\x03') stop()
      })

      observer = new ResizeObserver(scheduleFit)
      observer.observe(host)
      controlsRef.current = { start, stop, focus: () => term.focus() }
      setReady(true)
      scheduleFit()
      // 字体完成加载后再测量；Promise 无法撤销，所以检查 disposed。
      void document.fonts.ready.then(() => {
        if (!disposed) scheduleFit()
      })
    } catch {
      setError('终端初始化失败，请检查依赖和样式后重新打开面板。')
    }

    return () => {
      disposed = true
      controlsRef.current = null
      clearTimer()
      if (frame !== null) cancelAnimationFrame(frame)
      observer?.disconnect()
      inputSubscription?.dispose()
      // Terminal.dispose 会一起释放已经加载的 addon。
      term.dispose()
    }
  }, [])

  return (
    <section className="terminal-panel" aria-label="终端练习">
      <div className="terminal-toolbar">
        <strong>终端练习 · 未连接 shell</strong>
        <span>{size}</span>
        <button type="button" disabled={!ready || running}
          onClick={() => controlsRef.current?.start()}>模拟输出</button>
        <button type="button" disabled={!running}
          onClick={() => controlsRef.current?.stop()}>停止</button>
        <button type="button" disabled={!ready}
          onClick={() => controlsRef.current?.focus()}>聚焦输入</button>
        <button type="button" onClick={onClose}>关闭面板</button>
      </div>
      {error && <p role="alert" className="terminal-error">{error}</p>}
      <div className="terminal-host" ref={hostRef} />
      <p className="terminal-input-note">最近输入：<code>{lastInput}</code></p>
    </section>
  )
}
```

### 4.1 先读懂两条路径

- 输出：点击按钮 → start → 定时调用 term.writeln → 屏幕增加内容。
- 输入：聚焦终端 → 敲键盘 → term.onData → 最近输入区域更新。

xterm 不会自动把输入回显到屏幕。真实终端通常由 shell/终端驱动决定回显；下一课把输入发给 PTY，收到输出后再 write。若现在就无条件 `term.write(data)`，接真实 shell 后可能显示两份字符。

onData 不保证每次只有一个字符，粘贴可能是一大段。Enter 常见为 `\r`，Ctrl+C 为 `\u0003`，方向键可能是 `\u001b[A` 等转义序列。JSON.stringify 让控制字符可见；这里只展示前 120 个 UTF-16 代码单元，截断仅用于调试展示，下课发送给 PTY 时不能照搬截断。

本课的 Ctrl+C 只是调用 stop 清除计时器，不是系统进程信号。终端有文本选区时快捷键处理可能不同，验收时先取消选区并聚焦终端，也可以直接点停止按钮。

### 4.2 write、writeln 和颜色

`write` 写入字符或控制序列；`writeln` 额外添加回车换行。终端的 `\r` 表示回到行首，`\n` 表示换到下一行，它们不是同一个动作。

`\x1b[32m` 设置绿色，`\x1b[0m` 恢复样式。这是 ANSI 控制序列，不是 HTML。终端输出使用 Terminal 的接口，不交给 MarkdownContent，也不保存成聊天消息。

### 4.3 为什么监听容器大小

侧栏展开时，窗口宽度可以不变，但终端容器已经变窄。因此使用 ResizeObserver 观察 host，不只监听 window.resize。requestAnimationFrame 合并同一帧的重复测量；宽高为零时跳过，避免隐藏区域测出无效尺寸。

FitAddon 只调整 xterm 的行列；下一课还要把新行列发给 PTY。只改变 DOM 宽度，不代表 PowerShell 已知道尺寸变化。

### 4.4 每种资源都有对应清理

| 创建 | 清理 |
|---|---|
| setInterval | clearInterval |
| requestAnimationFrame | cancelAnimationFrame |
| ResizeObserver.observe | disconnect |
| term.onData | 订阅对象的 dispose |
| new Terminal / loadAddon | term.dispose |
| 字体加载 Promise | 完成后检查 disposed，不再访问旧实例 |

清理时不调用会更新 React state 的 stop，而是直接清除计时器。onClose 不放进初始化 Effect，Effect 也不依赖 running 或 size，否则每次状态变化都可能重建终端。

## 8. 常见错误

- **找不到模块**：确认在项目根目录成功安装两个 @xterm 包；不要只创建导入。
- **终端空白或只有细线**：检查容器高度、workspace-body 的 min-height 和终端样式导入。
- **输入没有显示在终端正文**：本课只观察输入事件，正文不回显。先看最近输入区域，不要把它当成真实 shell。
- **方向键不是“上”字而是一串转义字符**：这是正常终端数据，下一课应原样传给 PTY。
- **每次输出都清空屏幕**：检查是否把 running、lastInput 或 size 放进初始化 Effect 的依赖。
- **开发时出现两份输出**：检查 timer、订阅与终端实例是否全部清理，保留 StrictMode。
- **窗口没变但侧栏遮住字符**：检查是否观察终端容器，而不是只监听 window.resize。
- **关闭面板误触发应用退出**：面板按钮只调用 onClose，不调用 controlWindow 或 finishClose。
- **想把终端内容加进 Markdown 消息**：两者是不同的显示系统，本课不互相转换。

## 11. 自测 1–8 讲解（完成后的复习）

### 1. 三个工具分别做什么

xterm.js 负责终端的屏幕和键盘事件；node-pty 负责创建/连接伪终端进程，传递输入输出；PowerShell 负责理解和执行命令。只有 xterm 时，你有一个能显示文字、接收按键的界面，但没有解释 Get-Location 的程序。当前欢迎文字和模拟输出都来自你的 JavaScript。

### 2. onData 和 write 的方向

onData 是用户输入流出终端组件：按下 a，回调收到 a。write 是输出流入终端组件：term.write('你好')，屏幕显示你好。真实接线是键盘 → onData → PTY/shell → 输出 → write。

“回显”是让输入的字符出现在屏幕上。真实 shell/终端机制通常会提供回显；如果 onData 中自己写一次，再把后台返回的回显写一次，按 a 可能显示 aa。本课故意只在最近输入区域记录按键，没有自行实现 shell 的编辑功能。

### 3. 为什么在 Effect 中创建

组件函数会在每次渲染时重新执行；setRunning、setSize 都可能触发它。若把 new Terminal 放在函数顶层，就会反复创建实例，而且渲染时 DOM 引用还可能不存在。Effect 在 DOM 提交后初始化实例，并返回清理函数，把资源的使用期限与挂载关联起来。空依赖表示普通状态更新不重建；开发 StrictMode 还有额外检查。

### 4. state 与 ref 的分工

ready/running 变化后需要更新按钮，所以使用 state。setRunning(true) 让 React 安排重新渲染，按钮才能禁用。controlsRef 保存当前可调用的 start/stop/focus，修改 current 不会触发渲染；它让后续渲染中的按钮继续找到同一组控制方法。

实例 term 在本课存放于 Effect 闭包，不是所有实例都必须直接放 ref。Effect 内的 timer 也能跨组件重渲染继续存在，因为这些回调仍持有该次 Effect 的闭包。判断 timer !== null 可以立即阻止重复启动，不必等按钮更新。

### 5. 为什么观察容器

展开侧栏时，整个窗口可以保持原宽度，但终端可用宽度已经减少。window.resize 不一定触发，所以观察 host 的尺寸。FitAddon 根据容器和字体计算可容纳的字符列数、行数，然后调整 xterm。下一课还要将 cols/rows 发给 PTY；页面排版变化不会自动通知后台 shell。

### 6. 为什么关闭时需要清理

DOM 被移除只表示屏幕上不再显示，计时器和订阅不会因此全部自动取消。本课逐项清除 timer、动画帧、ResizeObserver、输入订阅，再 dispose Terminal（连同已加载 addon），并清空 controlsRef。disposed 标记阻止已经排队的回调或字体 Promise 再访问旧实例。否则关闭重开后可能留有旧输出、重复监听或内存占用。

### 7. StrictMode 在检查什么

开发模式额外执行一次 setup → cleanup → setup，检查初始化和清理能否配对。理想结果是第二次 setup 之后只剩一份有效终端和订阅。移除 StrictMode 可能暂时隐藏重复监听，但用户真正关闭重开时仍会遇到同一问题。它不是生产环境每次渲染都创建两个终端。

### 8. Ctrl+C 和会话切换

本课按 Ctrl+C 得到字符 \x03，代码手动调用 stop 清除计时器，没有系统进程被终止。真实终端会把输入传给 PTY/控制台和前台程序处理，通常用于中断当前命令，不等于关闭整个 PowerShell，也不保证所有程序都按同样方式响应。

App 中 TerminalPanel 与 ChatWorkspace 是同级组件。切换会话不会把 terminalOpen 变成 false，也没有改变 TerminalPanel 的 key 或位置，因此通常只是重渲染，终端不会卸载。关闭面板才会让条件渲染移除它，并触发清理；再次打开创建新实例。
