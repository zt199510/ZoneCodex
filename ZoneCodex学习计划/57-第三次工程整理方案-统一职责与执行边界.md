## 2. 整理目标与保持条件

### 整理目标

- 应用入口负责启动和组装，业务接口、运行流程和执行细节有明确归属。
- 会话数据保持唯一状态源，标题、任务恢复、修改审查和消息展示各自承担完整职责。
- 附件快照授权、工作区授权、默认目录、权限设置和一次批准分别有明确拥有者。
- 两条 AI 命令路径共用实际进程底层，为第45课的 Windows 沙箱提供一个接入位置。
- preload 按实际业务能力组装同一个 `window.api`，底层模型与文件模块不再借用 Agent 循环实现中的错误或传输定义。
- 样式和界面组件按当前功能归组；旧文件迁移与实际验收可以对照追踪。

## 6. 关键设计要求

### 唯一状态源与异步身份

会话库继续由 `useConversation` 持有。标题和审查模块通过明确回调请求更新会话，任务对账与实时事件使用同一合并规则，状态不会复制到新的全局容器。回调始终更新发起时的会话、请求和任务，不能读取回调到达时的活动会话来决定归属。

草稿缓存和贴底滚动属于页面运行时；标题代次、重命名保护及取消句柄属于标题生命周期。拆分时记录所有清理触发点，尤其会话切换、归档、清空、刷新、关闭和卸载。

### 运行生命周期与审批

整理前列出页面刷新、渲染进程退出、窗口关闭、授权撤销、停止和超时各自需要清理的资源。`app-runtime` 负责长期跨模块接线，运行任务仍负责自身计时器和临时监听解绑；重复通知应幂等，不能漏掉原来的中止或先发布假的终态。

审批协调接受已验证的用户任务、固定操作、权限当前性检查以及任务状态/计时回调。评估和人工等待继续使用同一任务；恢复执行计时、拒绝、异常和取消都由原运行流程收尾。批准之后仍复核来源、权限、路径、文件/目录基线，一次批准不变成持久 grant。

### 共用命令执行底层

共用底层接收已经过业务批准及复核的程序、参数、目录、环境、限制、取消信号和输出回调。旧 npm 入口继续管理一次性准备、确认和事件适配，通用工具继续管理工具回执及副作用记录。手动 PTY 不进入该底层。

底层通过回调保留通用命令启动前、每250毫秒及进程关闭时的权限复核，以及调用 `spawn` 前的副作用标记；标记后启动失败仍保持保守的重试保护。旧 npm 按原入口的检查触发点适配，两条路径的运行中政策不因提取而合并。

| 参数或行为   | 通用命令当前值                                | 旧 npm 当前值                           | 本次处理                   |
| ------------ | --------------------------------------------- | --------------------------------------- | -------------------------- |
| 执行超时     | 30秒                                          | 60秒                                    | 分别传入，不统一数值       |
| 输出上限     | 1800字节                                      | 256 KiB                                 | 分别保留截断和展示行为     |
| 环境变量     | 现有白名单筛选                                | 当前进程环境继承                        | 原样适配，政策调整另行安排 |
| 输出/结果    | 工具结果字符串                                | 分段执行事件及回执                      | 入口适配，协议保持         |
| 启动前置条件 | 运行上下文、当前操作批准、来源/权限及路径复核 | 提案、一次准备/确认、目录配置与权限复核 | 保留各自完整条件和次序     |

提取进程代码时先核对正常退出、启动失败、输出截断、取消、超时及未知结果的差异；底层不能凭统一接口宣称这些语义等价。第45课再接入真实隔离后端，本次仍明确标注命令没有 OS 沙箱。
