# 第二十二至三十三课小结

整理日期：2026-09-26。用户反馈已完成第 22–33 课。本小结把课程实现、自动检查、用户反馈和桌面验收分开记录；实现存在不等于每条桌面链路都已观察，也不等于相关原理已经熟练掌握。

## 1. 这十二课完成了什么进阶？

阶段主题从“只读项目工具”推进到“受控修改、受控命令和任务生命周期”。应用现在可以让模型提出结构化建议或固定命令，由主进程检查来源、范围和授权，再由用户明确确认；任务记录可以保存展示结果，但运行时句柄和短期授权仍留在主进程。

| 课程 | 核心内容 | 对应用的作用 |
|---|---|---|
| 22：修改建议与差异审查 | 单文件只读预览、候选内容、IPC 归属、差异展示 | 先审查修改内容，不直接写盘 |
| 23：模型修改建议与聊天关联 | 结构化建议工具、完整读取检查、ToolRun 与助手消息关联 | 模型建议可以追溯到具体对话和工具调用 |
| 24：写入前确认与磁盘冲突检查 | 原始字节基线、编码/换行、磁盘复核、短期准备记录 | 写入前明确看到差异和冲突边界 |
| 25：确认提交与备份恢复 | 一次性领取、精确备份、暂存替换、未知结果和旧授权失效 | 在受控副本上完成一次真实文件提交 |
| 26：单条命令提案与执行前审查 | 固定 `npm_typecheck` 提案、参数校验、只读审查面板 | 模型可以提出命令，但提案本身不会启动进程 |
| 27：工作目录授权与命令执行准备 | 目录选择、有限配置读取、脚本审查、短期准备记录 | 把工作目录授权和命令执行分开 |
| 28：明确确认与单条命令受控执行 | 一次性确认、Windows 启动、输出、取消、超时、清理 | 完成固定 `npm run typecheck` 的最小执行闭环 |
| 29：真实 Agent 工具调用与权限闭环 | 真实模型提案、工具参数复核、提案关联、复用执行器 | 验证模型提出请求不等于获得执行权限 |
| 30：权限策略抽象与执行边界 | 提案、批准策略、范围检查、一次性许可、执行器分层 | 从单个命令特例抽象出可复用权限边界 |
| 31：工作区、项目指令与任务状态 | 工作区、受限 `AGENTS.md` 快照、请求状态和权限状态分离 | 建立项目上下文和授权生命周期基础 |
| 32：任务生命周期与可恢复后台执行 | `TaskRecord`、主进程任务注册表、任务列表/取消/状态事件 | 刷新后恢复任务展示，不恢复旧运行时许可 |
| 33：任务状态收敛与生命周期闭环验收 | 窗口归属统一、合法状态转换、收尾、历史、容量策略 | 收口第 32 课的状态源和记录边界 |

## 2. 已验证

### 协议、类型和构建

- `TaskRecord` 只保存任务 ID、请求/会话归属、种类、状态、时间、结果和错误；运行时句柄、进程引用、`AbortController`、grant、`preparedId` 和 `confirmationId` 不进入会话记录。
- 主进程任务注册表统一使用 `BrowserWindow.id`，并集中限制状态转换；终态不可回退，重复收尾和迟到事件不会重新打开任务。
- `task:list`、`task:cancel`、`task:state` 已接入 preload 和共享 API。renderer 只展示主进程事件，不自行把任务推进到完成或取消。
- 任务记录数量上限统一使用 `maxTaskRecords`，主进程保留策略与会话解析策略一致，超限时仍可保存和重新加载。
- `npm run typecheck`、`npm run build`、`npm run lint -- --quiet`、第 32 课和第 33 课离线回归，以及工作区离线检查均已通过。

### 文件修改和命令授权

- 第 22–25 课的文件链路已覆盖预览、候选审查、磁盘冲突检查、明确提交、原始字节备份、失败分类和旧授权失效。
- 提交前取消不会写入目标；替换开始后取消会继续收尾。提交回执丢失时显示未知结果，不把结果误报为未写入，也不提供无条件重试。
- 第 26–28 课保持固定模板边界：模型不能传入任意命令、路径或环境变量；准备记录不是执行许可；执行前由主进程重新核对并一次性领取许可。
- 第 31–33 课保持工作区、文件快照、任务记录和短期执行许可分离；撤销工作区会取消关联任务并释放运行时引用。

### 失败、停止和消息操作

- 第一轮失败或停止后，用户消息和助手消息保留在当前会话中并显示终态；下一轮仍在同一会话内，但创建新的 `taskId` 和 `requestId`。
- 模型上下文只收集用户和助手均为 `complete` 的问答，因此失败、停止和空回复不会作为有效助手内容发送给下一轮。
- 失败或停止的助手消息提供“重新生成”，使用原用户内容创建新任务，旧失败记录不被覆盖。
- 只有当前会话最后一条用户消息提供“编辑”。编辑在原消息气泡内进行，发送后截断该消息之后的旧回答和工具记录，再按截断后的成功历史生成新的分支。
- 消息操作区支持复制；复制成功后短暂显示“已复制”。生成期间不显示编辑入口，避免编辑与运行中的请求并行。

## 4. 待验证

- 当前环境的完整 Electron 桌面步骤曾因 GPU 子进程不可用退出。需要在可用桌面环境逐项观察正常完成、取消、超时、启动失败、等待批准、刷新、切换会话、撤销工作区和窗口销毁。
- 第 29 课仍需真实模型桌面验收：模型实际提出提案、确认前进程数为零、确认后只执行一次固定命令，以及失败、取消、超时和刷新后的授权清理。
- 第 31 课的根目录选择器、真实 `AGENTS.md` UI 读取链和刷新后的重新授权仍需收尾观察；现有离线协议通过不等于完整项目工作区 UI 已验收。
- 第 25 课保留外部并发窗口、特殊文件属性、断电和跨崩溃恢复等边界；普通文件的隔离练习通过不代表通用安全文件编辑器已完成。
- 当前未持久化跨刷新聊天任务的原始请求来源，因此不显示无法安全重建来源的聊天重试按钮；需要新的来源协议后再评估。
- 上述失败后续聊、重新生成、最后一条消息编辑分支和复制反馈已完成类型及相关 lint 检查；真实 Electron 中的视觉位置、剪贴板权限和编辑后完整 UI 链路仍应在桌面验收时观察。

## 5. 明确不支持

- 不支持跨重启恢复 Node 进程、PTY、`AbortController`、旧 grant、`preparedId` 或 `confirmationId`；刷新恢复的是任务展示和可持久化结果。
- 不支持并发 Agent、自动批准、永久批准、命令队列、任意命令、任意环境变量或把模型输出直接送入终端。
- 不支持 SSH、MCP、远程执行、完整 Codex 权限模式、SQLite 或全局状态库；这些属于后续安排或当前范围之外。
- 不把固定 `npm run typecheck` 的执行闭环宣传为通用命令执行器，也不把文件附件路径推导为命令工作目录。
- 命令执行目前复用等待批准的 Agent 任务记录；若以后需要独立的 `command` 任务类型，应单独设计协议和历史边界。

## 6. 复习时优先掌握的工程能力

### 让权限沿着明确的链路收敛

模型输出只是结构化请求。主进程要再次检查工具参数、窗口、会话、快照、工作区和有效期；用户确认只产生一次性许可，执行器领取后立即失效。

### 让异步结果带着身份回来

`taskId` 表示一次任务记录，`requestId` 表示一次请求，`conversationId` 表示归属会话。回调必须按这些身份更新原对象，不能读取回调到达时页面当前选中的会话。

### 把展示数据和运行时资源分开

会话可以恢复状态、时间、结果和错误摘要；进程、计时器、监听器、快照授权和取消控制器必须由主进程创建和清理。刷新后先用 `task:list` 对账，找不到运行时句柄的活动记录才显示为 `interrupted`。

### 把取消当作收尾请求

取消按钮表示请求停止。底层工作停止并完成清理后，主进程才发布 `cancelled` 或 `timed_out`；页面不能先写一个假的终态。

### 把重试当作新任务

重新发起要使用新的 `taskId`、`requestId` 和当前授权，旧任务保留其失败、取消或中断记录。这样才能过滤迟到事件，也不会让旧许可重新生效。
