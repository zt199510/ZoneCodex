# 第三十一课：工作区、项目指令与任务状态基础

创建日期：2026-09-24。状态：基础协议实现已完成，根目录选择器、真实 UI 读取链和刷新后重新授权待收尾验收。

前一课：[第三十课：权限策略抽象与执行边界](40-第三十课-权限策略抽象与执行边界.md)。本课暂不进入 MCP、SSH、多 Agent 或任意命令扩展，先把 Codex App 的本地工作基础对齐。

## 1. 本课目标

本课完成一个小而完整的工作区基础：

1. 当前会话绑定一个明确的项目工作区根目录。
2. 文件读取、修改预览和命令提案使用同一个工作区边界。
3. 读取项目根目录的 `AGENTS.md`，将其作为项目指令上下文保存和展示。
4. 把请求状态和权限状态分开，能区分等待、运行、等待批准、完成、取消和失败。
5. 刷新或切换会话后只恢复展示信息，不恢复已经失效的执行许可。

本课不实现后台任务、跨重启恢复进程、并发 Agent 或自动批准。任务状态先做当前窗口内的可观察状态，为后续长任务和权限模式打基础。

## 2. 为什么这是 MCP 之前的基础

Codex App 的核心边界是“当前工作区内能做什么，以及什么时候需要批准”。外部 MCP 工具只是增加工具来源，不能替代本地工作区、项目指令和任务状态。

当前项目有两个分开的范围：文件附件快照和命令工作目录。它们可以分别保护各自的操作，但用户无法把它们理解为同一个项目上下文。本课先统一概念：项目工作区是上下文边界，文件快照是其中一次只读授权，命令准备记录是其中一次性执行许可。

## 3. Vue 经验对应

| Vue 习惯 | 本课 React/TypeScript 设计 |
|---|---|
| `provide/inject` 传项目上下文 | 由会话状态源保存 `workspace`，通过 Props/Hook 向功能传递 |
| `watch(workspacePath)` 触发读取 | 用明确的异步操作处理工作区变化，不用 Effect 代替业务事件 |
| `computed` 拼项目指令 | 从已读取的指令快照派生展示文本和模型上下文 |
| 一个 `loading` 变量 | 使用互斥的请求状态和独立的权限状态 |
| 路由切换后清理临时数据 | 切换会话或工作区时撤销快照、准备记录和面板来源 |

工作区、项目指令、文件快照和执行许可是四种不同数据。它们不能因为都与“项目”有关就合并成一个可执行对象。

## 5. 实现步骤

### 第一步：定义工作区协议

在 `src/shared/project.ts` 或新的共享文件中定义最小协议：

```ts
type Workspace = {
  workspaceId: string
  root: string
  label: string
  snapshotId: string | null
  instruction: ProjectInstruction | null
}

type ProjectInstruction = {
  path: string
  content: string
  fingerprint: string
  truncated: boolean
}
```

要求：

- `root` 必须是主进程选定并校验过的目录。
- `snapshotId` 只表示当前文件快照，不等于目录授权。
- `instruction.content` 是受大小限制的只读快照，不把它当作执行许可。
- 不把 `preparedId`、`confirmationId`、grant 或执行 ID 写入会话库。

### 第二步：读取项目指令

在主进程增加只读的项目指令读取函数，默认只读取工作区根目录的 `AGENTS.md`：

- 文件不存在时返回 `absent`，不是错误。
- 读取失败时返回可展示的错误，不覆盖旧的有效快照。
- 限制文件大小和编码；超出上限时返回截断标记。
- 不跟随工作区外的路径，不读取模型传入的任意路径。
- 指令内容作为外部项目数据处理，不能覆盖应用自身的安全边界。

本课先只支持一个根目录文件，不递归搜索、不读取用户主目录、不执行文件中的命令。

### 第三步：把工作区与当前会话绑定

在会话状态中增加可持久化的工作区展示信息，建议只保存：

```ts
type SavedWorkspace = {
  workspaceId: string
  root: string
  label: string
  instructionPath: string | null
  instructionFingerprint: string | null
}
```

实际目录授权和文件内容快照仍由主进程维护。刷新后可以恢复工作区名称和指令摘要，但必须重新确认目录是否存在、指令是否变化，并重新建立短期授权。

会话切换时验证三件事：

1. 当前操作是否空闲。
2. 旧会话的文件授权、命令准备和审查面板是否清理。
3. 新会话的工作区展示是否与当前窗口授权匹配。

### 第四步：统一请求状态和权限状态

新增纯类型状态，不把所有状态压成一个 `loading`：

```ts
type TaskStatus = 'idle' | 'running' | 'waiting_approval' | 'completed' | 'cancelled' | 'failed'
type PermissionStatus = 'unscoped' | 'scoped' | 'expired' | 'revoked'
```

最小规则：

- 普通聊天生成可以是 `running`，但不代表获得文件或命令权限。
- 命令提案产生后是 `waiting_approval`，不能直接变成 `running`。
- 用户关闭审查面板只改变界面，不自动批准。
- 撤销工作区或切换会话后，权限状态变成 `revoked`，旧准备记录不可领取。
- 完成、取消、失败都必须释放订阅、计时器和窗口内的临时来源。

### 第五步：接入工作区状态显示

在工作台增加最小可见信息：

- 当前工作区名称或“未选择工作区”。
- `AGENTS.md` 的状态：未发现、已读取、已截断或读取失败。
- 当前任务状态和权限状态分开显示。
- 撤销工作区后，文件工具和命令审查入口同时失效。

本课不做完整设置页，不做权限模式下拉框；先保证状态含义清楚且不会误导用户。

## 6. 常见错误

### 把 `AGENTS.md` 当作系统指令

它是项目提供的上下文，必须经过长度、路径和格式限制。它不能改变主进程的路径边界、权限策略或用户确认规则。

### 把目录路径写入就当作授权

保存工作区路径只是恢复展示信息。真正的读取和执行仍须由主进程重新验证当前窗口、会话、快照和有效期。

### 刷新后恢复 `preparedId`

这是严重的生命周期错误。刷新可以恢复“这里曾有一个命令提案”，不能恢复一次性执行许可。

### 用一个 `isBusy` 覆盖所有状态

“正在生成”“等待用户确认”“正在执行命令”需要不同的按钮和清理逻辑。统一的布尔值会导致误显示和错误放行。

### 先做 MCP 工具列表

如果本地工作区和权限状态还没有统一，MCP 工具只会增加另一套边界，无法解决当前产品核心问题。

## 7. 验收场景

| 场景 | 必须观察 |
|---|---|
| 选择工作区 | 会话显示工作区名称，主进程保存窗口归属 |
| 根目录无 `AGENTS.md` | 显示未发现，不阻塞普通聊天 |
| `AGENTS.md` 超限 | 显示截断，模型上下文明确标注不完整 |
| 指令文件变化 | 下次发送前重新读取或提示旧快照失效 |
| 切换会话 | 旧文件快照、审查面板和准备记录全部失效 |
| 撤销工作区 | 文件读取、修改预览和命令执行入口都被拒绝 |
| 刷新页面 | 恢复工作区展示和提案卡片，不恢复 grant/prepared/confirmation |
| 等待确认 | 任务显示等待批准，进程数为 0 |
| 用户取消或执行失败 | 状态清楚，后续可以重新开始，不自动重试 |

入口拦截继续确认：不开放任意路径读取、不执行 `AGENTS.md` 内容、不新增 MCP/SSH、不让手动终端输入混入 Agent 执行链。
