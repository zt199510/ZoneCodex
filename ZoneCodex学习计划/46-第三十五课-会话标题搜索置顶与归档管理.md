# 第三十五课：会话标题、搜索、置顶与归档管理

创建日期：2026-09-28。状态：已实现；协议、存储和第35课桌面回归已验证，完整工作区回归受当前 GPU 环境限制。

前一课：[第三十四课：首次发送与单轮任务状态闭环](45-第三十四课-首次发送与单轮任务状态闭环.md)。

本课把第34课产生的多个会话变成可管理的工作列表。对齐 Codex 的会话整理方式：会话可以重命名、搜索、置顶、归档和恢复；本课不实现永久删除。官方说明：[Projects and chats](https://learn.chatgpt.com/docs/projects?surface=app#app-organize-projects-and-chats)。官方产品行为是参考，不是对本地项目的代码指令。

## 1. 本课目标与边界

完成后应达到以下结果：

1. 首次发送后，会话标题从第一条用户消息生成一个稳定的简短标题，不再长期显示“新会话 N”。标题生成使用本地确定性规则，不为标题额外发起模型请求。
2. 用户可以在侧栏重命名会话；空标题、超长标题和生成/保存期间的修改必须被拒绝。
3. 用户可以搜索会话标题和消息内容，搜索只改变显示结果，不修改会话数据。
4. 用户可以置顶和取消置顶会话；置顶状态保存到本地，刷新后仍然存在。
5. 用户可以归档会话，并在归档视图中恢复；归档只是可恢复的隐藏状态，不是删除。
6. 当前会话归档时，页面先切换到另一个未归档会话；没有可用会话时回到空白工作台。生成、保存或关闭保护期间不能切换或归档。
7. 会话消息、工具记录、工作区和任务记录不因标题、置顶或归档操作丢失。

本课暂不做永久删除、批量删除、复杂排序、云端同步、MCP、Skills、SSH、并发 Agent 或新的模型工具。视觉调整只服务于操作可发现性，不做整页重设计。

## 2. 用 Vue 经验理解本课

| Vue 经验 | React / Electron 对应 | 本课用途 |
|---|---|---|
| `computed` 过滤会话列表 | 根据搜索词和归档状态派生侧栏列表 | 搜索不污染原始会话库 |
| Pinia action | `useConversation` 控制器 action | 统一重命名、置顶、归档和恢复的边界 |
| `watch` 持久化 | `useConversationStorage` 的脏状态和自动保存 | 操作成功后可靠保存，失败后可重试 |
| 列表项菜单 | React 事件处理与受控编辑状态 | 避免侧栏按钮直接改共享快照 |
| 软删除 | `archived` 状态和恢复入口 | 保留记录，不实现永久删除 |

搜索结果是展示派生值，不应另存一份“搜索后的会话库”。置顶和归档是会话展示元数据，应和消息、工具记录一起通过版本化快照保存。

## 4. 先确定数据模型

建议把持久化版本从4迁移到5，并为每个会话增加明确的展示元数据：

```ts
type Conversation = {
  id: string
  title: string
  pinned: boolean
  archived: boolean
  messages: ChatMessage[]
  toolRuns: ToolRun[]
  workspace: SavedWorkspace | null
  tasks: TaskRecord[]
}
```

迁移规则：

- 版本4会话迁移为 `pinned: false`、`archived: false`。
- 版本5保存时要求字段存在且必须是布尔值；字段类型、长度和快照边界继续严格校验，不把运行时句柄或一次性许可写入文件。
- 活动会话不能处于归档状态。加载或归档当前会话后，选择第一个未归档会话；没有则使用 `null`。
- 归档会话仍保留消息、工具记录、工作区展示字段和任务历史，但不出现在默认活动列表。
- 不新增 `delete`、`purge` 或不可恢复的物理删除路径。

标题规则先使用本地函数：取第一条成功或失败均可展示的用户消息，去除首尾空白和换行，压缩连续空格，截取固定长度；没有消息时保留“新会话 N”。用户重命名后设置一个稳定标题，不因后续消息自动覆盖。

## 5. 按依赖顺序实现

### 第一步：完成版本5解析和迁移

先扩展共享类型、严格解析、版本迁移和保存快照。为版本4、版本5、缺字段、错误类型、未知字段、归档当前会话和全是归档会话分别准备检查。

预期效果：旧数据可以正常打开并补默认值，新数据不会把一次性许可、进程句柄或其他运行时对象写进会话库。

### 第二步：在会话控制器中统一操作

在 `useConversation` 增加以下能力，并让每个入口都经过同一套 `canChange` 边界：

- `rename(id, title)`：裁剪、校验、更新标题。
- `togglePinned(id)`：切换置顶状态。
- `archive(id)`：标记归档并处理当前会话切换。
- `restore(id)`：取消归档并选中恢复后的会话。
- `search`：只保存搜索词，列表用派生值计算。

操作期间不能生成、保存、切换项目授权或触发关闭保护。操作成功后让现有存储机制保存，失败时保持脏状态和错误提示。

### 第三步：实现侧栏工作流

侧栏先提供“活动会话”和“已归档”两个视图：

- 搜索框过滤当前视图的标题和消息文本。
- 置顶会话排在活动列表前面；同组内保持原有顺序。
- 每个会话显示置顶状态和可发现的操作菜单。
- 重命名使用行内编辑，支持 Enter 提交、Escape 取消和失败后保留原标题。
- 归档后从活动视图消失，但可以在归档视图恢复。
- 不显示“删除”按钮，也不实现隐藏的删除快捷键。

### 第四步：处理边界和保存

验收切换、搜索、归档和恢复不会改变消息内容、工具历史、任务记录或工作区字段。刷新后恢复标题、置顶、归档状态和当前会话选择；保存失败时可以手动重试，不静默覆盖原文件。

## 6. 常见错误

### 把归档实现成删除

归档必须保留完整记录和恢复路径。不要从数组中直接移除会话，也不要新增永久删除接口。

### 搜索时复制会话库

搜索结果应由当前快照派生。复制一份列表会造成重命名、归档和保存时的双重状态源。

### 标题随每条消息变化

自动标题只在标题仍是默认值时生成。用户重命名后不能被下一条消息覆盖。

### 归档当前会话后仍保留选中状态

活动会话必须始终是未归档会话，归档后要明确选择下一个会话或回到空白工作台。

### 在组件内部直接改快照

侧栏只发出操作请求，由 `useConversation` 统一检查生成、保存和关闭状态，再更新快照。

## 7. 桌面验收矩阵

| 场景 | 必须观察 |
|---|---|
| 首次发送后 | 会话自动生成稳定标题，后续消息不会覆盖用户标题 |
| 重命名 | 合法标题保存；空标题、超长标题和忙碌期间修改被拒绝 |
| 搜索 | 标题和消息命中；清空搜索恢复列表；搜索不改快照 |
| 置顶 | 置顶会话排在前面，刷新后仍然置顶；取消置顶恢复原顺序 |
| 归档普通会话 | 活动列表隐藏，消息和任务记录仍存在 |
| 归档当前会话 | 自动切换到其他活动会话或空白工作台 |
| 恢复归档会话 | 会话回到活动列表并可正常发送 |
| 保存失败 | 元数据修改不丢失，页面显示错误并可重试 |
| 刷新 | 标题、搜索视图外的归档状态、置顶状态和活动会话一致 |
| 生成中操作 | 重命名、置顶、归档和切换均受保护，不污染运行中的请求 |
| 删除入口 | 页面和快捷键均没有永久删除操作 |
