# 第五课：真实模型请求与异步状态

## 1. 目标与前置条件

把 App 中的“模拟回复”替换为真实模型回复：发送文字 → 显示等待状态 → 收到完整回复；失败时显示可理解的提示，并允许再次发送。

第四课用户已确认没问题；本次核对目录选择代码，并执行 npm run typecheck，Node 和 Web 两组检查均通过。选择、取消和错误交互结果来自用户反馈，本次未重新操作窗口。

本课沿用 invoke/handle，只做单轮、非流式文本问答。页面可以展示多条记录，但每次请求只发送当前这一句话，模型不会自动记住之前的话。选中的工作目录仍只是路径，不会上传目录或文件。

你指定模型 gpt-5.5、wire_api = "responses"，base_url 为 https://www.gmapikey.com。本课因此使用 Responses 格式。配置中的 OpenAI 是提供者名称，但实际请求发往这个第三方域名；官方文档只能证明标准协议，不能证明该网关的模型可用性或兼容性。本次没有调用该网关。

你在反馈中贴出的密钥应先在服务商后台撤销并更换；文档不保存该密钥。新密钥只在本地填写。

本课不安装新依赖，使用当前 Electron 主进程内置的 fetch。

## 2. 用 Vue 经验理解

Vue 中常见的 loading.value = true，在 React 中对应 setIsSending(true)。两者都用于表达等待状态，但 React 的状态更新会安排下一次渲染，不会立即改变当前函数中的变量。

因此本课分两件事：isSending 控制界面；useRef 保存同步的“请求已经开始”标记，避免同一轮渲染内重复进入。

发送由用户操作触发，直接写事件处理函数，不需要用 useEffect 监听 messages 后再请求，否则容易重复发送。

```text
ChatInput 普通回调
  → App.handleSend
  → window.api.askModel(content)
  → preload.invoke('chat:ask', content)
  → main 校验输入并发 HTTP 请求
  → 模型服务返回 JSON
  → main 提取文字，返回业务结果
  → preload 校验结果
  → App 追加助手消息，恢复输入
```

复习：send 不直接返回处理结果；invoke 返回 Promise。unknown 表示类型未知；as 断言不会转换或验证实际数据。

## 5. 共享接口：成功与失败都说清楚

将 src/shared/api.ts 改成：

```ts
export type ModelReply =
  | { ok: true; content: string }
  | { ok: false; error: string }

export interface AppAPI {
  selectFolder: () => Promise<string | null>
  askModel: (content: string) => Promise<ModelReply>
}
```

这里用可辨识联合类型：先判断 reply.ok，TypeScript 才知道应该读取 content 还是 error。

目录选择的 null 是正常取消。模型请求的失败需要说明原因，因此用 { ok: false, error }。这不保证 Promise 永远不拒绝：IPC 中断、返回值格式不正确等问题仍可能抛异常，React 仍要有 catch。

## 6. 主进程：一次完整 HTTP 请求

新建 src/main/model.ts：

```ts
import type { ModelReply } from '../shared/api'

function isRecord(value: unknown): value is Record<string, unknown> {
  return typeof value === 'object' && value !== null && !Array.isArray(value)
}

function readReply(data: unknown): string {
  if (!isRecord(data) || !Array.isArray(data.output)) {
    throw new Error('响应格式不正确')
  }
  const texts: string[] = []
  for (const item of data.output) {
    if (!isRecord(item)) throw new Error('输出项格式不正确')
    if (item.type !== 'message') continue
    if (!Array.isArray(item.content)) throw new Error('消息内容格式不正确')
    for (const part of item.content) {
      if (!isRecord(part)) throw new Error('内容项格式不正确')
      if (part.type === 'refusal') throw new Error('模型未提供文字回复')
      if (part.type === 'output_text') {
        if (typeof part.text !== 'string') throw new Error('文字格式不正确')
        texts.push(part.text)
      }
    }
  }
  const content = texts.join('\n')
  if (!content.trim()) throw new Error('响应缺少文字')
  return content
}

let busy = false

export async function askModel(input: unknown): Promise<ModelReply> {
  if (typeof input !== 'string' || !input.trim() || input.length > 4000) {
    return { ok: false, error: '请输入 1～4000 个字符。' }
  }
  if (busy) return { ok: false, error: '已有请求正在进行，请稍后重试。' }

  const endpoint = process.env.MODEL_ENDPOINT
  const model = process.env.MODEL_NAME
  const apiKey = process.env.MODEL_API_KEY
  if (!endpoint || !model || !apiKey) {
    return { ok: false, error: '请配置模型地址、模型名称和密钥，再重启调试。' }
  }
  try {
    if (new URL(endpoint).protocol !== 'https:') throw new Error('协议不支持')
  } catch {
    return { ok: false, error: '模型地址必须是有效的 HTTPS 地址。' }
  }

  busy = true
  const controller = new AbortController()
  const timer = setTimeout(() => controller.abort(), 30_000)

  try {
    const response = await fetch(endpoint, {
      method: 'POST',
      redirect: 'error',
      headers: {
        'Content-Type': 'application/json',
        Authorization: `Bearer ${apiKey}`
      },
      body: JSON.stringify({
        model,
        input: [{ role: 'user', content: input.trim() }],
        store: false,
        stream: false
      }),
      signal: controller.signal
    })

    if (!response.ok) {
      // 不把服务商原始错误体或密钥返回给页面。
      await response.body?.cancel()
      if (response.status === 401 || response.status === 403) {
        return { ok: false, error: '认证失败，请检查密钥和模型访问权限。' }
      }
      if (response.status === 429) {
        return { ok: false, error: '请求受限，请检查额度或稍后再试。' }
      }
      return { ok: false, error: `模型服务请求失败（HTTP ${response.status}）。` }
    }

    const data: unknown = await response.json()
    if (!isRecord(data) || typeof data.status !== 'string') {
      throw new Error('响应状态格式不正确')
    }
    if (data.status !== 'completed') {
      return { ok: false, error: '模型未完成回复，请稍后重试。' }
    }
    return { ok: true, content: readReply(data) }
  } catch {
    return {
      ok: false,
      error: controller.signal.aborted
        ? '请求超过 30 秒，请稍后重试。'
        : '请求失败，请检查网络、接口地址和响应格式。'
    }
  } finally {
    clearTimeout(timer)
    busy = false
  }
}
```

按顺序解释这些新概念：

1. 请求参数在进程边界写 unknown，并检查它是否是合理的字符串。前端 TypeScript 类型不能替代此检查。
2. busy 是主进程里的同步标记；当前只有一个模型请求名额。finally 在成功和失败时都释放名额和定时器。
3. fetch 第一个 await 等到响应头；response.json() 第二个 await 读取并解析响应体。30 秒定时器覆盖这两个阶段。
4. HTTP 401、429、500 通常不会让 fetch 自动抛异常，必须检查 response.ok。网络失败、JSON 解析失败才会进入 catch。
5. readReply 从 unknown 开始逐层检查，避免通过 as 假装响应正确。value is Record<string, unknown> 是类型守卫；它告诉 TypeScript，函数返回 true 后可按对象访问属性，而实际检查由函数体完成。
6. abort 中止本地等待，不保证服务商已经停止计算或不计费。这里先学习自动超时，下一课再设计用户主动停止。

Responses 的原始 JSON 使用 output 数组，里面可能先出现 reasoning，再出现 message；所以不能假设 output[0] 就是回复。代码遍历 message.content 中的 output_text 片段并拼接。SDK 示例中的便捷属性 output_text 不应被当成原始 HTTP JSON 必有字段。

本课只把 completed 且包含非空文字的结果视为成功；incomplete、failed 等状态显示未完成提示，拒绝回答或没有文字则进入错误分支。HTTP 200 不一定代表模型已完整回答。暂不配置工具，也不实现工具调用循环。

30 秒只是本课练习超时值，不代表 gpt-5.5 必定在 30 秒内完成；先用短问题，若网关正常但经常超时，可有意识地调整该值并同步调整提示。

## 7. preload：增加方法并验证返回值

在现有 const api: AppAPI 对象中，保留 selectFolder，在它后面加逗号，再添加属性：

```ts
askModel: async (content) => {
  const result: unknown = await ipcRenderer.invoke('chat:ask', content)
  if (typeof result !== 'object' || result === null) {
    throw new Error('模型请求结果格式不正确')
  }
  if ('ok' in result && result.ok === true &&
      'content' in result && typeof result.content === 'string') {
    return { ok: true, content: result.content }
  }
  if ('ok' in result && result.ok === false &&
      'error' in result && typeof result.error === 'string') {
    return { ok: false, error: result.error }
  }
  throw new Error('模型请求结果格式不正确')
}
```

预期：App 中输入 window.api. 时出现 askModel，返回类型是 Promise<ModelReply>。不再调用一次 exposeInMainWorld，现有 api 暴露逻辑会包含新增的方法。

## 9. App：替换模拟回复

将 React 导入改成：

```tsx
import { useRef, useState } from 'react'
```

在 App 组件已有状态旁边添加：

```tsx
const [isSending, setIsSending] = useState(false)
const [chatError, setChatError] = useState<string | null>(null)
const sendingRef = useRef(false)
```

用下面的函数替换整个原 handleSend，包括删除原来的模拟 assistantMessage：

```tsx
async function handleSend(rawContent: string): Promise<void> {
  const content = rawContent.trim()
  if (!content || sendingRef.current) return
  if (content.length > 4000) {
    setChatError('请输入不超过 4000 个字符的消息。')
    return
  }

  sendingRef.current = true
  setIsSending(true)
  setChatError(null)
  const userMessage: Message = {
    id: crypto.randomUUID(), role: 'user', content
  }
  setMessages((previous) => [...previous, userMessage])

  try {
    const reply = await window.api.askModel(content)
    if (!reply.ok) {
      setChatError(reply.error)
      return
    }
    const assistantMessage: Message = {
      id: crypto.randomUUID(), role: 'assistant', content: reply.content
    }
    setMessages((previous) => [...previous, assistantMessage])
  } catch {
    setChatError('应用通信失败，请重启应用后重试。')
  } finally {
    sendingRef.current = false
    setIsSending(false)
  }
}
```

将页面的“本课使用模拟回复，没有连接模型。”替换为“单轮模型问答：每次只发送当前消息。”

在 MessageList 后添加：

```tsx
{isSending && <p role="status">正在等待模型回复…</p>}
{chatError && <p role="alert">{chatError}</p>}
```

现有 showInput 卸载实验可以保留，将 ChatInput 那一行改成：

```tsx
{showInput && (
  <ChatInput
    disabled={isSending}
    onSend={(content) => { void handleSend(content) }}
  />
)}
```

此时请求状态属于 App，切换输入框不会让请求状态重置。useRef 的 current 改变不会触发界面渲染，所以显示等待仍需要 useState。

失败结果中的 return 仍然会执行 finally。void 表示调用方不使用 Promise，不是处理异常；异步请求错误在 handleSend 的 try/catch 中处理。

## 10. 重启、检查与实验

执行 npm run typecheck，然后停止 Debug All，再 F5 启动完整应用。只热更新 React 不能保证 main、preload 和环境配置已更新。

先验证本地错误，再进行少量真实请求。不要把实际网络请求放进自动重复运行的测试中。

| 实验 | 操作 | 预期 |
|---|---|---|
| 未配置 | 暂时移除 MODEL_NAME，重新 F5 | 显示配置提示，输入恢复可用；随后恢复配置 |
| 正常请求 | 发送“只回复：你好” | 先显示用户消息和等待，随后追加一条真实助手回复 |
| 重复提交 | 等待时连续按 Enter 或点击发送 | 正常界面只发起一次请求 |
| 再次发送 | 上一条结束后提交新问题 | 能发起新请求，旧错误提示被清空 |
| 单轮边界 | 第一条告知昵称，第二条询问昵称 | 不能依赖它记住前文；检查请求体只有当前消息 |
| 目录功能 | 再次选择目录或取消 | 第四课功能仍正常 |

下面的错误实验不需要真实密钥，也不会连接服务商：在 model.ts 的 try 内、const response = await fetch(...) 前，临时插入一个实验分支，每次只做一种，改动后完整重启。

模拟 HTTP 类失败（验证业务失败结果能恢复 UI）：

```ts
return { ok: false, error: '学习实验：HTTP 429' }
```

这只模拟业务结果，并没有验证真实 HTTP 状态判断。401/429 的真实分支可在后续用本地受控测试验证，不用反复消耗服务额度。

模拟超时取消路径：

```ts
await new Promise<void>((_resolve, reject) => {
  controller.signal.addEventListener('abort', () => reject(new Error('实验超时')), {
    once: true
  })
})
```

等待 30 秒应出现超时提示并恢复输入，且不会走到 fetch。这验证定时器 → abort → catch → finally；真实网络超时尚需独立验证。

模拟响应格式错误：

```ts
readReply({ output: [] })
```

应显示请求失败提示并恢复输入。完成后删除所有实验行，完整重启，重新通过类型检查与正常请求。不要把真实密钥、请求头或完整服务响应记录到学习文档。

建议断点：App 的 await window.api.askModel、main 的 fetch 和 response.ok、App 的 if (!reply.ok)。主进程和渲染进程是不同调用栈；断点长时间暂停也会影响你观察超时，不在暂停断点时验收耗时。
