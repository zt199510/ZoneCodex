## 阶段 0：读懂现有骨架

学习：main、preload、renderer 的职责，应用生命周期，开发和打包后的加载方式，IPC 的基本概念。

实践：运行自己的模板，点击 Send IPC，在主进程日志中找到 pong；修改根组件的一句文字。

验收：能指出两个不同的入口文件；能说明为什么界面日志与主进程日志出现的位置不同；能说明 preload 不等于独立的第三个进程。

文档：[第一课](03-第一课-入口与通信.md)。

## 阶段 1：React + TypeScript 聊天界面

学习：函数组件、TSX、Props、useState、受控输入、列表 key、不可变更新，以及事件和消息的类型定义。结合 Vue 对照学习，不把 useEffect 简单等同于 watch。

实践：拆分 ChatPage、MessageList、MessageItem、ChatInput；定义 Message 类型，包含 id、role、content；实现发送和模拟回复。

验收：空消息不可发送；连续消息不会丢失；列表 key 稳定；输入有明确类型；能解释状态为什么放在相应组件中。

暂不引入全局状态库。派生值优先直接计算，不为每个值添加 useEffect 或 useMemo。

## 阶段 2：Electron 类型化本地接口

学习：contextBridge、ipcRenderer.invoke、ipcMain.handle、返回类型、取消与异常。类型检查不能替代运行时参数校验。

实践：通过 window.api.selectFolder() 打开文件夹选择器，在界面显示结果；新增共享接口类型，并同步 preload 的 Window 声明。

验收：能处理取消选择；界面不直接访问 Node 文件 API；接口只暴露完成业务所需的能力；能画出请求与返回路径。

## 阶段 3：真实模型与流式聊天

学习：HTTP、模型消息格式、流式事件解析、AbortController、请求状态和错误处理。

实践：先接入一个模型服务；由主进程管理请求，通过明确的 IPC 接口向界面发送增量内容；实现停止生成和失败提示。

拆课安排：[第五课](09-第五课-真实模型请求与异步状态.md)先完成 gpt-5.5 Responses 非流式单轮问答、等待与错误恢复；[第六课](10-第六课-多轮上下文与清空对话.md)实现简化的多轮文本上下文、完整问答裁剪与清空对话；[第七课](11-第七课-模拟流与停止生成.md)在独立练习区实现本地模拟流、主动停止和订阅清理；之后接入真实流式输出。进入复杂推理或工具场景前，另行设计保留完整 Responses output 与 phase 的协议历史。

验收：凭据不写入源码和日志；增量片段正确拼接；停止后不再追加；重复发送策略明确；失败后界面能恢复操作。先用模拟流验证，再做少量真实调用。

真实流入门：[第八课](12-第八课-真实流式响应与网络取消.md)使用独立单轮区学习 SSE 解码、分帧、Responses 终态和网络取消；[第九课](13-第九课-正式聊天的流式消息与上下文.md)合并至正式多轮聊天，处理助手占位、停止/失败和成功问答上下文。

## 阶段 6：SSH 远程环境

实践：通过维护中的 SSH 客户端库建立远程终端，复用终端界面；随后抽象本地与远程会话的公共接口。

验收：认证失败、超时、断线均可理解；未知或变化的主机密钥得到明确处理；凭据不进源码或日志；断线后不会误显示为已连接。

没有测试主机时先完成接口与模拟测试，真实连接验收保持待完成。

## 阶段 7：MCP 与模型工具循环

第十八课最小工具循环已收到完成反馈，自测讲解已追加。[第十九课：工具循环接入正式聊天](26-第十九课-工具循环接入正式聊天.md)先统一输入框、进度与停止，并保持会话归属；后续统一流式改造使正式聊天、工具调用和附件请求共用 Responses SSE。[第二十课](27-第二十课-工具历史的保存与恢复.md)已收到完成反馈；[第二十一课：项目文件读取与搜索](28-第二十一课-项目文件读取与搜索.md)在正式聊天中学习只读快照、读取/搜索、路径边界、历史范围隔离和授权撤销，安排版本 4 迁移。之后学习差异审查、授权写入和命令执行，再扩展 MCP。下方 MCP 实践属于后续安排。

学习：MCP client/server、传输方式、工具发现、参数 schema、工具调用和返回值；区分 MCP 协议与模型自己的工具调用机制。

实践：先连接一个本地、只读的教学 MCP server，列出工具并手动调用；然后将工具描述提供给模型，接收调用请求、校验与执行，并把结果交回模型继续回答。

验收：手动调用与模型调用均能解释；超时和参数错误可恢复；工具描述作为外部数据处理；涉及文件修改或命令执行的操作有具体的用户授权边界。

## 阶段 8：打包与自动更新

学习：electron-vite 编译与 electron-builder 打包的区别、版本号、安装包、更新元数据、发布渠道和签名。

实践：先构建 Windows 安装包；再使用自己控制的测试更新源，制作两个版本验证更新。

验收：打包版能启动，资源路径有效；安装目录与用户数据目录分离；确实完成低版本到高版本更新；无更新、下载失败、重启安装的状态清楚。

当前模板的 example.com 地址是占位值，安装了 electron-updater 不代表已实现自动更新。公开发布单独安排。
