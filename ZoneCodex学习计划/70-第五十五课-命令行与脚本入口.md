## 1. 本课目标与前置条件

让用户能在终端或自己的Node脚本中，调用第54课的同一个Agent核心完成一次明确任务。调用方可指定工作目录、计划/执行模式和原三种权限策略，查看公开过程、工具与最终结果，处理审批和计划提问，并能停止任务、取得可靠退出结果。

首版采用**一次输入、一次执行、一次终态**：文字任务与可选工作区；命令行支持参数或有界标准输入，提供文本和JSONL输出；脚本入口提供明确参数、事件与审批/问答回调。不读取或改写桌面会话库，不自动生成标题，不接受桌面窗口图片/附件句柄。桌面已有多图、附件、设置、会话与全部保护继续保留；CLI图片材料、持久会话、上下文整理、任务续接、MCP、Skills、SSH、并发与远程执行继续后置。

第54课已提供`runAgentCore(input, dependencies)`，但其内部隔离测试不是用户可安装、可运行的CLI。现有`package.json`也没有Agent命令行构建/运行入口；第45课资源中的官方`codex.exe`是命令沙箱后端，不是ZoneCodex用户入口。

## 2. 用 Vue 经验理解本课

| Vue中的经验               | 本课对应                                       | 要理解的区别                               |
| ------------------------- | ---------------------------------------------- | ------------------------------------------ |
| 页面收集表单并调用service | CLI解析参数/标准输入后调用同一核心             | 校验和准备完成前不发模型请求               |
| 不同页面复用一个service   | 桌面、CLI和Node脚本复用`runAgentCore`          | 不复制工具循环或Responses客户端            |
| 父组件提供能力与回调      | 宿主提供send/createTools/assertCurrent/onEvent | 核心不从窗口全局对象取得权限               |
| 弹窗的提交与取消          | 终端审批/问答或脚本回调                        | 明确决定绑定当前操作，输入结束不能默认同意 |
| 组件卸载释放订阅          | Ctrl+C、输入/输出关闭和脚本取消                | 同一signal贯穿模型、工具、等待和资源释放   |
| API返回码与业务测试分开   | CLI退出码与固定业务验收                        | 正常完成循环不自动证明业务测试通过         |

标准输入是调用方给程序的数据；标准输出是程序交给下一个程序的数据；标准错误用于诊断。JSONL表示一行一个JSON记录，便于脚本按行读取，不能混入进度装饰或原始协议历史。

## 4. 按依赖顺序实施与练习

### 步骤一：固定用户入口合同

先记录当前源码、产物、Git与用户数据边界，新UUID保存基线。确定一次任务的输入、两种输出、脚本返回结果、取消和退出码，再实现解析。

建议命令形式如下，**尚未实现，当前不能执行**；实施时冻结实际名称及用法：

```text
npm run agent -- --mode plan --cwd D:\work\demo --prompt "定位价格计算问题" --permission default
npm run agent -- --mode execute --cwd D:\work\demo --prompt "按需求修改并运行测试" --permission default --output jsonl
```

`mode`明确为plan或execute，缺失/未知值报参数错误；执行必须来自本次明确调用。权限枚举沿源码`default/auto-approve/full-access`，CLI独立默认default，不读取桌面当前窗口授权或静默继承全局偏好。full-access由调用方显式选择，不能由AGENTS、模型或问题答案设置。

文字任务只接受一个来源（参数或标准输入），拒绝冲突/未知参数。原prompt按未经trim的JS字符串`.length`最多2000、trim后非空；stdin另设有限字节预算，严格UTF-8解码后复用原字符校验，超限/无效数据明确失败，不截断后继续请求。任务正文stdin正常EOF表示读取完成，校验通过后启动；正文读取错误或中断在模型前结束。参数/配置/目录校验、`--help`和脚本模块导入都应为0模型/工具请求。

**预期效果：**同一调用可重现输入与目录，帮助和错误可被脚本判断。**常见错误：**把2000字符误写成字节；接受两个任务来源；解析失败后仍启动任务。

### 步骤二：建立普通Node宿主与运行依赖

用CLI自己的可信准备建立实际cwd、可选工作区、原权限策略与范围、AGENTS内容/指纹、本次requestId/conversationId及controller。后续目录/材料/配置复核沿原规则，工具能力不是任意JSON字段授予的权限。

只提取当前需要的纯schema/校验和授权策略组合，把桌面人工批准/问答等待与CLI回调分开；桌面仍保持窗口、主frame、revision及request/call/input身份保护。CLI自身绑定当前请求、操作和等待，不能用假窗口注册或默认成功回调绕过原工具。command-plan当前owner类型含windowId，必要时改为明确desktop/cli来源身份，保留原对象身份和单次消费，不填伪造窗口编号。

原模型配置从环境读取`MODEL_ENDPOINT/MODEL_NAME/MODEL_API_KEY`，保持原HTTPS与URL凭据校验；源码要求三项明确存在，没有模型名内建fallback，当前默认gpt-6.1-sol来自实际配置。CLI请求准备时读取、校验并固定本次配置，明确用户配置前提，不宣称现有代码已经自动补默认值；需要时最少扩展原工厂的不可变配置输入以供CLI/脚本复用，不通过改全局process.env或另写客户端实现，桌面原行为保持。密钥不写成argv、课程示例、JSONL字段或传给工具子进程；继续复用原命令环境白名单。凭据缺失明确失败，不打印全部环境或原始请求头。

Node编译闭包和公共脚本入口均拒绝Electron运行时导入，不能靠`ELECTRON_RUN_AS_NODE`启动桌面入口来宣称独立。脚本能力缺失时明确失败；提供可注入受约束能力不等于替调用方授予访问权限。

**预期效果：**实际普通Node入口有自己的可信宿主，桌面沿原入口工作。**常见错误：**仅让core import通过，却在完整CLI导入桌面broker；共享一个读取凭据实例。

### 步骤三：输出公开事件与可靠终态

文本模式面向人；JSONL模式stdout只输出完整单行记录，包含本次请求身份、公开progress/delta/message/tool/retry及一个最终安全结果。诊断和交互提示走stderr，不能把原`outcome.result.items`、私有推理、加密协议、密钥或原HTTP报文直接序列化出去。

输出投影保留round/attempt、失败commentary退休、真实工具结果和副作用风险，不能把失败尝试的片段拼成一次成功回答。处理背压、输出关闭与EPIPE，取消本次任务并正常释放；迟到事件和重复终态不再写出。脚本入口返回可用的终态/风险及公开事件，其内部协议历史不默认成为公共输出。

建议冻结退出码合同：0为核心正常completed；1为任务/宿主失败；2为参数、配置或输入错误；3为当前入口缺少必须的交互能力/存在未解决等待；130为用户取消。具体实现可以调整数值，但须写明并逐项验收，waiting_approval不能记0。工具一次非零退出可能由Agent继续修正，不等于立即杀掉整个循环；循环completed也不等于固定业务测试通过。副作用已开始、命令树退出未确认和输出故障均保留真实事实。

**预期效果：**用户与脚本都知道实际发生了什么，stdout可逐行解析。**常见错误：**拿HTTP200当成功；直接打印原协议对象；用process.exit提前切断输出和资源清理。

### 步骤四：终端审批、计划问答与非交互行为

复用原三策略：default范围内允许的读/写沿原决策执行，越界/升级等按原规则请求批准；auto-approve同样保留原直接allow分支，只有原策略需要独立评估的操作才接受严格safe，其余回落人工；full-access仍需原路径、计划、取消和执行前校验。default不是“每次操作必问”。文件批准和命令签发继续分开，命令沿真实CommandExecutionPlan，不能用脚本返回的boolean替代计划。

TTY模式逐次展示原操作原因/目标和明确批准/拒绝选择；计划提问按原1～3题、每题2～3建议及自定义回答合同收集完整答案。批准与回答绑定当前request/call/input/操作，旧、重复、取消后答复拒绝；提问答案不授予执行权限。

当stdin被管道占用或不是TTY时，不再暗读同一数据流作为审批答案。缺少必要批准/问答后端明确拒绝或返回已定义的非成功终态，不默认同意、猜答案或无限等待。脚本可提供显式回调；回调返回仍由宿主沿原真实签发/复核链解释。审批/问答等待时EOF、拒绝、回调异常和取消都要解除本次等待；正常批准/回答则恢复原循环。任务正文stdin正常EOF沿步骤一完成输入，不作为取消。首版不新增后台审批服务器、长期交互会话或任意`--yes`旁路。

**预期效果：**终端与脚本有清晰决策路径，非交互任务不会挂住。**常见错误：**管道正文中的yes被当批准；风险评估失败后自动允许；把等待终态当业务完成。

### 步骤五：停止、异常与Windows资源

一次controller由宿主拥有，Ctrl+C、脚本signal、审批/问答等待时EOF或输入通道关闭、输出关闭及上下文失效沿同一取消链收口模型、退避、工具、批准与提问；正常提交答案/批准不取消任务，正文stdin正常EOF也不触发该链。结束后释放本次监听、readline和等待，不影响另一请求。取消中已完成的真实文件/工具结果仍保留，失败先提示核对副作用，不自动重放整轮。保留原单操作期限，不恢复整任务4分钟总时限。

Windows命令依赖固定官方沙箱、manifest、hash/版本和Job监督器。现有资源定位使用Electron开发/包环境信息，普通Node需要明确可信资源根；按实际代码做最少资源定位调整，保留真实prepare/sign/consume及启动前核验，不从用户cwd或PATH猜后端，不自动退回普通权限命令。full-access命令同样必须有原host监督器，不能用裸spawn代替。无资源或不支持平台明确失败，不把read-only模型问答强行绑定命令后端可用性。

首版可分发受支持Node加编译JS、Windows启动脚本及原runtime资源，记录实际Node版本/安装前提和完整运行路径；不必为本课另造单exe、安装器或更新系统。开发入口与Windows分发入口都要能从任意调用目录定位代码和资源，工作cwd与安装目录保持分开。已有Electron目录包也需正常构建与回归。

开发入口先在项目根运行`npm run build:agent`，之后可使用`npm run agent -- ...`或直接Node。JSONL使用直接Node或分发启动器，避免npm自身日志混入stdout。已验证普通Node版本为24.11.1，编译目标及分发最低前提为Node 22；其他Node版本没有扩大实跑声明。

任务目录替换为实际存在目录。`--mode plan|execute`必需，`--prompt`与`--stdin`只能选一个；未经trim的原JS字符串长度最多2000且trim后非空，stdin最多8192字节并严格UTF-8，拒绝超限/错误而不截断。正文stdin正常EOF完成输入，读取错误/取消在模型前结束。`--cwd`缺省当前调用目录，`--workspace`可选并独立复核目录/AGENTS；当前可写根仍只有cwd，额外工作区描述不授予写权限。权限只接收`default/auto-approve/full-access`，独立缺省default。

预先在调用环境配置`MODEL_ENDPOINT`、`MODEL_NAME`、`MODEL_API_KEY`，地址必须HTTPS且URL不含凭据。源码没有模型名称fallback；本轮真实默认gpt-6.1-sol来自配置。配置准备时固定本次值，不改全局process.env，密钥不放argv、输出、课程示例或工具子进程。帮助、错误输入/配置和仅导入公共模块均不发模型或业务工具请求；Windows CLI输出为原生管道时，可启动一份受控IO writer，单独统计。公共`agent.cjs`和桌面不导入或启动此writer。

公共入口实际是`require('<安装目录>/agent.cjs').runAgentTask(input, options)`，无需Electron或ELECTRON_RUN_AS_NODE。例如在项目根保存Node CommonJS脚本后调用：

```javascript
const { runAgentTask } = require('./out/cli/agent.cjs')
const controller = new AbortController()

runAgentTask(
  { mode: 'plan', prompt: '研究价格计算规则并给出方案', cwd: 'D:/work/demo' },
  { signal: controller.signal, onEvent: (event) => console.error(JSON.stringify(event)) }
)
  .then((result) => {
    console.log(JSON.stringify(result))
    process.exitCode = result.exitCode
  })
  .catch((error) => {
    console.error(error instanceof Error ? error.message : '脚本准备失败')
    process.exitCode = 1
  })
```

`input`接mode/prompt及可选cwd/workspace/permission；`options`接signal、可选onEvent、approve与answer。approve收到精确操作和当前signal，只严格true批准；answer收到当前requestId/inputId/callId及问题，返回完整`{ id, answer }[]`，仍按原规则校验，答案不授权执行。此研究示例没有默认批准/猜答案；任务需要交互而未提供回调时以3结束。调用方通过controller.abort停止；回调异常/取消和迟到答复不会恢复旧等待。公共API输入/目录/配置等准备失败会reject，由脚本调用方处理；上例自行以1报告，CLI入口相应准备错误沿自身合同返回2。

### 9.4 公开输出、退出与生命周期

文本模式stdout只输出最终安全回答，进展/重试/工具/交互在stderr。JSONL stdout每行一个公开progress/delta/message/tool/retry记录及一次安全result；messageId和retry保留round/attempt，失败尝试过程退休，不拼接为成功回答。事件/结果显式重建白名单字段，不直接输出items、私有/加密协议、配置或HTTP对象。`options.answer`是问答回调，返回对象`answer`是最终文字，两者含义不同。

公共结果包含requestId/conversationId、task(state/result/error)、answer、effects(approved/started)、toolResults、elapsedMs和exitCode。toolResults只投影实际已返回的callId/name/output事实，保留取消竞争时已经完成的工具结果，不把历史/私有协议整体暴露。进程树退出未确认及副作用风险保留到安全终态。

| 退出码 | 当前含义                                |
| ------ | --------------------------------------- |
| 0      | 核心completed；仍须独立检查固定业务测试 |
| 1      | 任务、宿主或输出失败                    |
| 2      | 参数、目录、模型配置或正文输入错误      |
| 3      | 当前入口缺少审批/问答能力或仍待批准     |
| 130    | 用户取消                                |

default范围内原allow分支保留，auto-approve只有原review分支才做严格独立风险评估，其余人工回落，full-access仍走原文件/命令保护。TTY使用未被正文占用的终端，逐次yes/no或完整问题答案；管道/非TTY、审批问答EOF/异常/取消明确释放等待，不默认同意。CLI外层停止与宿主controller贯通模型、工具、退避和等待；目录身份/AGENTS指纹在执行前及250ms观察器复核，结束释放监听/readline/等待，不恢复整任务时限。

输出采用4MiB有界待写队列；正常等待写入确认，EPIPE/关闭取消任务。实际Windows继承管道的OS同步写会阻塞当前Node线程，`setBlocking(false)`原型未解决真实stdout/stderr停读。修后CLI对原生管道使用同目录固定`output-writer.cjs`，以当前`process.execPath`和绝对安装路径启动，cwd为安装目录。启动前复核安装目录、writer和manifest为普通独占路径，writer实际hash必须同时匹配编译entry固定hash及manifest唯一对应条目；缺失/篡改在模型和业务工具前失败，不从PATH/cwd替换或回退同步写。环境只留SystemRoot/WINDIR/TEMP/TMP，不传MODEL_*或NODE_OPTIONS。writer只向固定fd1/2按seq写入并ACK，不加载核心、模型、工具或工作区命令，也不构成原命令计划/沙箱链的权限降级。

父进程仍拥有任务取消与工具清理；健康通道可送终态，取消flush只有250ms宽限，未确认的输出可不完整，之后终止精确owned writer并等待close。消费者持续停读时JSONL尾部可能截断，通道不可用时可能无法交付完整终态，不能保证所有故障都能送达一条可解析result。stdout/stderr均为管道且writer身份失效时安全exit1、两输出可空，拒绝同步fallback；若终态已经ACK后helper退出异常，最终进程退出码1为依据。正常finish有独立1000ms回收宽限，帮助也在清理后确定退出码。桥接仅为自己创建的proxy保留幂等error接收，安全收口任务监听释放后的Node迟到error，不改用户传入流。业务命令仍必须走原CommandExecutionPlan/Job链，不能借writer执行。真实两流四组合与原Job组合结果见9.6。
