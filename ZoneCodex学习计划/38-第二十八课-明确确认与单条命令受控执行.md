# 第二十八课：明确确认与单条命令受控执行

创建日期：2026-09-23。状态：执行闭环已实现，待学习者完成桌面验收与自测。

前一课：[工作目录授权与命令执行准备](37-第二十七课-工作目录授权与命令执行准备.md)。第27课只读取目录配置并生成短期准备记录，没有启动程序。本课把这份审查上下文接成一次最小、明确、一次性的命令执行闭环。

## 1. 本课目标

完成一条可观察的用户流程：

`模拟命令提案 → 选择目录 → 查看脚本 → 检查执行准备 → 明确确认 → 执行 npm run typecheck → 查看输出和结果 → 释放授权`

本课只支持第26课固定的 `npm_typecheck` 模板。用户不能编辑命令字符串，模型不能传入程序、参数、目录或环境变量。执行前必须由主进程重新核对提案来源、目录准备记录和有效期；`preparedId` 只是短期审查记录，不能单独启动进程。

本课的学习重点是 Electron 的确认边界、主进程执行、IPC 事件、输出流、取消和生命周期。复杂的命令策略、任意命令、远程执行、MCP、自动重试和全面安全加固留到后续课程。

## 2. 明确边界

允许：

- 执行固定的 `npm run typecheck`。
- 使用第27课用户选择的本机目录。
- 显示有限的 stdout/stderr 和最终退出状态。
- 用户主动取消或达到短时超时后结束本次执行。

不允许：

- 把展示字符串拼成 shell 命令。
- 接受 renderer 或模型传来的绝对路径、命令文本或环境变量。
- 复用手动终端的输入接口。
- 把附件快照当成命令工作目录。
- 自动执行、自动重试或连续执行。
- 将执行结果写回版本4历史，除非后续课程单独设计协议。

界面必须清楚写出：**这是一次性执行；准备记录不会自动获得新的执行许可。**

## 3. 先画状态和调用链

面板状态建议为：

`未准备 → 准备完成 → 等待确认 → 执行中 → 成功/失败/取消/超时`

来源、目录、准备记录或窗口失效时回到“未准备”。执行中禁止重复确认、重新选择目录、启动 Agent、选择附件和文件提交。执行结束后立即释放 `preparedId`，同一记录不能再次执行。

调用链应保持清楚：

```text
React 面板
  → preload：confirmCommand / cancelCommand
  → ipcMain：复核来源、窗口和 preparedId
  → 主进程执行器：固定 program、args、cwd
  → stdout/stderr 事件
  → preload 解析事件
  → 面板显示输出和终态
```

主进程保存真实目录和执行状态，renderer 只保存不透明 ID、显示文本和当前状态。不要在 renderer 中调用 `child_process`，不要把 `preparedId` 发送给终端接口。

## 4. Windows 启动方式

先确认当前平台上的可用 Node/npm 启动方式，再实现执行器。不要直接把 `npm.cmd` 套进未经验证的 `shell: false` 示例，也不要通过 `cmd /c` 拼接展示字符串。

执行器应接收结构化数据：

```ts
type FixedCommand = {
  program: string
  args: string[]
  cwd: string
}
```

`program` 和 `args` 只能由主进程根据固定模板生成。Windows 的程序定位、参数数组传递和 stdio 管道必须在隔离练习目录中验证。若平台无法可靠定位或启动，应返回明确错误，不默默降级为 shell 字符串执行。

本课不负责解析全部 npm 配置。第27课已经说明：用户级/全局配置、环境变量、工作区设置和脚本引用文件仍可能影响结果；“执行前复查通过”不等于脚本安全。

## 5. 最小接口

新增共享类型，例如：

```ts
type CommandExecutionRequest = {
  source: CommandSource
  preparedId: string
  confirmationId: string
}

type CommandExecutionResult =
  | { status: 'started'; executionId: string }
  | { status: 'finished'; executionId: string; exitCode: number }
  | { status: 'cancelled' | 'timed_out' | 'error'; error: string }
```

实际接口可以把 started 和终态拆成 invoke 加事件，但必须满足：

1. renderer 不能传目录路径、程序名或参数。
2. `confirmationId` 由 renderer 为本次点击生成，主进程只接受一次。
3. 主进程检查窗口归属、完整来源、准备记录有效期和当前是否已有执行。
4. 过期、跨窗口、重复使用、来源不匹配的 ID 均拒绝。
5. 取消只影响所属窗口和当前 executionId，不影响下一次新一代请求。
6. 所有错误文本限制长度，不能回传令牌或完整 `.npmrc`。

建议事件只传递：`executionId`、流类型、受限文本片段和累计字节数。输出超过上限后停止继续累积并显示“输出已截断”，不能让日志无限增长。

## 6. 实现步骤

### 第一步：主进程执行服务

新增独立执行服务，维护窗口归属和当前执行 Map。执行前：

- 查找 `preparedId`，确认尚未过期、来源完全一致且属于当前窗口。
- 重新确认准备记录仍绑定固定 `npm_typecheck` 模板。
- 只读取主进程保存的真实目录，不接受 renderer 传入的 cwd。
- 建立一次性执行记录并立即标记为 running。

执行后无论成功、失败、取消还是启动异常，都删除一次性准备记录和执行记录。若启动结果未知，返回明确的 error/unknown 状态，不自动重试。

### 第二步：Windows 进程和输出

使用经过验证的结构化启动方式创建子进程，监听 stdout、stderr、error、close/exit。实现：

- 固定超时时间，例如 60 秒。
- 输出上限，例如总计 256 KiB；超过后停止追加显示。
- `AbortController` 或等价取消信号。
- 启动失败、非零退出码、信号结束分别产生可解释结果。

本课只要求单个 npm 进程的最小生命周期。进程树强制清理、Windows Job Object 和复杂孤儿进程恢复列为加固项目；但取消和超时不能只改变按钮文字，必须确实请求终止当前进程。

### 第三步：preload 与 renderer

在 `AppAPI`、preload 声明和运行时解析中加入有限接口。面板增加：

- “确认执行”按钮：只在准备完成时可用。
- 确认后显示固定命令、真实目录和影响说明。
- 执行中显示 stdout/stderr、已用时间和“取消执行”。
- 终态显示成功、失败、取消或超时，并提供关闭按钮。

确认对话框应让用户看到将要执行的固定模板、目录和“脚本可能运行任意项目代码”的提示。不要把前置/后置脚本隐藏在“typecheck”名称后面。

### 第四步：接入现有操作互斥

执行中阻止：

- 新 Agent 任务
- 附件选择、替换和撤销
- 文件准备和提交
- 重新选择命令目录
- 第二次执行确认

开始新会话、切换会话、清空消息、关闭审查面板、刷新页面和窗口销毁时，主进程应取消或清理当前执行。执行完成后的长时间状态不能阻塞整个应用。

## 7. 验收场景

先创建可丢弃的隔离目录，使用无副作用的 typecheck 脚本。测试前后比较目录文件，确认没有额外安装或写入；不要使用个人 `.npmrc`。

必须观察：

| 场景 | 结果 |
|---|---|
| 正常确认 | 固定命令在所选目录执行一次，显示输出和退出码 |
| 非零退出 | 显示失败和退出码，不自动重试 |
| 用户取消 | 进程收到终止请求，显示取消，ID 失效 |
| 超时 | 进程收到终止请求，显示超时，ID 失效 |
| 重复点击确认 | 只产生一次执行 |
| 过期/跨窗口/伪造 ID | 主进程拒绝，不启动进程 |
| 修改 package.json 后确认 | 重新检查失败或冲突，不执行旧准备 |
| 切换会话/关闭窗口 | 面板和主进程执行记录均清理 |
| 刷新页面 | 不恢复执行状态，历史不产生执行许可 |
| 长输出 | 达到上限后截断，界面仍可操作 |
| 680×560 窗口 | 输出可滚动，取消和关闭按钮可见 |

入口拦截应确认本课只启动预期的子进程，不调用 node-pty、不写入 `terminal:write`，不启动第二个 Agent 任务。执行测试不得把“命令成功”误记为文件修改成功。

## 8. 自测题

1. 为什么“准备完成”仍需要一次明确的执行确认？
2. 为什么执行接口不能接受 renderer 传来的 cwd 和命令字符串？
3. 为什么 `preparedId` 和 `confirmationId` 都必须一次性使用？
4. Windows 下为什么不能简单依赖 shell 字符串拼接？
5. stdout 和 stderr 为什么要分别处理并设置总输出上限？
6. 用户点击取消后，哪些操作必须由主进程完成，不能只更新 React 状态？
7. 执行超时、非零退出和启动失败为什么要显示不同状态？
8. 完成本课后，哪些问题仍应留给后续的命令安全加固课程？
