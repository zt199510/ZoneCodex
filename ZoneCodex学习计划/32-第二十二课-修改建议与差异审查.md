## 2. 开始前先认清当前工程

现在使用直接多选文件，不用第 21 课旧示例中的目录选择器和模式下拉框。添加即授权，发送后输入框附件清空，当前会话仍保留文件快照；“＋”菜单可清除会话文件。

- `projectSelection`：会话控制器对界面公开的待发送附件。

第 22 课预览入口要使用 `contextSelection`，不能因为待发送卡片消失，就认定文件快照不存在。当前 `App.tsx` 的终端入口被注释，保持现状即可，本课不依赖终端。

## 3. 用 Vue 经验理解

| Vue 经验 | 本课 React 写法 | 含义 |
|---|---|---|
| composable 管局部状态 | `useChangePreview` | 管请求、结果、错误和丢弃 |
| `computed` 派生展示 | 普通纯函数生成差异行 | 差异是原文和新文的计算结果 |
| `ref` 保存请求序号 | `useRef` 保存 generation | 避免迟到结果覆盖新界面 |
| `emit('discard')` | `onDiscard()` 回调 Prop | 面板通知控制器，不自己撤销文件授权 |

`useState` 决定页面显示，主进程决定文件是否属于授权快照。TypeScript 类型只约束开发代码，IPC 收到的对象仍需运行时检查。

## 5. 练习一：定义结构化建议

在 `src/shared/change-preview.ts` 中定义下面的最小协议，再自己补解析器：

```ts
export type PreviewChangeRequest = {
  conversationId: string
  snapshotId: string
  path: string
  proposedText: string
}

export type ChangePreview = {
  conversationId: string
  snapshotId: string
  path: string
  createdAt: string
  before: string
  after: string
}

export type PreviewChangeResult =
  | { status: 'ready'; preview: ChangePreview }
  | { status: 'error'; error: string }
```

这里 `path` 是选中文件的别名，不是绝对路径。空字符串 `proposedText` 是有效候选，表示把内容清空，不表示删除磁盘文件。

请求里没有 `before`：原文必须由主进程从快照获取。否则页面传一份假的旧内容，也能生成看似可信的差异。

解析器返回新对象，拒绝数组、null、访问器及未知字段；字符串长度和 ID 格式沿用现有共享解析习惯。禁止在失败提示里拼接全文。主进程检查新文本 UTF-8 字节数不超过 32768，单次只预览一个文件，规范化后原文和新文各不超过 500 行。preload 也要检查返回值中的类型、长度、时间与归属字段。

预期：空候选合法，非字符串、超限内容和错误 ID 能得到明确错误；不能把空候选当作“缺少参数”。

## 6. 练习二：从已授权快照取原文

主进程服务函数接收已验证请求与 `ProjectSnapshot`。先用 `snapshot.files.get(request.path)` 查找，不用 `fs.readFile(request.path)`。

```ts
const lines = snapshot.files.get(request.path)
if (!lines) throw new Error('文件不属于当前快照')
const before = lines.join('\n')
const after = request.proposedText.replace(/\r\n/g, '\n').replace(/\r/g, '\n')
```

现有快照已经规范化换行，所以 `before` 不是保留磁盘编码和换行的原始字节。本课只做文本预览；不要把这里的结果直接作为下一课写入策略。末尾换行差异需要单独展示“文件末尾换行发生变化”，不要无声忽略。

实现 `preview:change` 的 IPC 时按以下顺序：

1. 检查发送者属于有效 `BrowserWindow`，且来自该窗口主 frame。
2. 解析请求，失败返回统一错误结果。
3. 用 `BrowserWindow.fromWebContents(event.sender)!.id` 取窗口 ID，不要用 `webContents.id`。
4. 如果 `hasAgentJob(windowId)` 或 `hasProjectSelection(windowId)` 为真，提示先完成当前操作。
5. 调用 `captureProjectAccess(windowId, conversationId, snapshotId)`；返回 null 时拒绝预览。
6. 用上述服务函数从快照取原文，限制结果长度，再返回 `ready`。

建议服务函数保持同步纯计算，不引入新的磁盘读取与网络等待。不要根据页面传来的“已授权”布尔值绕过上述检查。

验收：随便改一个 path 或 snapshotId，得到错误；合法文件能拿到正确原文；重复请求不改变任何文件。

## 7. 练习三：用简单算法生成差异行

本课先实现“共同前缀 + 共同后缀 + 中间替换块”。它是线性比较，不保证像专业 diff 一样生成最少变化块：两处相隔很远的修改会显示为一个较大的替换块，这是本课明确的范围限制。

在 `diff.ts` 中定义：

```ts
export type DiffRow = {
  kind: 'same' | 'remove' | 'add'
  text: string
  oldLine: number | null
  newLine: number | null
}

const splitLines = (text: string): string[] => (text === '' ? [] : text.split('\n'))

export function buildDiff(before: string, after: string): DiffRow[] {
  const a = splitLines(before)
  const b = splitLines(after)
  let start = 0
  while (start < a.length && start < b.length && a[start] === b[start]) start++

  let oldEnd = a.length
  let newEnd = b.length
  while (oldEnd > start && newEnd > start && a[oldEnd - 1] === b[newEnd - 1]) {
    oldEnd--
    newEnd--
  }

  const rows: DiffRow[] = []
  for (let i = 0; i < start; i++) {
    rows.push({ kind: 'same', text: a[i], oldLine: i + 1, newLine: i + 1 })
  }
  for (let i = start; i < oldEnd; i++) {
    rows.push({ kind: 'remove', text: a[i], oldLine: i + 1, newLine: null })
  }
  for (let i = start; i < newEnd; i++) {
    rows.push({ kind: 'add', text: b[i], oldLine: null, newLine: i + 1 })
  }
  for (let i = oldEnd, j = newEnd; i < a.length; i++, j++) {
    rows.push({ kind: 'same', text: a[i], oldLine: i + 1, newLine: j + 1 })
  }
  return rows
}
```

输入必须已规范化换行；行数与大小限制在服务入口完成。`split('\n')` 保留末尾空行，界面可以用 `∅` 表示空行，并另外显示末尾换行提示。整份内容相同时显示“没有变化”，不要把所有行显示成删除再新增。

先在断点或现有练习环境验证：同文、纯新增、纯删除、修改一行、开头修改、结尾修改、末尾换行变化。不要先引入复杂编辑器组件。

## 8. 练习四：接好 preload 与界面状态

在现有业务 API 中增加 `previewChange(request): Promise<PreviewChangeResult>`。preload 调用固定频道 `preview:change`，校验请求和响应；不暴露通用 invoke、文件系统或路径转换函数。

`useChangePreview` 管理 `idle / loading / ready / error`。与 `useConversation` 协调复用现有 `operations.begin('selecting')` 和 `finish('selecting')`，本课只将 selecting 扩展为短暂的文件操作互斥。不要另起一套不受关闭保护控制的 busy 状态。后续复杂审查再拆分更明确的操作名。

请求开始前捕获 conversationId、snapshotId 和递增请求序号；返回时只有这三者仍匹配才能更新面板。使用 finally 释放互斥。组件卸载、丢弃、快照变更时让请求序号失效；改变会话或清除文件时立即清空预览，避免展示错误归属的结果。

不要让 effect 的旧请求 finally 随意结束其他新操作；每次完成前先确认自己仍拥有这次请求。一个请求 pending 时禁用重复预览与丢弃，卸载时释放自己持有的操作。

预期：连续点击不会重复请求；失败后可以修改候选并重试；关闭或切换后迟到结果不会重新打开旧面板。

## 9. 练习五：做一个可读的审查面板

面板放在聊天工作台内、输入区上方的独立区域，限制最大高度并内部滚动，不放在附件菜单里展示长代码。练习入口属于调试，面板属于正式布局组件，两者职责分开。

顶部显示文件名、快照时间、“仅预览，未写入文件”和关闭按钮。内容区显示旧行号、新行号、变化符号和原样文本：

```text
旧  新  变化  内容
1   1        export function greet(name: string): string {
2       -      return `你好，${name}`
    2   +      return `欢迎，${name}！`
3   3        }
```

删除用减号与背景色，新增用加号与背景色，不能只靠颜色区分。代码用 React 文本节点与 `<pre>` 展示，不使用 `dangerouslySetInnerHTML`；也不要把源码交给 Markdown 渲染，否则 `<script>`、反引号等内容会失真。

底部只提供“丢弃建议”，不要放一个实际上不工作的“应用修改”按钮。丢弃只删除临时建议，不清空对话、不撤销附件授权。

键盘与布局：关闭后焦点回到打开入口；Escape 关闭当前面板，不同时关闭侧栏；680×560 窗口里输入框、发送按钮仍可访问，长代码在面板内部滚动。

## 10. 完整练习与常见错误

自己新建 `greet.ts`，原文如下：

```ts
export function greet(name: string): string {
  return `你好，${name}`
}
```

候选内容只把第二行的问候语改成“欢迎”，在名字后添加感叹号，并与原文保持相同的末尾换行。先观察一删一增，再修改磁盘上的原文件，验证预览仍基于选入时的快照。重新选取文件后旧预览必须失效。

| 现象 | 优先检查 |
|---|---|
| 发送后无法打开预览 | 是否误用待发送 projectSelection 而不是 contextSelection |
| 文件已选却提示没有授权 | 是否误用 webContents.id，或沿用了旧 snapshotId |
| 新增空内容被拒绝 | 是否误用 `!proposedText` 判定缺参 |
| 差异里 HTML 变成页面 | 是否使用了 HTML 或 Markdown 渲染 |
| 取消后面板重新出现 | 是否校验请求序号与当前归属 |
| 页面看似改好了，磁盘没变 | 这是本课正常结果；预览没有写入能力 |

## 11. 验收清单

- 合法练习文件能看到正确的原行号、新行号与增删符号。
- 同文提示无变化；空候选显示全部删除；末尾换行变化可见。

- 丢弃不影响聊天与文件授权；源码始终按纯文本显示。
- 窄窗口可操作；预览前后用编辑器确认磁盘文件没有变化。
- `npm run typecheck` 与 `npm run build` 通过；已有工作台检查适配新入口后通过。

## 14. 八道自测题讲解

### 1. 修改建议、差异预览和真实写入分别是什么？

修改建议是一份候选新内容，例如把“你好”改成“欢迎”；差异预览是比较旧内容与候选内容，展示保留、删除和新增的行；真实写入才是实际修改磁盘文件。本课只做到建议与预览，没有写入能力。

### 2. 为什么请求不允许页面提供 before？

页面传来的数据不能直接作为可信原文。如果页面伪造 before，就可能隐藏实际差异。因此页面只提供文件别名和候选内容；主进程验证窗口、会话、快照归属后，从授权快照获取 before。这个基准是选入时的内容，不保证等于此刻的磁盘内容。

### 3. 为什么发送后待发送附件清空了，仍能打开预览？

`projectSelection` 是输入框待发送附件，`contextSelection` 是当前会话文件快照清单。发送后清空前者，后者仍可保留。预览使用后者，主进程再验证授权、获取快照内容。卡片消失不等于授权被撤销；清除会话文件或快照失效后，不能继续使用旧快照预览。

### 4. snapshotId 与磁盘文件现在的版本是不是同一件事？

不是。snapshotId 标识选入文件时建立的内存快照，不是实时磁盘版本号。例如选入时文件是“你好”，之后在编辑器里改成“早上好”，旧快照仍是“你好”，ID 不会因外部编辑自动变化。重新选择成功后才更新快照；以后写入还要检查磁盘是否变化。

### 5. 为什么空 proposedText 不能按缺少参数处理？

`proposedText: ''` 表示建议清空文件内容，是合法候选；预览应显示原内容全部删除，不表示删除磁盘文件。缺少字段、undefined、null 或非字符串才不合法。`if (!proposedText)` 会误拒绝空字符串，应检查字段、字符串类型和大小限制。

### 6. 共同前后缀算法有哪些限制，为什么本课仍采用它？

它保留连续相同的开头和结尾，把中间整体作为替换块。若第 2 行和第 10 行有修改，中间未变的第 3–9 行也可能被标成删除再新增。它不继续寻找中间相同片段，不保证最少变化块。本课使用它，是因为实现简单、比较耗时随行数线性增长，容易验证，足以先打通完整预览链路。

### 7. 切换会话后旧结果返回，依靠哪些信息避免串到新会话？

请求开始前捕获 conversationId、snapshotId 和递增请求序号（generation）。返回时三者必须仍匹配当前有效请求，才允许更新面板。切换会话、更新快照、丢弃或卸载时使旧请求失效，并按需清空预览。这样 A 会话的迟到结果不会显示在 B 中。旧请求 finally 也要检查操作归属，不能误释放新请求持有的互斥状态。

### 8. 为什么有读取授权、看过预览，仍不代表可以直接覆盖文件？

读取授权只允许获取内容，看过预览只说明看到了建议，都不等于同意写入。未来写入前还需要明确确认具体文件与具体内容，并核对磁盘是否在预览后发生变化，避免覆盖用户在其他编辑器中的新修改。发生冲突应提示并重新审查。本课没有写入接口，丢弃只清除临时建议。
