## 1. 本课目标与前置条件

完成一个可观察的闭环：**把两张截图添加或拖入同一个输入框，逐张预览或移除，发送给 AI 比较；退出重开后，仍能恢复这组图片并继续追问。**

沿用第47课的 PNG/JPEG、非空文字问题、可信图片导入、独立原图保存和现有预览。扩展同一消息的图片数量，选择、粘贴和图片拖放进入同一处理链；文本附件可共存，不增加新的聊天入口。主动截屏、图片生成、远程图片 URL、任意文件拖放和第49课不属于本课。

## 2. 用 Vue 经验理解本课

| Vue 中的经验                      | React 中对应的做法                       | 本课中的应用                                 |
| --------------------------------- | ---------------------------------------- | -------------------------------------------- |
| 响应式数组与 `v-for` 的稳定 `key` | 状态数组与基于图片身份的 `key`           | 同名截图不会互相覆盖，移除一张不影响其他图片 |
| `ref` 保存异步操作时的最新状态    | state 显示结果，ref/请求代次核对当前会话 | 迟到导入或恢复不能把旧图加入新会话           |
| 提交时复制表单数据                | 冻结本轮问题和图片组                     | 接受后清理同一草稿，重试继续使用原组         |

图片数组是界面状态；原图字节、可信归属和发送确认仍由主进程负责。不能只修改列表展示，就把它记为多图功能完成。

## 4. 按依赖顺序实施

### 步骤一：把单图契约扩展为有序图片组

先核对共享解析器、主进程和 preload，再同步 renderer。消息和当前请求需要表达有序图片组；版本6继续读取旧 `image` 单图与无图记录，可用可选图片组字段并统一归一化。新旧表示冲突、非法描述或重复身份必须明确处理，不靠文件名猜归属。

历史目前以 `index + messageId + imageId` 定位，解析器禁止重复输入位置；模型投影也按输入位置只保存一张图。扩展时让同一用户输入位置关联整组图片，同时核对消息身份、图片身份和顺序，不能简单取消重复检查。

沿用单张5 MiB、每边4096像素、1600万像素和现有20 MiB总预算；实施采用共享常量：每条消息最多8张，本次请求含历史最多100张且原图总量20 MiB。它们是本项目限制，不标为 Codex 或模型的固定上限。

**练习与预期：**旧单图、无图和新多图记录都能准确解析；同名文件仍是独立图片，非法引用拒绝。

**常见错误：**只改 TypeScript 类型却漏改严格运行时解析；为多图直接更换存储版本；让重复位置覆盖上一张图。

### 步骤二：统一多图选择、粘贴和图片拖放

原“＋”菜单支持选择多张图片，并把新图片追加到当前组。粘贴和拖放从明确的浏览器事件取得图片文件字节，复用主进程导入、格式校验和解码；输入区只接收本课支持的本地 PNG/JPEG，不把文本链接或文件名当成可信路径。

拖入输入区时给出简洁的放置提示，正确处理进入/离开和浏览器默认文件打开行为。正常文字粘贴、文字拖动及中文输入法继续使用已有处理。正在发送或准备时遵守现有互斥，不用新弹窗或新入口替代原流程。

**练习与预期：**选择两图或拖入两图，得到相同的可信卡片；失败说明准确，已有图片和文字保留。

**常见错误：**拖放绕过主进程校验；只接第一张却显示导入成功；把任意文件或远程 URL 加入图片组。

### 步骤三：逐张显示、预览和移除

`useImageSelection` 管理有序草稿组及消息图片组，卡片复用 `ImageAttachment`，一次预览一张。用户消息显示全部已发送图片，缺失项有对应提示；窄窗口中卡片可自然换行，保留文字输入和现有滚动位置。

逐张移除只作用于目标草稿图片，正确释放其运行时引用。异步导入和恢复沿用会话/请求代次核对，切换或清空后丢弃迟到结果。预览关闭时返回仍存在的卡片或输入框，保留 Tab、Enter/Space 和 Escape 行为。

**练习与预期：**移除第一张，第二张仍可预览；切换会话后不会串图；预览与右侧源码共存。

**常见错误：**用数组下标或文件名标识资源；移除一张清空整组；旧恢复结果覆盖新草稿。

### 步骤四：冻结发送及原图组重试、编辑

提交前冻结问题和整组图片，主进程逐张确认并捕获；只有整组准备成功才接受发送、绑定用户消息并清理同一版本草稿。中途失败保留草稿，不静默少发或降为纯文字。准备期间失败、取消及重复点击都遵守现有任务生命周期。

失败/停止后的重试使用该消息的原图组；新待发图片不能替换原组。编辑重发先核对整组可用性和容量，再裁剪后续历史。审计文字按实际图片组更新，`ToolRun.items` 不保存图片字节、data URL 或执行授权。

**练习与预期：**两图消息失败后加入第三张草稿图，再重试时仍发送原两张；整组失效时原消息与历史保留。

**常见错误：**第一张确认成功就发出；编辑先裁剪再检查图片；重试读取当前待发组。

### 步骤五：真实多图输入与历史追问

`agent-runner` 捕获经过核对的整组原图；实时适配器在对应用户项中按顺序加入多个 `input_image`，保留文字问题及原工具循环。第一次请求与每次工具后续请求都携带同组原图，不污染文字审计记录。

`selectToolContext` 输出同一消息的全部历史图片引用，使用消息身份和准确协议位置归组。不同消息即使问题文字或文件名相同也不能混淆；scope变化时沿用第47课的可见文字/图片历史规则，不恢复旧工具协议、推理或执行授权。

**练习与预期：**问“比较这两张图”，实际载荷含两张图且顺序准确；后续问“第二张图右下角是什么”仍携带对应组。

**常见错误：**只传两个路径；真实载荷仍只有一张；工具后续或历史追问丢掉其中一张。

### 步骤六：保存、恢复、清理及必要检查

复用逐图片原图存储，会话 JSON 仅保存有序描述/引用。主进程可信绑定、资产引用收集、恢复和清理都遍历整组；保存成功后才回收无引用图片，保存失败保留旧资产。切回、刷新及实际进程退出重开后恢复整组，缺图或损坏图明确提示，发送前不静默遗漏。

运行必要的 Node/Web 类型、lint、定向格式、构建和目录打包检查；开发版与打包版分别观察实际导入/解码、IPC、UI、请求和恢复链。使用自制图片验证多图请求及必要的真实模型比较，不上传此前用户截图，真实模型结果、合成响应和用户反馈分别记录。无变化的历史专项不重复扩大。

**练习与预期：**重开恢复两图并追问，旧单图和文本会话正常；完成检查后按实际结果更新课程、进度和结构地图。

**常见错误：**磁盘有原图但引用收集只读旧 `message.image`；保存失败仍删除旧图；只通过构建就标记真实多图问答通过。

## 8. 实施与验收记录（2026-10-08）

### 实际实现

- 新消息使用有序 `images`，当前请求使用 `images` 引用组；版本6旧 `image` 与无图记录仍可读，`getMessageImages` 统一归一化。新旧字段同时出现、重复身份、错序、错误消息归属及超限明确拒绝。历史同一协议位置按顺序关联整组，不用文件名或问题文字猜图片。
- 原“＋”选择器支持多选，粘贴和拖放取得本地PNG/JPEG字节，复用可信导入与解码。草稿按稳定imageId追加，批次失败只释放本批，已有文字和图片保留；逐张预览/移除、窄窗口换行及键盘返焦点沿用原组件。普通文字、输入法、文本附件和右侧源码保持。

### 手工测试方法

1. 开发入口使用 `npm run dev`；打包入口为 `dist/win-unpacked/zonecodex.exe`。可用本轮证据目录内 `generated-1.png`、`generated-2.png`，或自己制作两张词语/按钮不同的PNG/JPEG。
2. 在现有输入框通过“＋”一次选择两张，再分别试粘贴和从资源管理器拖入。逐张预览，移除第一张确认第二张仍在，再补回第一张。空问题不能发送，普通文字粘贴与中文Enter确认候选词应正常。
3. 发送“请分别读出这两张图片上的短词，并比较右下角按钮的颜色”。核对全部用户卡片与回答；保存后退出整个程序，再打开原会话，确认两张预览恢复，并追问“第二张图右下角的按钮是什么颜色”。
4. 两图消息生成中停止，另添第三张草稿图后点原回复“重试”；应使用原两图，第三图留在草稿。编辑原问题重发也应保留原组。失败/失效不应裁剪原消息或只发成功的一张。
5. 保留当前文字和一张图，试拖入不支持的文件、损坏PNG或超出8张；错误应准确，原草稿保留。缺失/损坏历史原图的隔离故障检查已有自动证据，手工检查时使用单独测试会话与备份，避免破坏正常历史。
