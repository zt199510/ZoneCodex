# 第三十九课：工作区项目上下文与项目指令

## 1. 本课目标与前置条件

本课把第31课留下的工作区协议接入实际聊天工作流。Codex App 的核心是选择项目或文件夹、在聊天中携带工作区上下文并查看产出；本课实现同样的最小闭环，不继续扩展任务诊断面板。

前置条件是第35至38课已经完成：会话可以创建、搜索、归档和恢复；输入框和附件浮层共用真实 Agent Responses SSE；失败和停止消息使用已有“重新生成”；任务记录只作为内部生命周期和刷新对账数据。

本课的完成目标：

- 用户可以为会话选择一个工作区目录，并看到当前工作区名称。
- 主进程只在选定根目录读取受限的 `AGENTS.md`，不执行其内容，也不接受模型提供的路径。
- 会话只保存工作区展示信息和指令指纹，不保存目录授权、运行时句柄、准备 ID 或执行 ID。
- Agent 请求明确区分工作区上下文和本轮附件快照；切换、清除、刷新后不会复用旧授权。
- 工作区变化、文件选择、生成和保存继续服从已有 `useOperation` 和关闭保护。

官方产品定位可参考 [ChatGPT desktop app](https://learn.chatgpt.com/docs/app)：选择项目或文件夹、使用文件和上下文、在多个聊天之间工作。本课只实现与当前 ZoneCodex 结构匹配的最小能力。

## 2. 用 Vue 经验理解本课

工作区不是全局可变单例，而是会话范围的上下文。可以把它理解为 Vue 中由页面状态持有的 `workspace`，再通过组合式函数把选择、清除和加载状态提供给侧栏、状态条和聊天请求。附件快照是一次请求可用的文件授权，不能直接当成永久工作区。

目录选择属于主进程能力，React 只保存显示结果和操作状态。与 Vue 中调用后端接口相同，IPC 返回值必须经过共享协议解析；类型声明只帮助开发，不能替代主进程的来源、窗口、路径和文件校验。

`AGENTS.md` 是上下文数据，不是要执行的脚本。发送请求时可以把受限内容作为模型上下文，但必须保留长度、编码、根目录和指纹边界，并在工作区改变后丢弃旧内容。

## 3. 当前源码核对

当前工程已经有以下基础：

- `src/shared/project.ts` 已定义 `Workspace`、`SavedWorkspace`、`ProjectInstruction` 和 `WorkspaceInstructionResult`。
- `src/main/agent/project-instruction.ts` 已实现根目录内单个 `AGENTS.md` 的普通文件、非符号链接、UTF-8、64 KiB 和 SHA-256 指纹检查。
- `Conversation` 已有可持久化的 `workspace: SavedWorkspace | null` 字段。
- `useProjectSelection` 和 `project-access.ts` 管理的是本窗口、本会话的附件授权快照，不是工作区目录。

当前缺口也要明确：

- `AppAPI` 尚无工作区目录选择、清除和读取指令的类型化接口。
- `src/main/index.ts` 尚未注册工作区目录对话框和 `readProjectInstruction` 的 IPC。
- `useConversation` 创建和恢复会话时仍把 `workspace` 保持为 `null`，没有工作区 Hook 或会话切换清理。
- Agent 请求目前只从附件快照生成项目说明，尚未安全合并会话工作区的指令内容。

## 4. 实际文件与职责

- `src/shared/project.ts`：补充工作区选择、清除和指令结果的共享请求/结果协议，保留 `SavedWorkspace` 的展示字段边界。
- `src/shared/api.ts`：声明工作区相关的 preload API。
- `src/main/agent/project-instruction.ts`：复用并检查 `AGENTS.md`，不新增任意路径读取。
- `src/main/index.ts`、`src/main/agent/project-access.ts`：注册窗口归属、目录选择、清理和授权失效处理。
- `src/preload/index.ts`：校验 IPC 输入和输出后暴露工作区 API。
- `src/renderer/src/features/project/useWorkspace.ts`（新 Hook）：管理选择、加载、错误、清除和当前会话归属。
- `src/renderer/src/features/conversation/useConversation.ts`：把工作区展示信息绑定到会话，切换、归档、恢复和刷新时清理运行时授权。
- `src/renderer/src/features/project/WorkspaceStatus.tsx`、侧栏或工作区入口：展示工作区名称和指令读取状态，不展示目录授权 ID。
- `src/renderer/src/features/chat/useChatRequest.ts`：发送前取当前工作区的受限指令快照，和本轮附件范围分开传递。
- `src/main/agent/agent-ipc.ts`：重新校验工作区/会话归属和指令长度，不信任 renderer 传来的绝对路径。

## 5. 按依赖顺序实施

### 步骤一：区分工作区与附件快照

先画出两条数据流：工作区是会话级上下文，附件快照是窗口内一次授权和本轮文件范围。确认 `snapshotId`、grant 和文件列表不写入 `SavedWorkspace`，也不把工作区根目录交给模型自由选择。

预期结果：能解释为什么清除附件不会自动删除工作区，为什么刷新后仍需要重新取得运行时授权。

常见错误：把 `ProjectSelection` 直接当成 `Workspace` 持久化，或把目录授权 token 写进 `conversation.json`。

### 步骤二：接通类型化工作区 IPC

新增窗口归属的目录选择接口和读取指令接口。主进程用 Electron 目录对话框取得路径，canonicalize 后再调用既有 `readProjectInstruction`；preload 对输入输出做共享解析，拒绝跨窗口、非目录、符号链接和未知字段。

预期结果：取消选择有明确的 `cancelled` 结果；目录无效、`AGENTS.md` 非法或读取失败不会产生半成品工作区。超过 64 KiB 的指令沿用现有截断标记，界面明确提示内容不完整。

常见错误：让 renderer 直接使用 Node `fs`，或仅依靠 TypeScript 类型而不在 preload/main 校验运行时数据。

### 步骤三：接入会话和界面

创建 `useWorkspace`，把工作区选择、清除、读取状态和错误放在 Hook 中。会话切换时只显示目标会话的 `SavedWorkspace`；归档当前会话、恢复会话和新建会话不得把上一个会话的工作区或附件授权带过去。

在工作区入口显示目录名称、`AGENTS.md` 的 absent/read/error 状态和清除按钮。显示内容只使用安全的标签和指纹，不显示 grant、准备 ID 或执行 ID。

预期结果：A/B 会话可以拥有不同工作区；切换后界面、聊天上下文和附件操作归属一致。

常见错误：把 Hook 状态放在整个应用单例中导致会话串工作区，或者只更新标签而没有撤销旧窗口授权。

### 步骤四：接入真实 Agent 请求

请求接受前读取当前会话的工作区指令快照，将其作为受限上下文与本轮附件说明分开传给既有 Agent 请求。主进程再次检查会话、窗口、工作区指纹和长度；指令内容只作为数据，不得改变工具白名单、权限策略或执行边界。

预期结果：普通聊天没有工作区指令时保持原路径；有工作区时仍只使用真实 Agent Responses SSE，工具历史和任务记录形状不新增第二份。

常见错误：把 `AGENTS.md` 拼到用户消息里、把指令当作新的系统权限，或让模型通过参数读取工作区外文件。

### 步骤五：处理生命周期和关闭保护

工作区选择、清除和指令读取使用 `selecting` 操作；生成、保存、提交和关闭保护期间拒绝冲突操作。窗口刷新或关闭时清理运行时授权，持久化的工作区只保留展示信息，不能恢复旧 grant。

预期结果：选择期间不能发送，生成期间不能切换目录；刷新后工作区名称可以恢复，但附件授权和执行许可必须重新建立。

## 6. 验收条件

- 目录选择、取消、清除和错误结果经过真实 Electron IPC，不能从 renderer 直接读磁盘。
- A/B 会话工作区互不串联；切换、归档、恢复和刷新不复用旧附件授权。
- `AGENTS.md` 只读取工作区根目录的受限文件，拒绝符号链接、非 UTF-8 和工作区外路径；超过 64 KiB 时只使用受限截断内容并提示。
- 有无 `AGENTS.md` 都能进入聊天；指令内容不产生新的消息、任务记录或工具调用。
- Agent、附件请求和普通聊天继续共用真实 Agent Responses SSE；不恢复模拟模型、普通文本入口或第二套传输。
- 状态条保持简洁，只展示项目上下文和当前操作；错误详情由聊天消息承载。
