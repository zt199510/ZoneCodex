# 第十一至二十一课小结

整理日期：2026-09-17。第 21 课已收到完成反馈，八题答案见[第 21 课第 16 节](28-第二十一课-项目文件读取与搜索.md#16-八道自测题讲解)。本小结总结学习内容，不把完成课程等同于已经熟练掌握所有原理或通过全部运行验收。

## 1. 这十一课完成了什么进阶？

从“能对话的桌面聊天界面”，推进到“有多会话存储、真实终端、AI 工具循环和只读项目文件能力的桌面应用”。重点逐渐从组件怎么写，转向数据怎么保存、异步任务如何归属、资源如何释放，以及模型能做什么。

| 课程 | 学到的核心内容 | 对应用的作用 |
|---|---|---|
| 11：自动保存 | 防抖、Effect 清理、dirty 判断、保存快照、失败暂停和重试 | 减少手动保存，同时避免失败后不断重试 |
| 12：退出保护 | 窗口关闭拦截、请求确认、保存成功后关闭、操作互斥 | 防止未保存时直接退出，保存失败留窗 |
| 13：多会话结构 | 会话 ID、活动会话、数据解析、纯函数迁移 | 从单会话升级为版本 2 会话库 |
| 14：多会话接入 | 旧文件备份、整库保存、侧栏新建和切换、请求归属 | 重启恢复会话，异步结果不串到其他会话 |
| 15：Markdown | 原文与展示分离、GFM、HTML 和 URL 限制 | 回复更易读，原始文本仍用于保存和上下文 |
| 16：终端界面 | xterm、尺寸适配、输入输出事件、实例与订阅清理 | 建立终端显示层，先用模拟理解生命周期 |
| 17：真实终端 | node-pty、PowerShell、IPC 数据传递、进程退出与释放 | 用户可以在应用内手动执行命令 |
| 18：工具循环 | function_call、工具参数校验、call_id 配对、结果回传、循环预算 | 模型提出工具请求，由应用执行并交回结果 |
| 19：聊天整合 | 模式路由、进度、停止、终态处理、请求与会话绑定 | 在原输入框使用工具，复用聊天生命周期 |
| 20：工具历史 | trace 与协议分离、按轮存储、连续历史、版本 3 迁移 | 重启可看工具记录，后续问答可使用合法协议历史 |
| 21：项目文件 | 只读快照、路径检查、搜索与按行读取、范围隔离、版本 4 迁移 | 模型在获准的文件范围内找代码并引用行号 |

## 2. 主要学到了哪些技术栈？

这些课沿用 React、TypeScript、Electron，并逐步加入 Markdown 和终端库。工具循环、快照和权限设计主要由自己的 TypeScript 代码实现。

| 层次 | 技术或库 | 你学到的用途 |
|---|---|---|
| 界面 | React、TSX、CSS | 聊天工作台、侧栏、消息、终端面板和状态提示 |
| 状态与生命周期 | useState、useRef、useEffect、useLayoutEffect、useCallback、自定义 Hook | 状态归属、实例保存、订阅清理、滚动、保存与请求逻辑拆分 |
| 类型系统 | TypeScript | 共享接口、联合类型、类型收窄、unknown 解析和跨模块约定 |
| 桌面应用 | Electron | 主进程、渲染进程、preload、窗口关闭、文件对话框和本地能力 |
| 跨进程接口 | contextBridge、IPC invoke/handle、事件订阅 | 让页面通过有限接口请求主进程，并接收进度和终端输出 |
| 本地文件 | Node.js fs、path、文件句柄、Map、UTF-8 解码 | JSON 存储、备份迁移、安全读取、构建文件快照 |
| 消息排版 | react-markdown、remark-gfm | Markdown 标题、列表、代码块和 GFM 表格的展示 |
| 终端显示 | @xterm/xterm、@xterm/addon-fit、ResizeObserver | 输入事件、字符绘制和面板尺寸适配 |
| 终端进程 | node-pty、Windows PowerShell | 伪终端连接、真实命令交互、进程生命周期和原生依赖重建 |
| 模型交互 | HTTP/fetch、Responses 格式的函数工具协议、JSON Schema | 定义工具、接收调用、回传结果、保留协议历史 |
| 异步控制 | Promise、async/await、AbortController、计时器 | 保存等待、停止请求、超时、失败恢复和迟到回调保护 |
| 工程检查 | npm、TypeScript 检查、ESLint、Prettier、electron-vite | 管理依赖、检查类型与代码、开发和构建 |

这里的“Responses 格式”指项目使用的模型协议，不代表必须使用某个专用 SDK；这些课的工具循环也不依赖 LangChain 等 Agent 框架。

## 3. 比库名更重要的六种工程能力

### 状态只有一个可信来源

会话库保管消息，当前会话由 activeConversationId 派生。Markdown 是原文的显示结果，trace 是执行过程的展示记录。不要为了方便在几个组件里分别保存同一份业务事实，否则容易一边更新、另一边遗漏。

### 给异步工作明确身份

启动请求时捕获会话、请求和快照 ID。回调回来时更新它原本属于的对象，不读取此刻页面选中的对象。state 驱动页面；ref 可保存当前任务、实例和同步锁。两者用途不同。

### 创建资源时就设计清理

计时器要清除，订阅要取消，xterm 要 dispose，PTY 要终止，文件句柄要关闭，网络请求要能取消。组件消失或页面刷新不代表所有外部资源都会自行结束。

### 类型与运行时校验各司其职

TypeScript 帮你在写代码时发现问题；磁盘 JSON、IPC 参数、模型参数仍需运行时检查。`as SomeType` 不会验证内容，JSON Schema 也不能保证模型永远返回合法参数。

### 历史记录和当前权限分开

保存消息不等于恢复任务，保存工具结果不等于恢复读取授权。文件内容是数据，模型输出的工具调用是请求，主进程才决定是否执行。

### 失败也是功能的一部分

保存失败要能重试，迁移失败不能覆盖原记录，取消后要恢复按钮，超限要如实报错，旧回调不能覆盖新状态。成功路径跑通只是其中一部分。

## 4. 三条链路串起来复习

```text
保存：会话变化 → 判断未保存 → 空闲防抖 → IPC → 主进程写 JSON
      → 成功后更新“已保存快照”；失败则保留未保存状态

终端：用户输入 → xterm → preload/IPC → node-pty → PowerShell
      PowerShell 输出沿反方向回到 xterm 屏幕

项目工具：用户选文件 → 主进程校验并创建 Map 快照
          → 模型请求搜索/读取 → 主进程校验授权及参数
          → 查快照并返回结果 → 模型回答 → 一次提交消息和工具记录
```

工具模式有实时进度，但当前最终答案是在任务完成后提交；不要把它与普通聊天已有的 SSE 增量文字混为一谈。

数据版本也对应能力演进：版本 1 单会话 → 版本 2 多会话 → 版本 3 工具轮次及协议历史 → 版本 4 工具范围 scope。迁移是验证旧结构、转换并验证新结构，不是只改版本数字。

## 5. 目前还没学完什么？

- 文件修改、差异审查、授权写入和冲突保护：下一阶段。
- 模型执行终端命令：需要单独的命令授权设计；当前终端由用户手动操作。
- MCP、SSH：属于后续课程；已经实现函数工具循环不等于已经接入 MCP。
- SQLite、全局状态库：当前主要是本地 JSON 和 React 状态，没有因为多会话就必须引入它们。
- 安装包发布与自动更新：模板依赖存在，不代表已经完成发布和更新流程。

## 6. 复习时优先掌握什么？

先能用自己的话讲清以下五点，再回头记 API：

1. 为什么 React 页面、磁盘记录、发送给模型的上下文是三份不同的数据？
2. 为什么迟到结果必须检查 requestId、conversationId 或选择 token？
3. 为什么 xterm、node-pty、PowerShell 分别承担显示、连接和解释命令？
4. 为什么模型请求工具后，还需要应用校验、执行、回传结果再请求模型？
5. 为什么重启能看到旧文件答案，却仍然需要重新选择文件？

目前你的学习重点已经进入 **React + TypeScript + Electron + Node.js 的桌面工程，以及模型工具调用的应用设计**。能把以上链路解释清楚，比背下全部函数名称更能说明理解程度。
