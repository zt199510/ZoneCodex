# 第十课：聊天记录的本地保存与恢复

## 1. 目标与起点

点击“保存到本地”，将当前消息和工作目录写入磁盘；重启后自动读取。文件不存在时显示空对话；文件损坏、版本不支持或读取失败时显示错误，并阻止覆盖原记录。

本次已核对 Message 类型、App 状态和已有 API：消息仍保存在 React 内存，尚无文件持久化。App 还保留第八课独立真实流区，请先按第九课移除它的导入、状态及挂载 JSX，之后只使用正式聊天入口。

本课采用“自动读取、手动保存”，不做每个 delta 自动写文件，也不依赖退出时临时保存。保存完成后才显示已保存。没有保存的修改在关闭后丢失，是本课明确的行为。

继续由你亲手实现，不安装依赖，不接触密钥。保存的是显示消息和路径，不是完整模型推理状态，也不把停止的半截回复变成成功历史。

## 2. 先确定存什么、存到哪里

文件使用主进程的 app.getPath('userData') 下的 conversation.json。不要写进 src、out、安装目录或用户选中的工作目录。

```text
React 消息和路径快照
  → preload 业务接口
  → main 运行时校验
  → 同目录临时文件
  → rename 替换 conversation.json

启动 → main 读文件并校验 → React 恢复消息和路径
```

| 项目 | 本课规则 |
|---|---|
| version | 固定为 1，识别文件格式版本 |
| messages | id、role、content、status |
| workspacePath | 字符串或 null；恢复路径不代表目录仍存在 |
| pending | 读取时改为 failed；旧网络请求不会随文件恢复 |
| complete / failed / cancelled | 原样恢复，只有 complete 问答进入上下文 |
| input 草稿、错误提示、requestId | 不保存 |
| API 密钥 | 不属于聊天文件 |

Vue/React 的状态都不会因为创建了一个对象就自动保存到磁盘。本课通过按钮明确提交快照；加载完成以前不允许发送和清空，防止空的初始状态覆盖旧记录。

## 4. 共享类型与校验

新建 src/shared/conversation.ts：

```ts
export type ChatMessage = {
  id: string
  role: 'user' | 'assistant' | 'system'
  content: string
  status: 'pending' | 'complete' | 'failed' | 'cancelled'
}

export type ConversationSnapshot = {
  version: 1
  messages: ChatMessage[]
  workspacePath: string | null
}

export type LoadConversationResult =
  | { ok: true; snapshot: ConversationSnapshot; missing: boolean }
  | { ok: false; error: string }

export type SaveConversationResult =
  | { ok: true }
  | { ok: false; error: string }

function isRecord(value: unknown): value is Record<string, unknown> {
  return typeof value === 'object' && value !== null && !Array.isArray(value)
}

export function parseSnapshot(value: unknown): ConversationSnapshot | null {
  if (!isRecord(value) || value.version !== 1 || !Array.isArray(value.messages) ||
      value.messages.length > 1000) return null
  const workspacePath = value.workspacePath
  if (workspacePath !== null &&
      (typeof workspacePath !== 'string' || workspacePath.length > 4096)) return null

  const messages: ChatMessage[] = []
  const ids = new Set<string>()
  let total = 0
  for (const item of value.messages) {
    if (!isRecord(item) || typeof item.id !== 'string' || !item.id ||
        item.id.length > 80 || ids.has(item.id) || typeof item.content !== 'string') return null
    const { role, status, content, id } = item
    if (role !== 'user' && role !== 'assistant' && role !== 'system') return null
    if (status !== 'pending' && status !== 'complete' &&
        status !== 'failed' && status !== 'cancelled') return null
    if (content.length > 100_000 || (role === 'user' && content.length > 4000)) return null
    if (status === 'complete' && !content.trim()) return null
    total += content.length
    if (total > 1_000_000) return null
    ids.add(id)
    messages.push({ id, role, content, status })
  }
  return { version: 1, messages, workspacePath }
}
```

这里只复制允许保存的字段；unknown 数据不能直接 as 成快照。限制条数和长度是本课资源边界，不是模型 token 上限。重复 ID 会破坏 React 列表身份，因此拒绝。

在 MessageList.tsx 删除原 export type Message = {...}，改为以下两行，其他渲染逻辑保留：

```ts
import type { ChatMessage as Message } from '../../../shared/conversation'
export type { ChatMessage as Message } from '../../../shared/conversation'
```

第一行让本文件能用 Message，第二行兼容 App 和 context.ts 已有的类型导入。主进程不能为了使用消息类型而导入 React 组件。

在 shared/api.ts 顶部添加类型导入：


## 5. 主进程：串行保存与保护旧文件

新建 src/main/conversation-store.ts：

```ts
import { mkdir, readFile, writeFile, rename, rm } from 'node:fs/promises'
import { join } from 'node:path'
import { randomUUID } from 'node:crypto'
import { parseSnapshot } from '../shared/conversation'
import type {
  ConversationSnapshot, LoadConversationResult, SaveConversationResult
} from '../shared/conversation'

export function createConversationStore(directory: string) {
  const file = join(directory, 'conversation.json')
  let queue: Promise<unknown> = Promise.resolve()

  function serial<T>(work: () => Promise<T>): Promise<T> {
    const next = queue.then(work, work)
    queue = next.catch(() => undefined)
    return next
  }

  async function readExisting(): Promise<ConversationSnapshot | null> {
    let bytes: Buffer
    try {
      bytes = await readFile(file)
    } catch (error: unknown) {
      if (typeof error === 'object' && error !== null &&
          'code' in error && error.code === 'ENOENT') return null
      throw error
    }
    if (bytes.length > 8_000_000) throw new Error('文件过大')
    const snapshot = parseSnapshot(JSON.parse(bytes.toString('utf8')))
    if (!snapshot) throw new Error('文件格式或版本不支持')
    return snapshot
  }

  return {
    load: (): Promise<LoadConversationResult> => serial(async () => {
      try {
        const saved = await readExisting()
        const snapshot: ConversationSnapshot = saved ?? {
          version: 1, messages: [], workspacePath: null
        }
        return {
          ok: true,
          missing: saved === null,
          snapshot: {
            ...snapshot,
            messages: snapshot.messages.map((message) =>
              message.status === 'pending' ? { ...message, status: 'failed' } : message
            )
          }
        }
      } catch {
        return { ok: false, error: '读取聊天失败：文件可能损坏、版本不支持或无法访问。原文件未修改。' }
      }
    }),

    save: (value: unknown): Promise<SaveConversationResult> => {
      const snapshot = parseSnapshot(value)
      if (!snapshot) return Promise.resolve({ ok: false, error: '聊天格式或长度不符合保存要求。' })
      const text = JSON.stringify(snapshot, null, 2)
      if (Buffer.byteLength(text, 'utf8') > 8_000_000) {
        return Promise.resolve({ ok: false, error: '聊天文件超过本课大小上限。' })
      }
      return serial(async () => {
        const temporary = join(directory, `conversation-${randomUUID()}.tmp`)
        try {
          // 写入前再次检查已有文件，防止将已损坏文件静默覆盖。
          await readExisting()
          await mkdir(directory, { recursive: true })
          await writeFile(temporary, text, { encoding: 'utf8', flag: 'wx' })
          await rename(temporary, file)
          return { ok: true }
        } catch {
          return { ok: false, error: '保存失败：请检查权限、磁盘或已有文件格式。未主动删除原文件。' }
        } finally {
          await rm(temporary, { force: true }).catch(() => undefined)
        }
      })
    }
  }
}
```

阅读重点：

1. 所有读写进入同一 Promise 队列，应用内保存不会相互交叉；一次失败不会让后续队列永远失效。
2. 在进入队列前序列化快照，保存的是点击时的数据，不会被后续对象变化改变。
3. 先写同目录唯一临时文件，再 rename 替换目标。不要先删除原文件，否则写失败就没有旧记录。
4. 如果已有文件损坏，load 和 save 都返回错误；不能把“读取失败”当成“第一次启动”。
5. 临时文件残留清理由 finally 尝试完成。rename 被系统占用或权限阻止时应报错，不用删除目标来强行重试。

这是单应用实例下的教学存储。它不是数据库事务，不提供多进程编辑冲突合并，也不承诺断电后一定保留最后一次写入。文件上限在读入后检查，用于控制解析范围；没有实现大文件流式读取。

在 main/index.ts 顶部添加：

```ts
import { createConversationStore } from './conversation-store'
```

在 app.whenReady().then(...) 内、createWindow() 前注册：

```ts
const conversationStore = createConversationStore(app.getPath('userData'))

ipcMain.handle('conversation:load', (event) => {
  if (!BrowserWindow.fromWebContents(event.sender) ||
      event.senderFrame !== event.sender.mainFrame) throw new Error('不支持的读取来源')
  return conversationStore.load()
})

ipcMain.handle('conversation:save', (event, snapshot: unknown) => {
  if (!BrowserWindow.fromWebContents(event.sender) ||
      event.senderFrame !== event.sender.mainFrame) throw new Error('不支持的保存来源')
  return conversationStore.save(snapshot)
})
```

只创建一个 store 并注册一次，不能每次保存都创建新队列。页面不传文件路径，读写目标固定。

## 6. preload：校验读取结果

在 preload/index.ts 顶部增加：

```ts
import { parseSnapshot } from '../shared/conversation'
```

在 api 内追加：

```ts
loadConversation: async () => {
  const result: unknown = await ipcRenderer.invoke('conversation:load')
  if (typeof result === 'object' && result !== null && 'ok' in result) {
    if (result.ok === false && 'error' in result && typeof result.error === 'string') {
      return { ok: false, error: result.error }
    }
    if (result.ok === true && 'snapshot' in result &&
        'missing' in result && typeof result.missing === 'boolean') {
      const snapshot = parseSnapshot(result.snapshot)
      if (snapshot) return { ok: true, snapshot, missing: result.missing }
    }
  }
  throw new Error('读取结果格式不正确')
},
saveConversation: async (snapshot) => {
  const result: unknown = await ipcRenderer.invoke('conversation:save', snapshot)
  if (typeof result === 'object' && result !== null && 'ok' in result) {
    if (result.ok === true) return { ok: true }
    if (result.ok === false && 'error' in result && typeof result.error === 'string') {
      return { ok: false, error: result.error }
    }
  }
  throw new Error('保存结果格式不正确')
}
```

这里 parseSnapshot 是实际函数，所以不用 import type。现有 index.d.ts 已引用 AppAPI，不另写运行时实现。

## 7. App：先加载，再允许操作

在 App 顶部增加：

```ts
import type { ConversationSnapshot } from '../../shared/conversation'
```

在已有状态旁增加：

```tsx
const [storageReady, setStorageReady] = useState(false)
const [isSaving, setIsSaving] = useState(false)
const [storageError, setStorageError] = useState<string | null>(null)
const [storageStatus, setStorageStatus] = useState('正在读取本地记录…')
const [savedSignature, setSavedSignature] = useState<string | null>(null)
const diskBusy = useRef(true)

const snapshot: ConversationSnapshot = { version: 1, messages, workspacePath }
const currentSignature = JSON.stringify(snapshot)
const hasUnsavedChanges = storageReady && currentSignature !== savedSignature
```

signature 是本课用于判断“当前状态是否等于上次保存快照”的字符串，不是加密签名。它可以涵盖选择目录和清空消息的修改；没有新增一个需要到处手动维护的 dirty 布尔值。数据更大时再优化序列化开销。

在现有流订阅 Effect 之外另加一个读取 Effect：

```tsx
useEffect(() => {
  let disposed = false
  async function load(): Promise<void> {
    try {
      const result = await window.api.loadConversation()
      if (disposed) return
      if (!result.ok) {
        setStorageError(result.error)
        setStorageStatus('读取失败，已禁止保存覆盖')
        return
      }
      setMessages(result.snapshot.messages)
      setWorkspacePath(result.snapshot.workspacePath)
      setSavedSignature(result.missing ? null : JSON.stringify(result.snapshot))
      setStorageReady(true)
      setStorageStatus(result.missing ? '首次使用，尚未保存' : '已读取本地记录')
    } catch {
      if (!disposed) {
        setStorageError('读取通信失败，请完整重启后重试。')
        setStorageStatus('读取失败，已禁止保存覆盖')
      }
    } finally {
      if (!disposed) diskBusy.current = false
    }
  }
  void load()
  return () => { disposed = true }
}, [])
```

加载失败时 storageReady 仍是 false，不自动写入空数组。disposed 防止旧加载结果回写已经卸载的组件；开发环境 Effect 重建时，旧调用结果被忽略。它不取消磁盘读取，只取消使用旧结果。

主进程将 pending 改为 failed 是读取恢复策略，不会自动改写磁盘；下次点击保存才落盘。上次生成中的网络任务不会凭空恢复。

## 8. 保存按钮与操作互斥

在 App 内增加：

```tsx
async function handleSaveConversation(): Promise<void> {
  if (!storageReady || diskBusy.current || sendingRef.current || isSelecting) return
  diskBusy.current = true
  setIsSaving(true)
  setStorageError(null)
  setStorageStatus('正在保存…')
  const toSave = snapshot
  const signature = JSON.stringify(toSave)
  try {
    const result = await window.api.saveConversation(toSave)
    if (!result.ok) {
      setStorageError(result.error)
      setStorageStatus('保存失败，修改尚未保存')
      return
    }
    setSavedSignature(signature)
    setStorageStatus('保存成功')
  } catch {
    setStorageError('保存通信失败，请重试。')
    setStorageStatus('保存结果未确认')
  } finally {
    diskBusy.current = false
    setIsSaving(false)
  }
}
```

快照里的对象由 React 不可变更新维护，后续更新不会原地改写它。保存期间也禁止生成、清空和选择目录，减少竞态。

在这三个函数原有入口判断中追加以下条件（合并进现有 if，不删除原条件）：

```ts
!storageReady || diskBusy.current
```

三个函数分别是 handleSend、handleClearConversation、handleSelectFolder。例如清空入口变为：

```ts
if (!storageReady || diskBusy.current || sendingRef.current) return
```

handleSelectFolder 原有的 isSelecting 检查保留。保存函数检查 isSelecting，避免已打开的目录对话框在保存过程中返回新路径；即使实际状态后来发生变化，也只将本次 snapshot 的 signature 标为已保存，新状态仍会显示未保存。

在页面消息区前添加：

```tsx
<section aria-label="本地保存">
  <button type="button"
    disabled={!storageReady || isSaving || isSending || isSelecting}
    onClick={() => { void handleSaveConversation() }}>
    {isSaving ? '正在保存…' : '保存到本地'}
  </button>
  <p role="status">{storageStatus}</p>
  {hasUnsavedChanges && <p>有未保存的修改，关闭前请点击保存。</p>}
  {storageError && <p role="alert">{storageError}</p>}
</section>
```

将已有控件的 disabled 条件补齐：

| 控件 | disabled 条件 |
|---|---|
| ChatInput | !streamReady || !storageReady || isSaving || isSending |
| 清空对话按钮 | !storageReady || isSaving || isSending |
| 选择工作目录按钮 | !storageReady || isSaving || isSelecting |

停止生成按钮保持原逻辑，不要在需要停止时禁用它。保存只允许在生成结束后进行。

清空仍先清内存，页面会出现未保存提示；想让重启后也为空，需要再点击保存。若清空后直接退出，下次会恢复上次磁盘记录。

## 9. 类型检查与磁盘实验

先运行 npm run typecheck，再完整重启 Debug All。每个新主进程通道只注册一次。新增 shared 文件已有 include 覆盖，无需关闭 composite。

在主进程断点里查看 app.getPath('userData')，确认实际保存目录，不要猜目录名。Windows 常在用户 AppData 下，但以 API 返回路径为准。本课不要求在日志打印聊天内容。

按顺序实验：

1. 首次没有 conversation.json：页面空对话，提示首次使用，操作可用。
2. 完成一轮聊天、选择目录，点击保存：出现保存成功；重启后内容、ID、状态和目录恢复，输入草稿不恢复。
3. 新增消息但不保存，退出重启：只恢复上次保存的版本。
4. 清空后保存，重启：空对话，目录仍保留。
5. 保存失败：界面显示错误，不能假装已保存；修复条件后允许再次保存。

损坏文件实验应使用测试数据，先关闭应用并自行复制备份：把 conversation.json 内容改为不完整 JSON，再启动。应显示读取失败并禁止发送/保存；不要把此情形当成空文件。关闭应用后恢复备份，再重启。若确实希望从空记录重新开始，可以先把损坏文件改名留存，保持原文件名缺失后重启；不能在代码中自动删除损坏文件。

未完成状态实验：在关闭应用时，将测试文件中一轮消息的 status 改为 pending（保留合法结构），重启后应显示 failed，且不进入后续上下文。修改 version 为 999 应拒绝读取和覆盖。

本地存储模块可以在临时目录中独立测试，不需要 Electron 窗口或模型请求：调用 createConversationStore(测试目录)，验证缺失、保存再读、损坏拒写、串行保存顺序、pending 恢复和非法快照。不要拿真实聊天文件做自动破坏性测试。

## 10. 验收、自测与后续

文档创建时已对共享校验、存储、preload 和 React 读取/保存示例做严格类型检查；在独立临时目录验证缺失、保存恢复、Unicode、pending 转换、非法快照、损坏/未知版本拒写、失败后队列恢复和连续保存顺序。未使用真实聊天文件，未验证 Electron 窗口集成；以下仍由你实现后验收。

- [ ] 类型检查通过，保存后重启能恢复消息和目录。
- [ ] 首次缺失与读取失败有不同处理，损坏文件未被覆盖。
- [ ] pending 恢复为 failed，不再显示仍在生成。
- [ ] 保存完成才标为已保存，失败保留未保存状态。
- [ ] 清空后是否重启恢复取决于是否保存，行为与提示一致。
- [ ] 加载/保存期间不能误发送或清空，流停止功能仍正常。
- [ ] 文件不含密钥，测试备份已恢复，没有实验损坏残留。

自测题：

1. React 内存状态、磁盘快照和模型上下文有什么区别？
2. 为什么先读取成功，再允许保存？为什么 ENOENT 和 JSON 损坏不能一样处理？
3. 为什么保存到 userData，而不是用户选中的工作目录？
4. 临时文件加 rename 比直接先清空原文件有什么好处？它是否等于数据库事务？
5. Promise 队列解决什么问题？一次保存失败后，后面的保存还能执行吗？
6. 为什么 pending 不能在重启后继续显示“生成中”？
7. 清空后没保存就退出，为什么旧聊天会回来？
8. 保存了消息文字，是否等于保存了完整模型推理状态或 API 密钥？


1-1. **内存、磁盘、模型上下文是三份不同用途的数据。**

   | 数据 | 保存什么 | 什么时候变化 |
   |---|---|---|
   | React 内存 | 页面当前消息 | 发送、收到回复、清空时 |
   | 磁盘快照 | 上一次保存的消息和目录 | 点击保存且成功后 |
   | 模型上下文 | 本次选中的成功问答＋当前问题 | 每次请求前重新构造 |

   **页面变了，不代表磁盘已经保存；磁盘有记录，也不代表模型自动知道。**

1-2. **先读取，是为了避免用启动时的空数组覆盖旧记录。**

   `ENOENT` 表示文件不存在，可以正常从空记录开始；JSON 损坏表示文件存在但读不懂，里面可能还有能恢复的数据，因此应保留并报错。

1-3. **`userData` 是应用自己的数据目录。**用户选中的工作目录可能随时改变、被移动，或者没有写入权限。聊天记录跟着应用管理，不应散落在不同项目文件夹里。

1-4. **先写临时文件，写好后再替换原文件，可以减少旧记录丢失的风险。**

   如果先清空原文件，随后写入失败，旧记录就没了。临时文件方案写失败时通常还能保留旧版本，但它不等于完整数据库事务，也不能保证断电时绝不丢失最后一次修改。

1-5. **Promise 队列让保存按顺序执行。**例如先保存 A，再保存 B，应先完成 A，再写 B，避免两次写入交叉。

   你的代码还处理了失败，所以一次保存失败后，后面的任务仍能继续执行。

1-6. **文件里的 `pending` 只是一个状态标记，不能恢复已经结束的网络连接。**重启后继续显示“生成中”会误导用户，因此本课将它改成 `failed`，提示上一轮没有完成。

1-7. **本课没有实时保存。**例如：

   ```text
   保存聊天 A → 磁盘是 A
   点击清空   → 页面为空，磁盘仍是 A
   直接退出   → 重启读取磁盘，A 又出现
   ```

   想让下次也为空，需要“清空 → 保存成功 → 退出”。

1-8. **正确。**保存消息文字不等于保存完整模型推理状态，也不会自动保存 API 密钥。
