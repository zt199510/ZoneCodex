# 第八课：真实流式响应与网络取消

## 1. 目标与起点

把第七课的“定时器产生片段”扩展为“从模型 HTTP 响应中读取片段”。新增真实流练习区，支持文字逐段显示、停止、60 秒总超时，以及连接提前结束的错误提示。

第七课已收到完成反馈，源码已核对，上一轮两组类型检查通过；停止和卸载窗口交互未由助手独立验收。本课保留原模拟区和第六课正式聊天，新增单轮真实流练习区，避免同时改动历史、消息状态和网络解析三套逻辑。

本课仍由你亲手实现，不新增依赖。不实现工具调用、多会话、自动重试或完整推理状态回放。后续再把验证好的流合并到正式聊天。

## 2. 先看懂三层数据

```text
网络字节块（任意分块）
  → TextDecoder 保留未解完的 UTF-8 字节
  → SSE 分帧器积累完整行，以空行结束一条事件
  → JSON.parse 解析事件 data
  → 检查 type，提取 delta 或识别终态
  → IPC 增量事件 → React 函数式追加
```

一次 reader.read() 可能读到半个汉字、半条 JSON，也可能读到三条事件。不能把“一次读取”等同于“一条事件”。

典型 SSE 内容（示意，省略其他协议字段）：

```text
event: response.output_text.delta
data: {"type":"response.output_text.delta","delta":"你好"}

event: response.completed
data: {"type":"response.completed","response":{"status":"completed"}}

```

这里是 HTTP 响应体持续到达，采用 SSE 格式，不是 WebSocket。前端 Vue/React 的区别不影响网络格式；React 仍用第七课的 useEffect 订阅和 setOutput(previous => previous + delta)。

| 信号 | 本课处理 |
|---|---|
| response.output_text.delta | 追加一段可见文字 |
| response.output_text.done | 某段文字结束，不把其中完整文本再追加一次 |
| response.completed | 整次响应成功终态，校验状态和已收到的文字 |
| response.failed / response.incomplete / error | 标为失败，保留已显示的部分文字 |
| reader.read() 的 done=true | 仅代表字节流结束；没收到 completed 就是提前断流 |

“读完网络”与“模型成功完成”是两件事。停止也不是成功完成。

## 5. SSE：先拼成完整事件，再解析 JSON

新建 src/main/sse.ts，写入下面整个代码块。先理解分帧器，再读网络循环。

```ts
export class StreamError extends Error {}

export class SseParser {
  private line = ''
  private data: string[] = []
  private skipLF = false
  private frameSize = 0

  push(text: string): string[] {
    const frames: string[] = []
    const endLine = (): void => {
      if (this.line === '') {
        if (this.data.length > 0) frames.push(this.data.join('\n'))
        this.data = []
        this.frameSize = 0
      } else if (this.line === 'data' || this.line.startsWith('data:')) {
        const value = this.line === 'data' ? '' : this.line.slice(5)
        this.data.push(value.startsWith(' ') ? value.slice(1) : value)
      }
      this.line = ''
    }

    for (const char of text) {
      if (this.skipLF) {
        this.skipLF = false
        if (char === '\n') continue
      }
      this.frameSize++
      if (this.frameSize > 1_000_000) throw new StreamError('单条流事件过大。')
      if (char === '\r') {
        endLine()
        this.skipLF = true
      } else if (char === '\n') {
        endLine()
      } else {
        this.line += char
      }
    }
    return frames
  }
}

function isRecord(value: unknown): value is Record<string, unknown> {
  return typeof value === 'object' && value !== null && !Array.isArray(value)
}

export async function readResponseStream(
  body: ReadableStream<Uint8Array>,
  onDelta: (delta: string) => void
): Promise<void> {
  const reader = body.getReader()
  const decoder = new TextDecoder('utf-8', { fatal: true })
  const parser = new SseParser()
  let output = ''

  function accept(data: string): boolean {
    let event: unknown
    try { event = JSON.parse(data) } catch {
      throw new StreamError('流事件不是有效 JSON。')
    }
    if (!isRecord(event) || typeof event.type !== 'string') {
      throw new StreamError('流事件格式不正确。')
    }
    if (event.type === 'response.output_text.delta') {
      if (typeof event.delta !== 'string') throw new StreamError('文字片段格式不正确。')
      if (output.length + event.delta.length > 100_000) {
        throw new StreamError('回复超过本课显示长度上限。')
      }
      output += event.delta
      onDelta(event.delta)
    } else if (event.type === 'response.completed') {
      if (!isRecord(event.response) || event.response.status !== 'completed') {
        throw new StreamError('完成事件的状态不正确。')
      }
      if (!output.trim()) throw new StreamError('响应完成，但没有可显示的文字。')
      return true
    } else if (event.type === 'response.failed' ||
               event.type === 'response.incomplete' || event.type === 'error') {
      throw new StreamError('模型未完整完成回复，请重试。')
    } else if (event.type === 'response.refusal.delta' ||
               event.type === 'response.refusal.done') {
      throw new StreamError('模型未提供本课要求的文字回答。')
    }
    return false
  }

  try {
    while (true) {
      const { value, done } = await reader.read()
      const text = done ? decoder.decode() : decoder.decode(value, { stream: true })
      for (const data of parser.push(text)) {
        if (accept(data)) return
      }
      if (done) throw new StreamError('连接已结束，但没有收到完成事件。')
    }
  } finally {
    try { await reader.cancel() } catch { /* 已断开或已取消时允许清理失败 */ }
    reader.releaseLock()
  }
}
```

逐项理解：

- parser 实例跨多次 push 保留半行和 data 行；空行才交付完整 data。多条 data 行用换行拼接。
- LF、CRLF 和 CR 都能分行；skipLF 处理 CRLF 恰好被拆到两个网络块的情况。注释行和 event/id/retry 字段不放进 data，本课以 JSON 内的 type 为准，不实现自动重连。
- TextDecoder 的 stream: true 保留没解完的字节；最后 decode() 刷出尾部。损坏的 UTF-8 会报错。
- response.output_text.done 含完整文字时也不能重复追加。本课只追加 delta。
- 有了 completed 就可以结束读取，不必等服务端关闭连接；finally 取消剩余读取并释放 reader 锁。
- 协议残缺时不“猜测成功”。没有空行结尾的半条事件也不能当完整事件使用。
- 1,000,000 的帧限制和 100,000 的输出长度限制是教学资源边界，不是模型 token 配额。

本课只实现单次 HTTP SSE 读取器，不是通用 EventSource 客户端。只有 [DONE] 而没有 Responses 完成事件的网关不满足本课约定，不能删除终态检查来掩盖不兼容。

## 6. 主进程：请求、超时与停止

新建 src/main/model-stream.ts：

```ts
import { BrowserWindow, ipcMain } from 'electron'
import type { IpcMainInvokeEvent } from 'electron'
import type { ModelStreamResult } from '../shared/api'
import { readResponseStream, StreamError } from './sse'

type Job = { requestId: string; cancel: () => void }
const jobs = new Map<number, Job>()

function checkSource(event: IpcMainInvokeEvent): void {
  if (!BrowserWindow.fromWebContents(event.sender) ||
      event.senderFrame !== event.sender.mainFrame) {
    throw new Error('不支持的真实流来源')
  }
}

function validId(value: unknown): value is string {
  return typeof value === 'string' && /^[a-zA-Z0-9-]{1,80}$/.test(value)
}

export function registerModelStream(): void {
  ipcMain.handle('model-stream:start', async (
    event, requestId: unknown, content: unknown
  ): Promise<ModelStreamResult> => {
    checkSource(event)
    if (!validId(requestId) || typeof content !== 'string' ||
        !content.trim() || content.length > 200) {
      return { status: 'error', error: '请输入 1～200 个字符，并提供有效请求标识。' }
    }
    const sender = event.sender
    if (jobs.has(sender.id)) return { status: 'error', error: '请等待当前真实流任务结束。' }
    const endpoint = process.env.MODEL_ENDPOINT
    const model = process.env.MODEL_NAME
    const apiKey = process.env.MODEL_API_KEY
    if (!endpoint || !model || !apiKey) {
      return { status: 'error', error: '请配置模型地址、名称和密钥，再重启调试。' }
    }
    try {
      if (new URL(endpoint).protocol !== 'https:') throw new Error('协议不支持')
    } catch {
      return { status: 'error', error: '模型地址必须是有效的 HTTPS 地址。' }
    }

    const controller = new AbortController()
    let timedOut = false
    function cancel(): void { controller.abort() }
    const timer = setTimeout(() => {
      if (controller.signal.aborted) return
      timedOut = true
      controller.abort()
    }, 60_000)

    jobs.set(sender.id, { requestId, cancel })
    sender.once('destroyed', cancel)
    sender.once('did-start-loading', cancel)
    sender.once('render-process-gone', cancel)

    try {
      const response = await fetch(endpoint, {
        method: 'POST',
        redirect: 'error',
        headers: {
          'Content-Type': 'application/json',
          Accept: 'text/event-stream',
          Authorization: `Bearer ${apiKey}`
        },
        body: JSON.stringify({
          model,
          input: [{ role: 'user', content: content.trim() }],
          stream: true,
          store: false
        }),
        signal: controller.signal
      })

      if (!response.ok) {
        await response.body?.cancel()
        return { status: 'error', error: `模型请求失败（HTTP ${response.status}）。请检查配置、额度或服务状态。` }
      }
      const mime = response.headers.get('content-type')?.split(';')[0].trim().toLowerCase()
      if (mime !== 'text/event-stream' || !response.body) {
        await response.body?.cancel()
        return { status: 'error', error: '服务未返回 SSE，请确认网关支持 Responses 流式接口。' }
      }

      await readResponseStream(response.body, (delta) => {
        if (controller.signal.aborted || sender.isDestroyed()) throw new Error('任务已取消')
        sender.send('model-stream:delta', { requestId, delta })
      })
      if (controller.signal.aborted) throw new Error('任务已取消')
      return { status: 'done' }
    } catch (error: unknown) {
      if (timedOut) return { status: 'error', error: '请求超过 60 秒，已停止等待。' }
      if (controller.signal.aborted) return { status: 'cancelled' }
      return {
        status: 'error',
        error: error instanceof StreamError ? error.message : '网络请求或流读取失败，请重试。'
      }
    } finally {
      clearTimeout(timer)
      controller.abort()
      jobs.delete(sender.id)
      sender.removeListener('destroyed', cancel)
      sender.removeListener('did-start-loading', cancel)
      sender.removeListener('render-process-gone', cancel)
    }
  })

  ipcMain.handle('model-stream:cancel', (event, requestId: unknown) => {
    checkSource(event)
    if (!validId(requestId)) throw new Error('请求标识不正确')
    const job = jobs.get(event.sender.id)
    if (job?.requestId === requestId) job.cancel()
  })
}
```

在 main/index.ts 顶部加入导入，并在现有 registerMockStream() 旁调用一次：



停止请求触发 abort，但 jobs 要到 fetch/读取循环真正退出、finally 执行后才释放。cancel 的确认不等于清理全部结束，React 仍等待 start 的结果。

60 秒是从发请求到完成的总时限，包括等待响应头和读响应体，不是“60 秒没收到文字才超时”。先不加自动重试，避免重复请求和费用。abort 只中止本地网络等待，不保证服务商停止计算或不计费。

StreamError 只包含本地定义的提示；不把网关原始错误体、请求头、密钥或完整异常转给页面。模拟任务、旧的非流式聊天与本课有各自的并发限制，尚未合并为全局请求队列；验收时一次只使用一个真实请求入口。

## 7. preload：复用已经学过的桥接模式

在 preload/index.ts 的 api 内追加三个方法，不删除模拟方法。已有 IpcRendererEvent 导入可以复用：

```ts
startModelStream: async (requestId, content) => {
  const result: unknown = await ipcRenderer.invoke('model-stream:start', requestId, content)
  if (typeof result === 'object' && result !== null && 'status' in result) {
    if (result.status === 'done' || result.status === 'cancelled') {
      return { status: result.status }
    }
    if (result.status === 'error' && 'error' in result && typeof result.error === 'string') {
      return { status: 'error', error: result.error }
    }
  }
  throw new Error('真实流结束结果格式不正确')
},
cancelModelStream: async (requestId) => {
  await ipcRenderer.invoke('model-stream:cancel', requestId)
},
onModelDelta: (listener) => {
  const handler = (_event: IpcRendererEvent, value: unknown): void => {
    if (typeof value !== 'object' || value === null ||
        !('requestId' in value) || typeof value.requestId !== 'string' ||
        !('delta' in value) || typeof value.delta !== 'string') return
    listener({ requestId: value.requestId, delta: value.delta })
  }
  ipcRenderer.on('model-stream:delta', handler)
  return () => { ipcRenderer.removeListener('model-stream:delta', handler) }
}
```

方法通道名必须与 main 完全一致。依然用原 handler 移除订阅，依然不把 Electron 事件对象暴露给 React。

## 9. 先离线检查分块，再验证网关

执行 npm run typecheck。下面是可以在本地测试脚本中构造的数据，不需要网络或密钥：

```ts
const sample =
  'data: {"type":"response.output_text.delta","delta":"你🙂"}\r\n\r\n' +
  'data: {"type":"response.output_text.done","text":"你🙂"}\r\n\r\n' +
  'data: {"type":"response.completed","response":{"status":"completed"}}\r\n\r\n'
const bytes = new TextEncoder().encode(sample)
const body = new ReadableStream<Uint8Array>({
  start(controller) {
    for (const byte of bytes) controller.enqueue(Uint8Array.of(byte))
    controller.close()
  }
})
let output = ''
await readResponseStream(body, (delta) => { output += delta })
// 应得到“你🙂”，没有乱码，也没有因为 output_text.done 重复追加。
```

此代码放在你自己的测试入口并导入 readResponseStream；不要贴进应用启动流程。每个字节单独一块是刻意制造最苛刻的拆分。

| 本地实验 | 预期 |
|---|---|
| 所有事件一次入队 | 能处理同一块内的多条事件 |
| 每字节一块 | 汉字、emoji、CRLF 都正确 |
| 多行 data 与注释心跳 | 空行才输出事件，注释不变成文字 |
| 删掉 completed 再关闭 body | 报提前结束，不显示成功 |
| 改为 response.failed 或 response.incomplete | 显示失败，保留已到达文字 |
| 损坏 JSON 或 delta 不是字符串 | 报格式错误并释放 reader |
| completed 已到达但服务器不主动关闭 | 能主动清理读取并结束任务 |

完整停止 Debug All 后 F5 重启，再进行少量真实验收：

1. 短问题能逐步显示并最终“已完成”。网关可能缓冲，几段一起出现不一定是前端 bug；先用断点确认事件确实分批到达。
2. 生成中停止：显示“已停止”后文字不再变化，之后可以再次开始。
3. 生成中卸载、重挂载：旧请求取消，旧片段不会进入新组件。
4. 错误配置时显示 HTTP 或 SSE 提示，恢复配置后可再次请求。
5. 本地模拟无响应来验证超时及 cleanup；不要靠反复真实请求凑超时场景。

60 秒没有收到任何文字时可能仍在服务端排队或生成，但本课会按总时限取消。暂停断点会影响计时观察，不在长时间暂停时判断超时机制。

8. 为什么本课真实流区不能直接当成已经完成的多轮流式聊天？

网络块、SSE 事件、delta 是三个层次。
- 网络块：一次读取拿到的一批字节，可能只有半条事件，也可能有多条事件。
- SSE 事件：按格式拼完整的一条消息，可以表示文字增量、完成或失败。
- delta：文字增量事件里的新增文字。
SSE 本身不负责等待对话或执行工具。

**TextDecoder 的 stream: true 是为了保留没解完整的字节。**例如“你”的 UTF-8 编码占三个字节，这次只收到两个，就先保留，等下次收到第三个再解码，避免乱码。它和请求里的 stream: true 含义不同。

**response.output_text.done 只表示某段文字结束，整次响应可能尚未完成。**之前的 delta 已经逐段拼出了完整文字，再追加 done 里的全文就会重复。整次成功看 response.completed。

**reader.read() 的 done=true 表示字节流结束。**它不是“某个文字块完成”，也不证明模型成功；网络中途断开，同样可能结束读取。

“依次停止”还需要明确机制：
点击停止 → 主进程 abort()
→ 网络读取退出 → reader 清理
→ 主进程 finally 清理任务与计时器
→ start Promise 返回 cancelled
→ 页面显示已停止

前半句接近：总超时是这一次请求从开始到结束的总时间，不是整个多轮对话的持续时间。“多久没收到数据”则统计连续无数据的时间；原因可能是排队、网络、网关缓冲，不一定是服务器卡住。

要更具体：**HTTP 200 只说明 HTTP 层成功返回。**响应体仍可能格式错误、包含 response.failed，或者传到一半断开，所以还要检查内容和最终事件。

**正确。**本课只发送当前一句话；尚未接入正式聊天的 messages/history，也没处理正式聊天中未完成回复的状态。
