## 1. 这十一课完成了什么进阶？

第22–33课建立了受控修改、命令批准和任务生命周期，第34–44课把这些能力接到日常聊天体验中：空白工作台能直接发送，会话可以管理，输入与回复展示逐步对齐 Codex，工作区和附件成为可选上下文，本地文件与命令统一经过运行范围和权限策略。

本阶段可以分为三段：

- 第34–38课：收口首次发送、会话管理、草稿、标题、错误和安全重试。
- 第39–42课：接通项目上下文，整理附件与回复展示，统一主 Agent 指令和工具构造。
- 第43–44课：提供默认运行目录，统一相对/绝对路径与执行权限，接通三种授权模式和自动审批。

## 3. 当前应用的完整使用链路

### 从输入到回答

空白工作台发送时先创建会话并捕获本轮身份；已有会话则沿用该会话。输入框只在发送被接受后清空草稿，异步失败保留消息和任务记录。首次发送先显示本地标题，独立标题请求成功且来源仍有效时才更新为 AI 标题。

聊天只有一个请求入口，工作区与附件均为可选上下文：

```text
输入与当前会话
  → 可选工作区、可选已授权附件
  → 主进程确定运行目录、权限和本轮工具
  → Responses SSE 与工具循环
  → 参数、来源、范围和审批检查
  → 实际执行及结果回传
  → 真实工具活动、回答正文与消息终态
  → 保存消息、合法工具历史和任务展示记录
```

主进程仍是任务状态和实际执行的权威。页面的忙碌状态用于交互互斥，不能代替主进程宣布完成、失败或取消。

### 没有工作区时为什么仍能创建文件？

每个无项目会话都有稳定的默认目录：`userData/chats/<conversationId>/workspace`。同一会话复用目录，不同会话分开；选择并授权工作区后，本轮使用该工作区作为运行目录。

同一套本地工具处理相对和绝对路径。相对路径按本轮运行目录解析，绝对路径指向明确目标，再由权限策略决定是否需要批准。写入某个绝对目标不会自动切换聊天工作区，也不会产生永久的路径授权。

### 三种授权模式现在分别做什么？

下表描述当前没有 Windows 命令 OS 沙箱时的实际行为。三种模式都沿用文件格式、容量、路径、冲突和来源检查。

| 模式                          | 有效可写范围内新建/编辑 | 范围外新建/编辑                                | 当前非沙箱命令                                 |
| ----------------------------- | ----------------------- | ---------------------------------------------- | ---------------------------------------------- |
| 请求批准（`default`）         | 直接执行                | 请求本次人工批准                               | 请求本次人工批准                               |
| 帮我批准（`auto-approve`）    | 直接执行，不额外评估    | 独立评估；仅严格的 `safe` 自动批准，其余转人工 | 独立评估；仅严格的 `safe` 自动批准，其余转人工 |
| 完全访问权限（`full-access`） | 直接执行                | 直接执行                                       | 直接执行                                       |

权限设置由主进程按窗口管理，页面刷新后回读实际状态，窗口关闭时清理。它不写入会话历史；恢复旧聊天不能恢复旧批准。

“帮我批准”的评估只接收已验证的本轮用户任务和这一笔具体操作，不调用副作用工具，不把整个聊天历史当作授权。输入或结果无法确认、评估异常或30秒超时，复用原人工批准弹窗。评估期间取消或权限失效后，迟到结果不能继续执行或弹出新批准请求。

人工弹窗位于输入框上方，与输入框等宽，取消和确认位于右下角。文件审批显示原因、操作和完整目标路径；命令审批显示原因、工作目录和可读命令。文件全文不在弹窗展示，独立评估仍需要这笔操作的新建内容或修改前后内容。

旧 `npm_typecheck` 提案缺少可信的原始用户任务，因此在自动模式下仍转人工批准。启动前继续复核目录身份、`package.json`、`.npmrc`、权限版本、页面和来源，不能把准备记录当作永久执行许可。

## 5. 复习时优先掌握的工程能力

### 状态归属比组件数量更重要

会话库管理可持久化消息，输入组件管理草稿，主进程管理授权和任务。Vue 的计算属性可以对应 React 的派生值，实例状态可以对应 `ref`；不能把每份状态都复制进 `useState` 或 `useEffect`。第38课的状态条就是已有事实的展示，不是另一套任务状态源。

### 接受请求与完成任务是两个时刻

发送被同步拒绝，保留原草稿；发送已被接受后失败，保留失败消息和任务。只有真正被接受才清空输入，只有执行结果和终态事件才能说明完成。

### 异步结果必须回到原来的对象

标题和聊天回调都要携带会话、请求及来源身份。标题结果回来时，既要核对请求代次，也要核对用户是否已经重命名。切换会话、归档、刷新或清空后，旧结果不能更新当前选中的其他会话。

### 项目指令、工具能力和执行权限分别判断

`AGENTS.md` 是不可信的项目上下文，不能扩大工具清单或批准操作。`ToolScope` 用于本轮工具和协议历史隔离；运行目录、权限版本和一次批准由主进程检查。统一请求入口不等于无条件开放能力。

### 批准之后仍要重新检查

人工或模型批准仅适用于当前具体操作。等待期间文件、目录配置、权限或来源可能变化，执行器仍须复核。自动批准不能绕过“完整读取后编辑”、哈希冲突、新建不覆盖及取消检查。

### 重试先判断是否已经影响外部状态

只读请求失败可以在来源仍有效时创建新任务重试；文件或命令副作用开始后，旧请求不能直接重放。批准记录也会收紧重试，结果不确定时要先核对实际状态。刷新能恢复展示，不恢复旧批准、原始重试来源或进程句柄。
