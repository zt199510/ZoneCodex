# 第七课：模拟流与停止生成

## 1. 目标和起点

新增一个独立的“模拟流练习区”：输入一句话后，主进程每隔 150 毫秒推送一个文字片段，页面逐段追加；可以停止，停止后不再追加；卸载练习区时清理监听器和主进程定时器。

第六课已收到完成反馈，上一轮 Node、Web 类型检查均通过。本次核对源码：App 已实现上下文与清空、页面文案已改为“多轮文本问答”。真实模型聊天沿用原代码，本课的练习区使用独立输出状态，不把模拟回复混进真实聊天历史。

本课不连接模型、不安装依赖、不读取密钥。它模拟“分批到达”的行为，不实现 HTTP 流解析，也没有 WebSocket。学会生命周期之后，下一课再把数据来源换成真实流。

## 2. 先分清两种返回

第五课的 invoke 一次返回完整文字。本课保留 Promise 表示“整次任务何时结束”，另外通过事件接收中间片段：

```text
React 先订阅片段事件
  → startMockStream(requestId, content)
  → main 启动定时器
  → 多次发送 delta 事件 → React 多次追加文字
  → 完成、停止或出错 → 清理定时器 → start 的 Promise 返回最终状态

点击停止 → cancelMockStream(requestId) → main 结束对应任务
```

| 数据 | 用途 |
|---|---|
| requestId | 区分每一次生成，拒绝旧任务片段 |
| delta | 本次新增的一小段文字 |
| start 的最终结果 | done、cancelled 或 error，决定界面结束状态 |
| 取消方法的返回 | 主进程已处理取消请求，不代表必须显示“已停止”：任务可能刚好已完成 |

useEffect 在这里管理外部事件订阅。可以联想到 Vue 的挂载订阅、卸载取消，但不要把 useEffect 当成自动发送函数；请求仍由用户提交触发。

## 5. 主进程：可结束的模拟任务

新建 src/main/mock-stream.ts，完整写入：

```ts
import { BrowserWindow, ipcMain } from 'electron'
import type { IpcMainInvokeEvent } from 'electron'
import type { MockResult } from '../shared/api'

type Job = { requestId: string; cancel: () => void }
const jobs = new Map<number, Job>()

function checkSource(event: IpcMainInvokeEvent): void {
  if (!BrowserWindow.fromWebContents(event.sender) ||
      event.senderFrame !== event.sender.mainFrame) {
    throw new Error('不支持的模拟流来源')
  }
}

function validId(value: unknown): value is string {
  return typeof value === 'string' && /^[a-zA-Z0-9-]{1,80}$/.test(value)
}

export function registerMockStream(): void {
  ipcMain.handle('mock:start', (event, requestId: unknown, content: unknown) => {
    checkSource(event)
    if (!validId(requestId) || typeof content !== 'string' ||
        !content.trim() || content.length > 200) {
      return { status: 'error', error: '请输入 1～200 个字符，并提供有效请求标识。' }
    }
    const sender = event.sender
    if (jobs.has(sender.id)) {
      return { status: 'error', error: '这个窗口还有模拟任务正在进行。' }
    }

    return new Promise<MockResult>((resolve) => {
      const chars = Array.from(`模拟回复：我收到了“${content.trim()}”。这些文字正在分段到达。`)
      let index = 0
      let ended = false
      let timer: ReturnType<typeof setInterval> | undefined

      function finish(result: MockResult): void {
        if (ended) return
        ended = true
        if (timer !== undefined) clearInterval(timer)
        jobs.delete(sender.id)
        sender.removeListener('destroyed', cancel)
        sender.removeListener('did-start-loading', cancel)
        sender.removeListener('render-process-gone', cancel)
        resolve(result)
      }

      function cancel(): void {
        finish({ status: 'cancelled' })
      }

      jobs.set(sender.id, { requestId, cancel })
      sender.once('destroyed', cancel)
      sender.once('did-start-loading', cancel)
      sender.once('render-process-gone', cancel)

      timer = setInterval(() => {
        if (sender.isDestroyed()) {
          cancel()
          return
        }
        try {
          sender.send('mock:delta', { requestId, delta: chars[index] })
          index++
          if (index === chars.length) finish({ status: 'done' })
        } catch {
          finish({ status: 'error', error: '模拟片段发送失败。' })
        }
      }, 150)
    })
  })

  ipcMain.handle('mock:cancel', (event, requestId: unknown) => {
    checkSource(event)
    if (!validId(requestId)) throw new Error('请求标识不正确')
    const job = jobs.get(event.sender.id)
    if (job?.requestId === requestId) job.cancel()
  })
}
```

在 main/index.ts 顶部导入，在 app.whenReady().then(...) 内、createWindow() 之前调用一次：

```ts
import { registerMockStream } from './mock-stream'
```

```ts
registerMockStream()
```

理解这段代码后再往下走：

- Map 的 key 是发起请求的窗口 WebContents ID，一个窗口同时只有一个模拟任务。
- requestId 匹配后才取消。旧请求迟到的取消消息不能取消同一窗口的新任务，也不能取消别的窗口任务。
- finish 集中清理定时器、Map 和三个窗口监听器，然后完成 start Promise。ended 保证多次结束只执行一次。
- 成功也要清理，不能只在“停止”时清理。
- 窗口销毁、加载或渲染进程退出时取消任务。本课采用保守的加载清理策略，适用于当前本地单窗口页面。
- Array.from 按 Unicode 码点拆分，普通 emoji 不会拆成两个代理项；复杂组合 emoji 仍可能分成多个片段。真实流片段也不等于单个字符或 token。

不要只 resolve 而不 clearInterval，否则 Promise 已结束，后台仍在运行。

## 6. preload：隐藏 Electron 事件对象

在 preload/index.ts 顶部增加类型导入：

```ts
import type { IpcRendererEvent } from 'electron'
```

在现有 api 对象里追加以下属性，保留前面的 selectFolder 和 askModel，注意属性之间的逗号：

```ts
startMockStream: async (requestId, content) => {
  const result: unknown = await ipcRenderer.invoke('mock:start', requestId, content)
  if (typeof result === 'object' && result !== null && 'status' in result) {
    if (result.status === 'done' || result.status === 'cancelled') {
      return { status: result.status }
    }
    if (result.status === 'error' && 'error' in result &&
        typeof result.error === 'string') {
      return { status: 'error', error: result.error }
    }
  }
  throw new Error('模拟流结束结果格式不正确')
},
cancelMockStream: async (requestId) => {
  await ipcRenderer.invoke('mock:cancel', requestId)
},
onMockDelta: (listener) => {
  const handler = (_event: IpcRendererEvent, value: unknown): void => {
    if (typeof value !== 'object' || value === null ||
        !('requestId' in value) || typeof value.requestId !== 'string' ||
        !('delta' in value) || typeof value.delta !== 'string') return
    listener({ requestId: value.requestId, delta: value.delta })
  }
  ipcRenderer.on('mock:delta', handler)
  return () => { ipcRenderer.removeListener('mock:delta', handler) }
}
```

不把 Electron 的 _event 转交页面，只传校验后的业务数据。事件格式异常时丢弃；主进程最终结果仍是任务结束依据。

removeListener 必须拿到当初注册的同一个 handler。不要写一个新的箭头函数去删除，也不要 removeAllListeners，否则会误删其他组件的订阅。

## 7. React：订阅一次，逐段更新

新建 src/renderer/src/components/StreamPractice.tsx：

```tsx
import { useEffect, useRef, useState } from 'react'
import type { FormEvent } from 'react'

function StreamPractice(): React.JSX.Element {
  const [input, setInput] = useState('你好，模拟流')
  const [output, setOutput] = useState('')
  const [running, setRunning] = useState(false)
  const [ready, setReady] = useState(false)
  const [status, setStatus] = useState('尚未开始')
  const [error, setError] = useState<string | null>(null)
  const currentId = useRef<string | null>(null)
  const subscribed = useRef(false)

  useEffect(() => {
    const unsubscribe = window.api.onMockDelta((event) => {
      if (event.requestId !== currentId.current) return
      setOutput((previous) => previous + event.delta)
    })
    subscribed.current = true
    setReady(true)

    return () => {
      subscribed.current = false
      unsubscribe()
      const id = currentId.current
      currentId.current = null
      if (id !== null) {
        void window.api.cancelMockStream(id).catch(() => {
          // 组件已卸载，不再更新它的 UI；页面加载/窗口退出另有主进程清理。
        })
      }
    }
  }, [])

  async function start(): Promise<void> {
    const content = input.trim()
    if (!subscribed.current || currentId.current !== null || !content) return
    if (content.length > 200) {
      setError('请输入不超过 200 个字符的内容。')
      return
    }
    const id = crypto.randomUUID()
    currentId.current = id
    setOutput('')
    setError(null)
    setStatus('正在生成')
    setRunning(true)

    try {
      const result = await window.api.startMockStream(id, content)
      if (currentId.current !== id) return
      if (result.status === 'error') {
        setError(result.error)
        setStatus('生成失败')
      } else {
        setStatus(result.status === 'done' ? '已完成' : '已停止')
      }
    } catch {
      if (currentId.current === id) {
        setError('模拟流通信失败，请重试。')
        setStatus('生成失败')
      }
    } finally {
      if (currentId.current === id) {
        currentId.current = null
        setRunning(false)
      }
    }
  }

  async function stop(): Promise<void> {
    const id = currentId.current
    if (id === null) return
    try {
      await window.api.cancelMockStream(id)
    } catch {
      if (currentId.current === id) setError('停止请求失败，请等待任务结束。')
    }
  }

  function handleSubmit(event: FormEvent<HTMLFormElement>): void {
    event.preventDefault()
    void start()
  }

  return (
    <section aria-label="模拟流练习">
      <h2>模拟流练习</h2>
      <p>本区域只生成本地模拟文字，不请求模型。</p>
      <form onSubmit={handleSubmit}>
        <label htmlFor="mock-input">练习内容</label>
        <input id="mock-input" value={input} maxLength={200} disabled={running}
          onChange={(event) => setInput(event.currentTarget.value)} />
        <button type="submit" disabled={!ready || running || !input.trim()}>
          开始模拟
        </button>
        <button type="button" disabled={!running} onClick={() => { void stop() }}>
          停止生成
        </button>
      </form>
      <p role="status">{status}</p>
      <p style={{ whiteSpace: 'pre-wrap' }}>{output || '这里将显示分段回复。'}</p>
      {error && <p role="alert">{error}</p>}
    </section>
  )
}

export default StreamPractice
```

分三遍阅读：

1. 先读 Effect：订阅完成才允许开始；清理时取消订阅、使旧 ID 失效，并请求主进程停止。
2. 再读 delta 回调：ID 匹配才追加，使用函数式 setOutput，避免读取旧 output 快照而丢片段。Effect 不依赖 output，所以不会每来一个片段就重新订阅。
3. 最后读 start/stop：停止按钮只请求取消；start 的最终结果负责恢复界面。主进程处理停止前可能已经有片段在路上，所以允许“点击后、确认已停止前”再到达少量片段；显示已停止后不应继续变化。

不要在 stop 中立即把 running 设为 false、允许新请求抢跑。自然完成与停止同时发生时，以主进程最终状态为准，显示已完成也可能是正确结果。

React 开发环境可能执行一次额外的 Effect 设置与清理。正确的清理函数确保之后仍只有一个有效订阅。本例卸载时先把 currentId 置空，旧 Promise 回来后也不会更新已卸载的练习区。

本地模拟任务长度有上限，会自然结束；异常到无法通信时可以完整重启。未来真实网络任务仍需超时与断线策略，不能只照搬本课的定时器。

## 9. 验证错误与资源清理

运行 npm run typecheck，停止 Debug All 后完整 F5 重启。只刷新页面不会保证新主进程处理器已注册。

| 实验 | 预期 |
|---|---|
| 正常生成 | 文字分段追加，结束后显示已完成，开始按钮恢复 |
| 停止 | 显示已停止后等待至少 1 秒，输出不再变化，部分文字保留 |
| 再次开始 | 输出清空，新任务正常追加，没有旧片段混入 |
| 连续点停止 | 不报错，不取消下一次任务 |
| 生成中卸载 | 后台定时器清理；重新挂载后可再次开始 |
| 重复挂载/卸载 5 次 | 每个片段只追加一次，不出现重复字符或越来越快的增长 |
| 生成中刷新页面 | 主进程 loading 路径清理旧任务，新页面可再次开始 |
| 保留功能 | 第六课聊天与目录选择仍使用原来的逻辑 |

断点建议：主进程 sender.send、finish，以及 React 的事件 ID 判断。观察 jobs.size：启动后该窗口占一项，完成/取消/卸载清理后归零。不要只看到按钮恢复就认为定时器已经清理。

模拟失败实验：在主进程定时器 try 内、sender.send 前临时加入：

```ts
if (index === 5) throw new Error('学习用模拟故障')
```

完整重启后开始，应该先出现 5 个片段，再显示错误，主进程 jobs 清空，开始按钮恢复。删除实验行、重启，再验证正常结束。

旧 ID 实验可用本地测试或断点验证：任务 A 已结束、B 已开始时，传入 A 的取消 ID，B 应继续；主进程只匹配当前窗口和当前请求。不要为测试往其他任务或窗口发消息。
