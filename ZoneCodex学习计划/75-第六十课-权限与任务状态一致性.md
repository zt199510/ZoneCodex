## 1. 本课目标与前置条件

目标：让用户看见的权限选项、等待提示、停止按钮、消息/工具结果与真正的执行行为一致。能解释「拒绝一次操作」「停止整条任务」「重开历史」「显式继续任务」分别改变什么。

实施完成后应达到：

1. 权限名称/描述对应实际策略及执行后端，不能用一句「完全访问」替代当前路径、输入、文件和命令保护。
2. 分清窗口权限模式、工作区有效性、公开任务记录和UI操作状态；每一项有明确权威来源及映射。
3. 审批拒绝不自动等于整个任务取消；批准/问答响应只作用于当前一次等待。
4. 停止先请求执行方取消，再由执行方报告结果；界面不能在点击后直接伪写「实际已停止」。
5. 终态不被旧事件回退，未知权限不得带着旧mode/revision继续发送；恢复不复活旧批准或命令票据。
6. 开发/目录包桌面、开发/分发CLI分别验收，模型传输与真实进程/磁盘/界面分记；既有终端独立性保持。

### 1.1 创建时核对到的事实

| 维度 | 当前事实 | 本课处理方式 |
| ---- | -------- | ------------ |
| 权限模式 | `default` / `auto-approve` / `full-access`；纯策略返回allow/review/ask/deny | 冻结每种结果的调用链，再对齐文案；模型理由不是授权 |
| 桌面权限状态 | 按窗口保存mode/revision；模式实际变化才revision+1；主IPC在busy时拒绝切换 | 保留互斥，验证UI禁用和主进程拒绝一致 |
| CLI权限状态 | 单次运行捕获当前输入permission，默认default；revision=0，靠新run/request/scope身份隔离 | 不照搬桌面可切换的窗口状态；resume使用当前输入重新核验 |
| 公开任务记录 | `shared/task.ts`有九态；`task-registry`已定义允许转换及终态保护 | 核对真实发布/合并/保存，不新增第二套权威状态机 |
| 工作区状态helper | `project.ts`七态task、四态permission；`workspace-state.ts`纯helper当前未接入产品调用 | 先确认是否仍需要，再决定最小整理；不得写成已在管理运行任务 |
| 核心/CLI结果 | `AgentCoreOutcome`及公开CLI结果是较小的结果集合，并非九态实时任务流 | 明确映射和未暴露状态，不为凑相同枚举扩JSONL协议 |
| 实际界面 | 状态条、消息/工具展示、审批/问答、生成/停止/继续入口；尚无按九态逐项列出的任务管理面板 | 改现有呈现，不假设已有独立任务卡片或task取消按钮 |

### 1.2 明确不做

- 不扩权限、不删除执行器校验、沙箱/Job/文件冲突/原容量保护，不取消busy时的权限切换限制。
- 不恢复Agent整体时间上限；现有`timed_out`仍需按具体命令/局部期限解释。
- 不新增持久`stopping`、运行句柄、目录grant、读取凭据、approvalId或命令票据；必要「正在停止」只作当前请求的UI过程。
- 不新增并发任务、后台进程恢复、任务队列、自动resume或恰好执行一次保证。
- 不全面重做UI或复刻第30/33课；已有行为正确时保留并建立当前证据。
- 不把旧课失败、未覆盖、自测待答或原生资源未证明改写成全部通过。

## 2. 用 Vue 经验理解本课

| Vue中的经验 | 本课对应 | 必须分清 |
| ----------- | -------- | -------- |
| Store里的业务状态与组件loading分别存在 | 主进程TaskRecord与renderer Operation/局部stopping | 「保存中」不等于Agent任务running；UI发送取消不等于执行已结束 |
| Select绑定偏好，但提交前仍校验当前版本 | 权限菜单、mode/revision与ExecutionInfo | 图标和历史ExecutionInfo不是运行授权，读回失败不能猜测权限 |

| 请求序号挡旧响应 | approvalId、requestId、taskId、窗口/document、generation | 迟到的批准、问答、任务状态不能改当前新请求 |
| 刷新后恢复展示与重新发请求分别处理 | 历史中断记录、checkpoint元数据与显式resume | 只看历史零请求；点击继续才以新运行身份核验当前权限 |

例子：Agent等待某次文件修改批准，用户在审批面板点「取消」，这次文件不得修改；Agent可以收到拒绝结果继续说明。用户点「停止生成」才请求取消整条运行，并等待执行方报告结果。两者都不能因为迟到批准再执行，用户独立终端继续存活。

## 4. 按依赖顺序实施与练习

整课按§4A/§4B交付。每步先记录现状与差异，再做必要改动；不得把本课创建记录当实施完成。

### §4A 阶段：冻结权限、任务与界面的合同

#### 步骤一：基线与四个状态维度

1. 新UUID保存当前源码/产物身份、Git未提交补丁与用户数据基线；保留第59未提交优化、node-pty字节锁定补丁、工作目录及旧证据，不提交或reset。
2. 画出四个维度：窗口mode/revision、运行ExecutionContext/scope有效性、TaskRecord、UI Operation/局部stopping。
3. 标出桌面与CLI各自owner、核心结果投影、谁发布/保存、谁只展示；盘点未调用helper，不从旧课假定产品正在使用它。
4. 默认`npm test`及本课会受影响的旧suite先作为行为锁；记本轮实际结果，不引用旧UUID冒充新通过。

**预期效果：** 找到权威状态及真实调用链。  
**常见错误：** 把九态TaskRecord、七态workspace或CLI结果直接强制合并为一个枚举。

#### 步骤二：冻结权限语义与读回合同

1. 建立三模式×read/write/command×范围/后端的表；纯策略的allow/review/ask/deny与实际执行是否成功分列。
2. 对照各真实调用者：文件路径的`localPermission`当前传入sandboxAvailable=false；命令另外走具体后端准备、授权及执行核验。不能凭纯策略一次allow宣称任意读写/联网可用。
3. 模式同值revision不变；桌面实际切换才+1；default→full-access→default虽恢复同一mode，旧revision仍失效。busy切换在UI和主IPC均拒绝，mode/revision/任务保持。忙碌失效测试可注入旧context，不为测试新增可切权限入口。
4. 切换已被main接受但回包失败：renderer先进入未知状态，再读回实际mode/revision；未知或持续读回失败时禁发，不拿旧状态乐观继续。
5. CLI单次权限不可变、revision=0，新run/scope隔离；resume按当前输入（默认default）重新核验，不能从历史恢复模式或批准。
6. 权限菜单读取/普通选择本身不启动Agent主/摘要/title/approval请求。auto-approve在实际风险操作中的审核请求另计，不误写成权限菜单触发请求。

**预期效果：** 文案、互斥和真实策略对应。  
**常见错误：** 「帮我批准」写成永不询问，或把full-access写成绕过原执行保护。

#### 步骤三：冻结等待、拒绝、取消与恢复

| 情境 | 必须冻结并核对的合同 |
| ---- | ------------------- |
| 单次审批拒绝/Escape | respond(false)，只拒绝该操作；不直接等同任务取消。Agent路径由工具/owner解释后续；独立命令入口按当前失败结果展示 |
| 提案完成后等待执行交接 | `propose_command`可使核心done结果对应waiting_approval，与当前broker正在等待一次批准不同；分别核对提案/执行入口，不把done一律映射成已执行完成 |
| 等待审批/问答时停止整任务 | 当前等待被清理，响应只能用于原ID/document；取消后迟到批准/回答不得重开等待、恢复running或造成副作用 |
| 运行中停止 | 本地显示「正在停止」或等价过程，调用现有取消链；owner确认结果才发布终态。取消发送失败/执行失败按事实展示，不伪称停止成功 |
| 解析运行上下文时停止 | 可结束本地占位，迟到resolve不得再startAgent；与已启动任务停止分开 |
| 上下文撤销/失效 | 旧scope/revision/读取证据及批准再核验失败，不产生新的写入/进程启动；已发生副作用不宣称自动回滚 |
| 终态与旧事件 | 按主进程允许转换和renderer当前任务身份核对；完成/取消/失败等终态不被旧非终态复活，已删除任务不被重新插入 |
| 被动重开/切会话 | 校准旧非终态为interrupted或读取续接元数据，主/摘要/title/approval/start/resume零请求；历史不恢复grant |
| 显式继续 | 当前目录/权限与checkpoint核验，以新运行task/request身份开始；稳定checkpoint任务标识可保留，不回退旧TaskRecord终态 |
| 独立终端 | 开/用终端零Agent调用、不授凭据；停止/拒绝/撤销Agent上下文不杀PTY、不把PTY写入raw/checkpoint |

审批清空事件、任务状态事件与请求结果是不同消息，不要求跨通道瞬时原子同到；允许短暂「收尾中」，但收敛后不得矛盾。终态名称只陈述owner已知的结果：窗口销毁的interrupted不证明整个进程树/原生句柄回收；任务completed不自动证明业务测试全部通过。第56容量与局部工具期限保持。

停止与批准的竞态分三种排列：停止先到，旧批准无新副作用；批准先到但commit/spawn尚未发生，取消/上下文失效仍须挡住副作用；副作用已经开始再停止，保留真实effects/raw与可能已执行的事实。一次命令票据领取/消费与重新核验不能退化成可重用boolean；不宣称取消会回滚已经完成的操作。

**预期效果：** 每个动作的身份、时序、公开结果及例外都有明确语义。  
**常见错误：** 把拒绝、取消、interrupted和checkpoint可继续混为一类，或在点击按钮时直接改持久终态。

### §4B 阶段：最小对齐、护栏与双宿主验收

#### 步骤四：对齐现有展示与事件映射

1. 按合同更新必要权限描述及等待/停止/中断提示，保留三个模式值、现有样式/键盘/焦点行为。
2. 必要时抽极小纯投影函数：输入已知权威状态与当前请求过程，输出标签、可发送/可停止/可继续等呈现；不在其中发IPC、请求模型或决定授权。
3. 任务记录、工具执行状态、UI加载/保存与checkpoint进度分别映射；旧纯helper无产品调用时不硬接成第二个状态中心。
4. 主进程和renderer各挡迟到/错窗口/旧任务/旧approvalId事件；跨层结果已一致时保留现有代码。
5. preload/shared协议优先保持；不新增持久字段和全局任务面板，不把CLI结果变成桌面实时TaskRecord流。

**预期效果：** 用户能分清等待什么、请求停止是否已收尾、继续任务会重新核验什么。  
**常见错误：** 为标签正确把授权逻辑搬进renderer，或靠UI禁用代替主进程核验。

#### 步骤五：建立有行为意义的合成护栏

1. 普通Node/隔离存储：三模式决策、桌面revision/busy与未知权限读回、owner状态允许转换/终态、核心/CLI投影。
2. 合成审批与执行：拒绝不发生该操作；等待取消→迟到批准/回答→无新副作用；批准→停止→commit/spawn与副作用→停止的排列分别记录；运行停止→迟到完成→终态不回退；旧ID/跨窗口/frame/重复回应不影响新等待或任务。
3. 测真实接线：renderer停止入口、审批回应与任务事件；工具write/process-start计数、主/审核请求计数、磁盘记录必须各自核对，不能只断言标签函数返回字符串。
4. 主已接受切换但renderer回包失败、持续读回失败、停止响应失败等故障独立标记；不靠缩短现有限额或改变测试预期通过。
5. 第60最少新增suite与调度在实施时落盘；保留默认第58组、第59独立终端组及选定续接/权限行为锁。旧失败仍留档。

另核对review未批准时的人工fallback，审核异常不得默认为批准；当前等待/pending监听与运行reservation按owner收尾，不为标签正确提早释放。审批过程中目录/目标/项目指令变化须在副作用前重新核验，失败保持原文件和坏checkpoint的真实证据。

**预期效果：** 合同可被反例推翻；正确的现有保护得到当前源的新证据。

| 显式继续 | 新request/task、当前目录/权限重新核验；旧TaskRecord终态和稳定checkpoint标识可保留，旧读取凭据/批准/命令票据不恢复 |

等待清空、任务事件和请求结果分通道到达，允许短暂收尾过程，最终按当前身份收敛。运行中cancelTask请求owner收尾；waiting状态在取消callback成功后可退休，失败保持未终结。窗口interrupted只说明旧显示/运行中断，不证明任意进程树或全部原生句柄回收；completed也不自动证明业务测试全过。
