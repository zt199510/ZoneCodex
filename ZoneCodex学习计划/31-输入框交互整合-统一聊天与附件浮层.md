# 输入框交互整合：统一聊天与附件浮层

日期：2026-09-17。接续[第 21 课后的工程整理](30-工程整理-项目上下文与工作台布局.md)，属于第 22 课前的产品交互调整。

## 1. 使用方式

正常使用只保留一个聊天输入框。点击左下角“＋”，在浮层中选择“添加文件”，直接打开可多选的文件选择器，不再先选择目录。

添加后，文件以卡片形式排列在输入框内部、文字输入区上方，卡片右上角可单独移除；菜单也提供全部移除。文件名过长时省略显示，悬停可查看完整名称。同名文件带区分标识。用户主动添加文件即授权当前会话使用这些附件；没有额外的发送许可勾选框。实际内容随发送问题后的工具调用交给模型，不会在选择文件时立即请求模型。

按用户参考图，浮层与整个输入框同宽，左右边缘对齐，底边贴着输入框上沿（间距 8px）；不再跟随“＋”按钮显示为窄菜单。菜单使用紧凑单行项目，附件卡片不放在菜单中。浮层使用原生 Popover 顶层显示，不占页面排版空间；点击外部、按 Esc 或点击关闭按钮可收起。短窗口限制浮层高度，附件卡片横向滚动。当前文本附件显示文件图标卡片，图片缩略图输入尚未接入。

## 2. 原来的三种回复模式去了哪里？

普通聊天、时间查询和附件读取不再要求用户预先选择。正常入口默认真实模型：普通问题可以直接回答，需要时间时模型调用时间工具，有附件时还能请求搜索和读取。

内部仍区分工具范围，供授权和历史校验使用：

| 当前上下文 | 可用工具 |
|---|---|
| 无附件 | get_current_time；也可以直接回答而不调用工具 |
| 有获准附件 | get_current_time、search_project_text、read_project_file |

**统一入口沿用工具循环，显示处理进度，最终答案在完成后一次提交。** 本次没有实现工具协议的流式增量解析。原来的纯文本逐字流式功能保留在“＋ → 开发调试 → 纯文本流式调试”，切换到它会撤销附件授权。

开发调试中也保留离线模拟：无附件固定查询时间，有附件固定搜索 greet。它用于排错，不代表能理解任意问题。离线模拟不会发送网络请求；切回真实模型后，仍可使用已添加的附件。

## 3. 文件选择和授权有什么变化？

| 操作 | 当前行为 |
|---|---|
| 首次添加 | 直接多选 1–8 个支持的文本文件 |
| 再次添加 | 合并到已有附件，仍受最多 8 个文件限制 |
| 再选同一个文件 | 保留其附件标识，重新读取所选文件，更新快照 |
| 取消或选择失败 | 保留此前完整附件、授权，不留下半份新快照 |
| 移除一个文件 | 从内存快照移除，生成新的 snapshotId；最后一个移除后清空授权 |
| 成功添加、更新或移除 | 沿用剩余已选文件的使用许可，下一轮不自动携带旧快照的协议历史 |
| 新建、切换或清空会话 | 先撤销当前附件授权 |
| 页面刷新、关闭或重启 | 附件授权失效；已保存记录仍可查看 |

不同目录里的同名文件使用 `file-UUID/文件名` 形式的唯一附件标识作为工具 path；页面通常显示文件名，同名时补充标识。这里的 path 是快照键，不是磁盘地址。主进程保存原文件身份用于去重，绝对磁盘路径不经 IPC 交给页面或模型。

选择器可以从不同目录分次添加；没有授予模型访问共同父目录或其他相邻文件的能力。主进程从文件系统根开始检查路径层级，保留对链接、硬链接、隐藏或阻断路径段、文件大小、编码和读取期间变化的检查。

当前支持 `.md .txt .ts .tsx .js .jsx .json .css .html`，单文件最多 32 KiB，全部最多 128 KiB。不支持图片、PDF、目录递归导入或写入文件。

## 4. 请求与历史边界

- 模型请求仍固定使用本次捕获的窗口、会话、模式和快照，不能由迟到回调重新解释。
- 工具执行与历史解析共用 `isToolAllowed`；无附件的范围不会接受文件工具调用。
- 项目范围现在允许组合时间与文件工具。循环上限调整为 5 次模型请求、4 次工具执行，仍有 90 秒超时以及原有输入、输出和存储体积限制。
- 同模式、同快照、连续成功轮次才能携带完整协议。增删附件、刷新快照或切换调试来源会形成历史边界；旧普通流式记录仍保留原来的筛选规则，不伪造成工具轮次。
- 文件选择进行中不能启动工具任务，任务进行中不能添加或移除文件。任务和授权统一按 BrowserWindow.id 归属，避免误把 webContents.id 当作窗口 ID。
- 会话库仍为版本 4，未新增持久字段；旧记录保持可读。项目范围的工具白名单有所扩展，包含新组合调用的记录不保证能被旧版本程序读取，不应直接降级打开唯一记录。

## 6. 验证与后续

`scripts/check-attachments.cjs` 用真实生产模块、临时文件和 Electron 替身检查文件快照、同名标识、路径限制、组合工具、历史和授权生命周期。`scripts/check-workspace.cjs` 使用正式 UI/preload 和内存业务替身检查浮层不移动布局、Esc/外部关闭、添加后直接发送、移除附件、调试切换和原有聊天保存流程。

真实模型服务未在本次调用。原生对话框的配置和快照流程通过替身与临时文件验证，窗口布局使用真实 Electron 截图核对；不等于实际用户文件与真实模型端到端验收。最新结果见[学习进度](04-学习进度.md)。
