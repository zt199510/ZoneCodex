## 4. 默认目录、三种权限与一次批准

### 默认运行目录

没有选择工作区时，主进程为当前会话解析并创建：

```text
Electron userData/chats/<conversationId>/workspace
```

选择有效工作区后，运行目录改为该工作区的真实路径。默认目录和工作区均需要目录身份/链接检查。历史 `cwd`、工作区描述与 `scopeId` 只描述已有记录，不能恢复执行许可。

证据：[运行上下文及默认目录](../src/main/execution/execution-context.ts)、[工作区授权](../src/main/project/workspace-access.ts)、[历史执行描述](../src/shared/execution.ts)。

### 三模式实际决策

下表指新版本地工具。当前运行根目录是本轮默认目录或已选工作区；“允许”仍要通过工具自身的路径、内容、身份和容量检查。

| 操作                 | 请求批准 `default` | 帮我批准 `auto-approve`                    | 完全访问 `full-access` |
| -------------------- | ------------------ | ------------------------------------------ | ---------------------- |
| 本地读取             | 直接允许           | 直接允许                                   | 直接允许               |
| 当前运行根目录内写入 | 直接允许           | 直接允许                                   | 直接允许               |
| 当前运行根目录外写入 | 人工批准本次操作   | 独立风险评估；严格 safe 才通过，其余转人工 | 直接允许               |
| 通用命令执行         | 人工批准本次操作   | 独立风险评估；必要时转人工                 | 直接允许               |

当前 `sandboxAvailable` 固定为 `false`，没有命令 OS 沙箱。设置 `cwd` 不隔离程序对其他文件、网络或子进程的访问。完全访问也不取消 UTF-8、文件大小、链接、文件身份、哈希等工具限制。

权限状态由窗口内存持有：切换模式递增 `revision`，任务进行中禁止切换；当前窗口刷新后回读仍保留模式，关闭窗口清除。权限不是 V6 会话文件中的持久授权。

证据：[权限纯规则](../src/shared/permission-policy.ts)、[权限状态](../src/main/execution/permission-state.ts)、[权限接口](../src/main/execution/execution-ipc.ts)。

### 自动评估与人工批准

风险评估接收已验证的本轮用户请求和精确待执行动作；文件正文、修改前后内容与命令参数都作为数据，不能改变评估规则。评估最多30秒，载荷最多128 KiB，输出文本最多256字符。

只有完整响应符合严格的 `{"risk":"safe"}` 语法才自动通过。重复字段、额外字段、解释、工具调用、异常、超时、未知响应或 risky 均转原人工批准浮窗；不能把一次真实模型的 safe 结果写死为某类命令的固定结论。

人工批准绑定窗口、当前页面、批准ID及精确操作，只能回应一次，不形成持久目录许可。停止、刷新、页面销毁、窗口关闭或上下文失效会取消；评估返回后、人工回应后和操作启动前仍要复核。取消后不能新弹窗或迟到启动。

旧 npm 提案缺少已验证的当前用户任务，因此 `auto-approve` 仍走人工批准；`full-access` 可以直接允许，目录检查及一次准备/确认继续生效。

证据：[风险评估器](../src/main/execution/approval-reviewer.ts)、[操作批准协调](../src/main/execution/action-authorization.ts)、[一次人工批准](../src/main/execution/execution-approval.ts)。

### 批准、执行与重试是不同结果

批准只表示本次操作取得许可，不证明文件或命令已经成功。原实现会在已批准或副作用开始后保守阻止自动重试；例如命令在启动前记录副作用后启动失败，也不能当作安全的“从未执行”轮次重试。

新建失败可能留下空文件/部分文件，替换尝试后的异常可能无法确定目标结果，必须保留 `uncertain` 等真实状态。不能把停止请求当作文件回滚或确认进程树退出。

证据：[Agent 运行及副作用标记](../src/main/agent/agent-runner.ts)、[文件/命令动作](../src/main/tools/workspace-actions.ts)、[前端重试保护](../src/renderer/src/features/chat/agent-request.ts)。

## 5. 文件、附件与项目指令的实现边界

### 文件读取与路径检查

- 拒绝 UNC/设备路径、ADS、Windows 保留设备名、控制字符以及尾点/尾空格等非法文件名；逐级检查并拒绝符号链接/目录联接，核对真实路径和目录/文件身份。
- 普通文件读取要求单硬链接 `nlink = 1`；打开句柄后复核身份，读取前后核对大小及时间等信息，严格验证 UTF-8。
- 本地读取单文件最多128 KiB、每次100行；搜索最多扫描2 MiB/200文件；列表最多250项、访问3000项、深度8；本地读取工具结果最多11000字符。
- 跳过 `.git`、`node_modules`、`dist`、`out`、`.ssh`、`.aws` 等目录和 `.env`、`.npmrc`、凭据/私钥等匹配文件。这里是代码中的规则集合，不是涵盖所有秘密文件的识别器。

证据：[本地路径检查](../src/main/tools/local-path.ts)、[本地读取工具](../src/main/tools/workspace-files.ts)。

### 新建与编辑

新建限80行/2000字符，编码最多32 KiB，父目录必须已存在。通过独占创建避免覆盖，写入后同步并回读字节、文件身份和父目录。出现写入后的失败返回未知结果，不能宣称磁盘没有变化。

编辑要求同一请求已完整读取目标小文件，并匹配 `expectedSha256`；原文、候选正文同样受80行/2000字符及32 KiB限制。保留 UTF-8 BOM 与 LF/CRLF 策略，混合换行/孤立CR不支持，候选正文不能自行首加 U+FEFF。

实际提交流程是原字节备份、同目录临时文件、同步、验证、最后权限门、替换和回读。原实现不提供与外部编辑器之间的原子比较交换保证；替换后异常不自动回滚目标，保留恢复备份并返回真实结果。

证据：[本地动作](../src/main/tools/workspace-actions.ts)、[完整读取许可](../src/main/agent/agent-tools.ts)、[写入准备](../src/main/tools/change-preparation.ts)、[提交底层](../src/main/tools/change-commit.ts)。

### 附件快照与兼容修改链

附件最多8个，每文件32 KiB、合计128 KiB；只接受现有文本扩展名，标识路径最长240字符，读取工具每次最多80行。授权归属是逐个选中文件，不是共同父目录；附件授权和工作区授权独立保存于运行内存。

兼容修改链仍完整存在：只读快照 → 完整读取 → 修改建议 → 差异预览 → 检查写入条件 → 用户确认提交 → 真实回执。写入准备有效2分钟，只能领取一次，并锁定路径与文件身份；替换阶段取消不能假称操作从未发生。

回执的备份入口是在文件管理器中定位经过复核的备份文件，方便人工处理，当前没有“点击后自动恢复原文件”的功能。

证据：[附件快照](../src/main/tools/project-snapshot.ts)、[附件读取工具](../src/main/tools/project-file-tools.ts)、[一次写入准备](../src/main/execution/change-preparation-ipc.ts)、[备份定位接口](../src/main/execution/change-commit-ipc.ts)、[提交回执](../src/renderer/src/features/review/CommitReceipt.tsx)。

### AGENTS.md

读取当前运行根目录的 `AGENTS.md`：有工作区时读取已选工作区根目录，没有工作区时在请求中读取会话默认目录根。没有递归查找或嵌套继承。校验普通文件、单硬链接、真实路径及完整文件 UTF-8，记录完整内容哈希；给模型的有效前缀最多64 KiB。已选工作区的状态栏展示读取/截断状态，默认目录的请求时读取不新增一套状态界面。

已选工作区的指令在请求时重新读取，并与选择/重新读取时已登记的指纹比较；变化后要求用户重新读取。默认目录分支在每次请求时读取当前内容，没有登记同样的工作区选择指纹。

64 KiB 是模型前缀上限。当前实现先读取完整文件再验证/截取，不能宣传为磁盘读取上限。项目指令属于不可信上下文，不能扩大权限或替代用户请求。

新版环境白名单为 `PATH`/`Path`、`PATHEXT`、`SystemRoot`、`TEMP`、`TMP`、`HOME`、`USERPROFILE`、`HOMEDRIVE`、`HOMEPATH`、`LANG`、`LC_ALL`。复刻时不能无意中把旧 npm 改成同一白名单，或把通用命令改成完整环境继承。

旧 npm 目录检查读取 `package.json` 和可选 `.npmrc`，各最多64 KiB；审查 `typecheck` 及前/后置脚本、`packageManager`，记录真实目录身份和两配置内容指纹。`.npmrc` 只有确实不存在才算 absent；不可读、链接、目录或超限必须失败。目录审查有效5分钟，执行准备有效60秒，只能领取/确认一次。

停止目前只请求终止所启动进程并停止观察，没有可靠的整棵进程树终止和退出确认。复刻课程不能宣称原工程已经具备这一保证，也不能将默认目录或风险评估称为命令沙箱。

## 7. 模型请求与工具循环

当前服务从 `MODEL_ENDPOINT`、`MODEL_NAME`、`MODEL_API_KEY` 环境配置读取模型信息。请求使用 HTTPS Responses SSE，拒绝 URL 内凭据和 HTTP 重定向，要求正确 SSE 响应；没有可见模型配置/选择界面。

请求保留 `parallel_tool_calls: false`、`store: false`、`include: ['reasoning.encrypted_content']`、4096输出 token。SSE 解析处理 UTF-8 分块、事件分帧、多行 data，以真实 `response.completed` 完整响应确认完成；拒绝 failed/incomplete/refusal，单帧及响应总量限制1,000,000字符。流式文字增量累计最多100,000字符，与工具循环的最终回答上限分别检查。

工具循环每轮最多9次模型请求、8次工具执行，每次模型响应最多一个工具；拒绝重复 `call_id` 和超出本轮范围的工具。工具参数最多4096字符、工具结果12000字符、最终回答16000字符、运行中的协议输入128000字符、响应 output 最多50项。

发送前续聊历史另限300项、紧凑JSON序列化长度64000字符；单轮完整协议解析限160项、128000字符。历史上限、单轮记录上限和运行输入上限是不同检查，不能合并成一个128000字符限制。

保留原始 reasoning/function_call/message 及 phase 等协议内容，不能只用界面消息重建上下文；失败/取消轮次不保存为可续用的完整协议轮次。

Agent 运行计时4分钟，进入风险评估或人工等待时清除该计时器，恢复运行后重新开始4分钟计时；这不是“整轮含批准等待最多4分钟”的总墙钟上限。会话标题是独立30秒模型请求，最长80字符，不混入聊天工具循环及聊天任务记录。

证据：[模型请求](../src/main/model/response-client.ts)、[SSE](../src/main/model/sse.ts)、[工具循环](../src/main/agent/tool-loop.ts)、[协议历史](../src/shared/agent-history.ts)、[Agent 运行计时](../src/main/agent/agent-runner.ts)、[标题请求](../src/main/agent/conversation-title-ipc.ts)。

## 8. 任务、保存与恢复

任务契约包含 `chat`、`agent`、`command` 三种类型和八种状态：`created`、`running`、`waiting_approval`、`completed`、`cancelled`、`failed`、`timed_out`、`interrupted`。正式聊天实际由 Agent 运行器创建 `agent` 记录；类型存在不代表另有三套独立运行引擎。

主进程是运行任务终态的权威，按合法状态转换、窗口/请求身份防止重复；进入终态后不能再次迁移。窗口注册表与每会话持久任务列表有100条上限。取消是请求，运行拥有者负责收敛；等待批准可立即取消，页面/窗口清理处理中断。恢复记录不恢复进程、批准、计时器、监听器或其他运行句柄。

会话磁盘文件为 `conversation.json`，当前版本6，支持版本1–5的备份迁移。唯一存储实例串行处理 load/save；迁移先独占写入原始字节备份，再写 V6，旧格式不能通过 save 跳过加载/备份。保存采用独占临时文件后 rename，失败不主动删除原会话文件。

限制包括磁盘UTF-8文件8,000,000字节，以及整个快照JSON序列化长度8,000,000字符；最多100会话、总1000消息、总1,000,000消息字符。所有会话的完整 `toolRuns` 数组序列化长度之和最多2,000,000字符，包含ID、scope、trace等元信息，不只统计协议items正文。每会话工具运行记录与任务记录均受100条等各自严格解析条件约束。迁移和加载后会把遗留 pending 消息改为 failed 并写回；前端再对账孤儿任务与真实终态。

保存工作区描述和历史范围不恢复目录授权。草稿只存在当前界面内存，刷新/重启清空；空闲10秒自动保存和“立即保存”不能混为一次按钮操作。

证据：[任务类型](../src/shared/task.ts)、[任务注册表](../src/main/execution/task-registry.ts)、[V6 与迁移](../src/shared/conversation-library.ts)、[会话存储](../src/main/storage/conversation-store.ts)、[存储接口唯一实例](../src/main/storage/conversation-ipc.ts)、[前端恢复对账](../src/renderer/src/features/conversation/useConversationTasks.ts)。

## 10. C# / Avalonia 的复用边界

| 范围       | 可复用依据                                                  | 需要在新工程重新实现和验证的部分                                                                                                  |
| ---------- | ----------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| 界面       | 当前界面截图、布局/文字/状态、操作顺序和限制                | XAML、View/ViewModel、UI线程更新、窗口行为、中文输入法、浮层/焦点、滚动和 Markdown 控件                                           |
| 状态与服务 | 唯一会话状态源、请求/会话/窗口身份、权限及任务规则          | C# 应用服务、异步取消、订阅释放和生命周期；无需仿造 Electron IPC 或引入通用事件总线                                               |
| 模型与协议 | 工具名、JSON schema、原始协议项、SSE规则、限额              | `HttpClient` 流式读取、`CancellationToken`、UTF-8/SSE 分帧、完整响应与严格解析                                                    |
| 风险审批   | 固定评估载荷、严格 safe 语法、回退/归属/失效场景            | 显式检查未知/重复字段及响应结构；`System.Text.Json` 默认行为不能替代现有规则                                                      |
| 文件       | 字节样本、哈希、BOM/换行、身份/链接/冲突/未知结果的行为样本 | Windows 真实路径、文件身份、句柄/硬链接/目录联接检查及安全写入；`FileInfo` 大小/时间和字符串前缀不足以替代现有保护                |
| 命令       | 两条策略、参数数组、环境、限额、超时与输出样本              | `ProcessStartInfo.ArgumentList`、`UseShellExecute = false`、独立stdout/stderr与取消计时；Windows `.cmd` 启动兼容必须专门设计/验证 |
| 存储       | V6 camelCase 字段、1–5迁移、原字节备份、解析与恢复样本      | 唯一C#存储服务、串行队列、临时写入/替换、失败保护；独立数据目录与旧记录副本兼容验证                                               |
| PTY        | 会话身份、输入/尺寸/退出/清理契约                           | Windows ConPTY/PTY 后端与终端渲染；Avalonia 本身不会提供 node-pty 或 xterm.js 的能力                                              |

TypeScript、React、CSS、Electron/Node 运行实现用于对照，不能直接当作原生 Avalonia 代码使用。协议、规则、JSON样本和边界场景可以复用为迁移依据。

JS 字符限制按 UTF-16 代码单元计数，与 C# `string.Length` 接近；UTF-8 字节上限必须另算。JSON 属性命名、允许字段、null、状态枚举、时间、ID、历史协议结构及拒绝条件均需要显式保持。

不能仅用 `.NET AppData` 名称宣称与 Electron `userData` 同一路径；新工程的数据目录和默认会话工作目录应在课程中明确。旧记录用副本验收兼容，两份应用不同时写同一会话文件，也不增加产品导入流程。原课程的 `npm_typecheck` 检查的是用户选中的 npm 项目，不改成新 Avalonia 工程自身的 `dotnet build`。

## 11. 验证证据与录制口径

本盘点没有新增应用测试或联机验证。第44课和第三次整理的已有证据见[第44课](../ZoneCodex学习计划/55-第四十四课-自动审批接入与三种授权模式闭环.md)和[第三次整理验收记录](../ZoneCodex学习计划/57-第三次工程整理方案-统一职责与执行边界.md)，不能直接记为 Avalonia 新工程的通过结果。
