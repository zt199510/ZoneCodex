# Avalonia 复刻 ZoneCodex：合集视频制作方案

规划日期：2026-10-06。状态：录制方案，尚未录制或发布。

目标观众已确认：有 C# 基础，Avalonia 入门。内容依据[功能盘点](00-当前功能盘点与复刻边界.md)和[逐课路线](01-Avalonia逐课复刻路线.md)，复刻的是第44课与第三次整理后的当前工程。

## 1. 系列与合集形式

系列名称建议：**《用 Avalonia 复刻 ZoneCodex：从桌面聊天到本地 AI Agent》**。

按44课主线逐集制作，先发布或保留各课完整视频，再按阶段合并为6篇合集。终端C1/C2单独作为第7篇兼容附录；最终需要覆盖当前全部工程能力时，将它们一起归入系列。课号与Avalonia路线一致，避免把课号、旧Electron课号和视频篇号混用。

单课一般15–25分钟，文件身份、提交、命令和自动批准等复杂课允许25–40分钟，也可在同课下分上下集。44课主线先按约12–18小时安排剪辑预算，终端另预留约1–2小时；这是估算，不是成片时长。长度以讲清并跑通本课为准。

不建议第一次就录制一条连续十几小时的视频。先得到课前/课后代码都能运行的单课素材，阶段合辑复用单课内容，删去重复开场，保留章节导航和真实验收。

## 3. 每课的拍摄结构

| 顺序 | 建议时长 | 镜头与内容                                                         |
| ---- | -------- | ------------------------------------------------------------------ |
| 1    | 20–40秒  | 原版效果与本课将完成的操作；明确这课只处理哪个结果                 |
| 2    | 2–4分钟  | 简图、状态归属和前置代码；解释Avalonia绑定/命令/UI线程等必要概念   |
| 3    | 8–15分钟 | 从本课课前代码实现；重点代码放大，保留决定调用顺序和状态变化的步骤 |
| 4    | 3–6分钟  | 运行成功场景，再运行必要的拒绝、取消、冲突或失败场景               |
| 5    | 1–2分钟  | 解释结果，列本课实际改动、2–4道自测和下一课需要的能力              |

复杂课可以延长第3–4部分。界面课以实际窗口为主，后端课至少给出一个可见业务结果与结果验证，避免整节只是念代码。需要解释请求流动时，用同一张简图逐步标出调用位置，不引入另一套“教学版架构”。

观众已经会C#，不重讲循环、继承和语言基础。每次遇到新桌面概念再解释：XAML、DataTemplate、INotifyPropertyChanged、Command、UI线程、取消及窗口生命周期。模型协议、文件安全与批准政策则结合实际场景解释。

## 4. 录制前准备

每课必须有可恢复的课前与课后代码快照，能从干净环境完成本课。代码快照的具体标签/分支规则在建立Avalonia仓库后确定；目前没有创建仓库、标签或提交。

准备一个独立教学数据目录，包含小文本、同名附件、AGENTS.md、可制造外部修改冲突的文件，以及用于旧npm审查的Node项目。原应用的聊天记录、源码和运行授权不作为破坏性演示素材。

保持桌面分辨率、缩放、字体和录屏区域固定；正常1280×840与窄窗口680×560做对照，原生DPI缩放再独立验证。截图注明窗口逻辑尺寸与缩放，避免把不同缩放下的物理像素误当布局差异。字体、图标、圆角、间距和浮层优先对照当前源码及截图。

模型配置不进入屏幕、源码或下载包。纯讲解阶段使用隔离传输/进程夹具，正式演示用限定合成任务走真实链路。夹具只存在测试/录制宿主，不增加产品模拟模式或“测试成功”按钮。

录制前逐项确认本课演示能够重复运行：删除的是教学新建文件，外部修改只改教学副本，准备记录只使用一次，上一轮任务和批准已清理。失败镜头可以剪短等待时间，但保留错误、取消或未知结果，不能剪成成功。

## 6. 里程碑与录制顺序

实现和录制按课推进。每篇完成后录一次阶段演示，再继续下一篇；第44课最后录制最终成果、系列总开场和完整端到端验收。第一篇开场中的最终效果片段应来自这份最终成品，避免先拼一段尚未运行的功能宣传。

第14课前先验证原生Markdown方案，第32课前先验证Windows文件身份，第37课前先验证进程启动/取消，第40课前单独确认`.cmd`适配；终端兼容篇开录前确认原生显示与ConPTY。这些是技术准备，最终验收仍在对应课程里呈现。

如果旧npm真实Windows链、真实模型场景或终端方案尚未通过，在视频说明和验收清单中保留待验证项。普通`Process`和风险评估不提供OS沙箱，本系列到当前基线为止，沙箱、MCP、Skills、SSH、图片输入及自动更新放后续系列。
